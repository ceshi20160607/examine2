## 当前结论

旧 IA、旧原型、旧 review、旧细分规范引用全部作废。下一轮只按 `docs/design/prototype-brief.md` 生成。若需要追溯 review，只读取 `docs/design/reviews/prototype-latest-2026-06-18.md` 顶部“当前唯一开发口径（1.7.24）”和最新 37 节；早期段落仅作历史记录，不作为 coding 口径。

当前设计目标已提升为“完整可配置业务系统平台”：先稳定平台层、系统层、运行态业务层、配置态管理层、权限身份层、流程审批层、数据集成层、AI Agent 能力层和工作管理层，再表达页面。AI Agent 不再只是后续概念，当前设计必须同时表达平台/系统配置入口与运行态对话入口；工作管理必须把项目、任务组、任务、日报、日历、统计、消息和待办串成闭环。

## 本轮新增硬约束

- 统一入口保持干净登录形态：账号、密码、MFA、登录/注册/忘记密码；不在登录右侧堆系统选择、架构说明、统计卡片。
- 连续复审仍出现缺口时，必须拉起干净上下文审阅：只读落盘需求、brief、review、原型和知识库，不继承聊天上下文；产品架构、UX、权限流程、开发验收至少四视角合并结论后再给用户看。
- 登录页必须首屏容纳，不出现外层滚动条；窄屏可压缩演示身份说明，但不能丢失登录、注册、找回密码、SSO/验证码入口。
- 角色必须覆盖系统普通成员、系统管理员、平台普通成员、平台管理员四类；平台普通成员只能进平台工作台和授权系统，平台管理员才有平台后台管理入口。
- 系统信息必须表达单租户/多租户模式、租户隔离策略、默认租户、租户配额、模式切换影响和审计边界。
- 字段配置必须按无代码/低代码主流能力扩展字段类型、字段专属配置、权限/导出/校验、列表/筛选/场景/动作/发布检查。
- 字典管理必须覆盖普通字典、树形/级联字典、状态字典、标签字典、字段选项字典、版本发布、引用影响、颜色、图标、排序、默认项、停用历史和导入导出。
- Flow 必须覆盖企业级审批流、办公流、自动化工作流，包含节点库、画布连线、节点属性、审批方式、退回策略、转办/加签、超时、模拟运行和状态回写。
- AI Agent 新需求：平台级配置本地/外部模型、购买授权和系统继承；系统可使用平台授权或配置第三方模型，并按模块、字段、动作、数据范围和人工确认策略控制 Agent 对话录入、统计查询、任务提取、日报草稿和项目总结。
- 平台工作台 Agent 和系统业务页 Agent 必须分开：平台 Agent 只处理平台授权、平台日志、平台任务、模型额度、系统健康和系统切换引导，不能直接打开系统业务列表/详情或写入业务数据；平台 Agent 写入确认只生成平台任务、平台消息和平台日志，不能复用系统业务写入确认；系统 Agent 只能在系统切换后的当前系统成员上下文内工作。
- 系统后台必须有独立 AI Agent 配置页；平台和系统都只保留一个“日志管理”入口，页面内区分登录日志和业务日志，不能只用泛日志表。
- 待办必须是左侧类型 + 右侧列表工作台，至少覆盖审批待办、提醒待办、今日需处理，并提供筛选和进入业务对象。
- 消息必须从顶部入口打开右侧抽屉，以手机消息流形式一条一条展示完整内容；筛选至少包含系统、租户、模板、类型、状态、时间和关键词；关联模块、系统、任务、项目、日志的消息必须整条点击可跳转，卡片内不放重复小按钮。
- 登录必须展示注册、找回密码、企业 SSO 或验证码登录等基础入口；注册创建系统和找回密码必须是可走通页面；注册创建系统后，创建人成为系统超级管理员，并进入系统后台初始化引导。
- 企业 SSO 不能只在登录页放按钮；平台后台配置管理必须有“统一认证 / 企业 SSO”身份源配置，覆盖 OIDC/SAML/OAuth2/LDAP、回调、证书/JWKS、域名白名单、属性映射、JIT、MFA、测试发布和登录审计；系统后台必须有一级“统一认证”页，负责系统继承身份源、域名范围、组织架构映射、员工绑定、JIT 系统成员策略和无成员映射反馈。系统信息页只做摘要和入口。
- 平台/系统后台入口和可操作功能来自角色配置；平台内置超级管理员 `platform_admin_root` 和系统创建人超级管理员是特权角色，不走普通角色配置。
- 日报和任务合并为工作管理，并按“仪表盘 / 项目任务 / 普通任务 / 日报”四个主标签表达：仪表盘中项目/今日预警与当月完整日历上下展示；项目任务和普通任务都通过按钮在列表/看板之间互斥切换，列表有分页，看板无分页并滚动加载；普通任务单独成页，支持一行创建和后补项目/业务对象；日报页只展示我的日报列表和筛选项，写日报/自动生成草稿作为操作入口。
- 工作配置必须作为系统后台一级页面，不只藏在模块管理某一行或抽屉里；工作配置不显示统计卡片，不直接维护状态/标签选项，主要配置项目任务字段列表、普通任务字段列表、日报字段列表、字段属性、字段权限、卡片字段、看板取数字段、发布检查和回滚。
- 状态、标签、颜色、图标等选项统一由数据字典配置；任务看板的列、泳道或分组依据已发布的下拉单选或多选字段构建，颜色和图标来自字段绑定的数据字典。
- 全系统状态颜色必须统一：草稿/待处理用低强调灰，处理中/当前用蓝，待确认/临期用橙，通过/完成用绿，失败/拒绝/逾期/停用用红，自定义标签可用独立色但不能覆盖核心状态语义；颜色配置落在数据字典项上。
- 后台日志必须在同一个日志管理入口内区分登录日志和业务日志；登录日志关注账号、认证方式、IP、设备、地点、风险和结果，业务日志关注模块、对象、动作、字段变化、审批、导入导出、OpenAPI、AI Agent、追踪号和结果。平台后台和系统后台日志都采用“左侧日志类型/审计范围 + 右侧统一列表”的组织架构式布局，左侧日志类型树是唯一主分类，右侧统一筛选、列设置、导出和行点击详情，不再重复放日志类型下拉或登录/业务页签。
- 个人信息菜单不再放“授权系统/进入系统”入口；多系统进入统一保留顶部“系统切换”，避免同一能力重复占位。
- 开发前关键配置入口不能只用 toast：模块场景、页面动作、发布到业务页、工作字段、工作看板、流程类型、流程模拟、字典发布、AI Agent 发布检查都必须有可开发的抽屉或页面结构。
- 加载、空、无权限、错误、禁用、后台任务状态必须作为统一组件和接口语义表达，不能留到开发时各页面临时补。
- 平台内置超级管理员账号示例为 `platform_admin_root`，系统管理员示例为 `sys_admin_vehicle`；平台账号、系统成员映射、系统角色、系统超管来源必须分清。
- 系统切换是唯一多系统入口，必须包含当前系统、租户、系统角色、授权状态、进入/申请/禁用原因，并在切换后刷新模块、角色、字段权限、数据范围、待办和消息。
- 系统切换必须生成 `SystemSwitchContext`，包含 systemId、tenantId、systemMemberId、effectiveRoleIds、dataScope 和权限快照；平台身份没有系统成员上下文时不能直接打开系统业务页。
- 多租户系统必须有 `TenantSwitchContext`，包含 tenantId、tenantRoleIds、tenantDataScope、isTenantSwitchable、disabledReason；系统切换或租户切换后必须重绘系统业务壳的品牌、模块分组、左侧模块、列表、待办、消息和字段权限。
- 系统切换列表必须使用 `accountMemberBindingId` 表示平台账号和系统成员的绑定关系；只改显示系统名称、不重建 member/role/dataScope 的切换不能作为开发口径。
- 平台消息中心和系统消息中心必须拆开；平台消息不得直接跳系统业务详情，涉及系统业务时先跳系统切换或平台授权/平台任务对象。
- 消息模板与通知渠道必须显式配置：templateCode、平台/系统层级、变量、站内消息/待办/邮件/短信/Webhook 渠道、跳转目标、去重键、已读回执、免打扰、失败重试和 `message_delivery_log`。
- SSO、OpenAPI、Webhook、外部模型等密钥只能通过 SecretRef 和版本表达；密钥轮换必须有 `SecretRotationJob`，覆盖新版本、双写验证、切换生效、旧版本停用、失败回滚和审计。
- 无系统成员映射不能复用普通授权说明；必须形成 `NoMemberAccessRequest`，没有 `systemMemberId` 时不可进入系统业务页。
- `NoMemberAccessRequest` 必须有 requestId、status、identityProvider、externalUserId、targetSystemId、tenantId、requestRole、approverId、approveResult、roleIds、dataScope、rejectReason、traceId，审核通过前不得自动授权。
- 系统 AI Agent 策略必须显式保存 `AgentPolicyScope`：moduleScope、fieldScope、actionScope、dataScopeExpression、外发限制、脱敏策略、策略版本。
- 日报自动草稿必须有 `DailyReportAutoSourceRule`，只读取当前成员有权限的任务、待办、消息、业务日志和审批记录，并在提交前人工确认。
- OpenAPI 外部应用不展示明文 appKey/secret，页面和 API 只表达 `OpenApiSecretRef`、版本、轮换状态、到期和最近使用。
- 消息筛选、全部已读、归档、分页上一页/下一页、加载更多等按钮必须有可见状态变化或结果承接。
- `defaultDrawer` 是设计缺口阻断态，不是兜底详情；P0 入口落到 default/generic 时不能进入 coding。
- 关键提交按钮必须有明确承接：同步结果、后台任务、发布检查、日志追踪或专属抽屉，不能落到泛化“操作已响应”。
- 表格整行点击只允许出现在明确的数据列表或业务核心列表；说明表、配置矩阵和普通状态表不能显示可点击手势。
- 流程画布必须显示条件分支标签；条件、字段更新、外部 API、超时提醒等不同节点必须有专属属性承接，不能都复用同一审批节点表单。
- 平台应用页的新增/配置授权只对平台管理员开放，平台普通成员只能进入已授权系统、查看授权结果或发起申请。
- 流程管理必须表达绑定规则、优先级/互斥、幂等键、实例快照、任务快照和 traceId。
- 流程高级运行策略必须在原型中表达：转办、委托、加签、候选人领取、手动插入节点、子流程、外部 API 重试/补偿、状态机、任务版本和实例版本。
- 平台 Flow 必须使用专属配置与运行结果结构，包含触发源、影响系统、节点连线、幂等键、重试/补偿、平台任务、运行批次和 traceId，不能复用通用说明抽屉。
- 有效权限必须可解释，至少包含 permissionVersion、sourceRoleIds、denyPolicyIds、dataScopeExpression、systemMemberId、字段权限矩阵、按钮禁用原因和解释链路。
- 平台配置管理和系统信息页必须表达上线保障：平台/系统体检、功能开关、灰度发布、容量配额、限流、备份恢复、归档策略、最近备份、服务连通性和扩容申请。
- 运行态必须有普通用户日常效率入口：全局搜索、最近访问、快捷创建、表单草稿和错误字段定位；这些入口仍受角色权限、字段脱敏和数据范围控制。
- 流程节点属性、审批处理、AI 写入确认、字典发布检查、AI Agent 发布检查、通用状态样例必须有专属模板结构，不能依赖 default/generic 兜底。
- 模块组不是业务数据父级，只负责运行态顶部模块分组、组内模块导航、排序、可见角色和发布关系；业务数据归属于 `systemId/tenantId/moduleId`，不得再按 `appId` 归属。
- 对外应用只负责 OpenAPI 接入来源、appKey/secret、scope、回调、限流和审计来源，不得和系统内模块组混叫“应用”，也不得作为模块父级。
- 平台账号进入某个系统前必须存在系统成员映射和系统角色上下文；平台内置超级管理员不能绕过系统成员/权限直接查看或修改业务数据。
- 直接访问无权限页面必须有无权限态或 403 反馈，显示缺失权限、当前角色、申请授权入口和 requestId；不能只靠前端隐藏菜单。
- 组织树、角色树、模块树、字典分类和待办类型都必须能选择节点并刷新右侧列表/配置语义，不能只做静态左栏。
- 流程设计器画布必须保证节点不被裁切：中间画布最小宽度、横向滚动或可折叠属性面板必须有一种落地方式。
- 开发前覆盖锁定：原型必须显式出现启用系统、停用系统、字典类型、表头排序、整行点击、消息流、系统筛选、租户筛选、模板筛选、平台级模型、系统级 Agent、容量配额、备份恢复、归档恢复、错误状态和禁用状态；不再接受只用近义词暗示。
- 操作列去重锁定：整行点击作为详情主动作后，操作列不得再用“详情 / 查看 / 打开 / 进入”承接同一详情动作；这些词只能在“查看日志、查看授权、进入系统、打开弹窗”等不同业务目的里出现。
- 多环境与部署回滚、缓存策略与 API 规范属于开发契约级入口，必须在平台配置管理和系统信息页可见；不能等 API 阶段才补出页面边界。
- 收藏菜单、移动端扫码和拍照上传属于普通用户高频效率入口，必须进入运行态快捷创建/附件草稿链路，并受权限、脱敏、失败重试和日志审计控制。

## 已沉淀的旧版好内容

- 业务列表高密度工作台：搜索、场景、高级筛选、列设置、导入、全部导出、导出选中；所有列表数据行点击打开详情，行内按钮不重复承担“查看详情”。
- 勾选批量态：转移、删除、导出选中、批量编辑，按权限和数据状态禁用。
- 右侧详情工作区：保留列表上下文、顶部摘要、操作按钮、标签页、审批面板。
- 配置态细节：字段抽屉、列表配置、筛选配置、场景配置、页面动作、发布检查。
- 导入导出细节：模板下载、字段匹配、预检查、错误行、任务状态、完成消息、下载入口和批次回滚。
- 打印模板细节：模块字段绑定、模板版本、打印预览、导出 PDF、详情打印记录。
- 权限态细节：菜单/模块、页面动作、字段、数据权限和权限预览。
- 流程态细节：审批类型、触发事件、节点库、节点属性、流程模拟、审批人预览、发布检查和错误态。
- 配置版本细节：草稿/已发布、发布影响、运行端使用已发布版本、历史版本和回滚入口。
- 待办消息细节：待办是左类型右列表工作台；消息是右侧抽屉消息流，包含筛选、已读、整条点击跳转业务对象、关联任务结果、日志和 Agent 结果，不在卡片内塞重复动作按钮。
- 工作管理细节：项目/任务组/项目任务/普通任务/日报/月历/统计闭环，支持老板派发、员工协作、多人任务、标签、项目关联、完成度、评论回复、完成时间、预警和自动统计日报草稿；任务看板是同一批任务的字段视图，不是重复功能，列/泳道来自工作配置选择的下拉或多选字段，选项颜色和图标来自数据字典。
- AI Agent 细节：后台配置模型授权和系统继承，平台运行态 Agent 与系统运行态 Agent 分离；平台运行态只生成平台任务草稿并进入平台确认页；系统运行态提供对话录入、统计查询、任务提取、日报草稿，写入必须人工确认并审计。
- 日志态细节：日志管理一个入口内区分登录日志和业务日志，分别提供筛选、导出、列设置、详情追踪；平台和系统日志页都必须保持左类型右列表，不再回到两个并排卡片、日志类型下拉、页签主分类或泛日志表。
- 任务契约细节：导入、导出、发布检查、AI 写入和日志导出统一走后台任务模型，必须有 taskId、bizType、idempotencyKey、status、progress、cancelable、resultFile、errorFile、createdBy、createdAt、traceId、auditLogId、retryable 和回滚边界。
- 字段类型细节：字段类型注册表必须能支撑后端建模和筛选表达式，包含存储形态、筛选/排序操作符、默认值校验、字段权限、导入导出和脱敏规则。
- 行点击细节：整行点击只对明确标记的数据列表或业务核心列表启用；配置说明表、状态样例表和静态表格不能默认打开兜底详情。
- 状态态细节：列表骨架屏、筛选无结果、无权限页、接口错误追踪号、流程/发布检查失败、按钮禁用原因、导入导出后台任务状态。

## 复审重点

生成后优先看：

- 是否仍按 CRM 骨架表达系统业务页。
- 顶部是否只放模块分组，组内模块是否在左侧。
- 详情是否从右侧打开并保留列表上下文。
- 详情顶部主信息、按钮、标签页、右侧审批面板是否完整。
- 系统后台与业务页是否完全分离。
- 角色权限、流程节点、模块配置、导入导出、打印模板、待办、消息抽屉、工作管理、AI Agent、日志筛选是否足够开发前确认。
- 关键配置按钮是否都有抽屉或页面承接，而不是只弹提示。
- 通用状态与异常态是否在原型和 brief 中都有明确样例。
