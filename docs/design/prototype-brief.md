## 0. 最高优先级

本 brief 是当前唯一有效设计输入。旧 IA、旧原型、旧 review、旧细分规范引用全部作废。

本项目最终目标是一个完整可落地的“可配置业务系统平台”，不是页面 demo，也不是单个车辆系统后台。设计必须先表达项目级架构层级，再表达具体页面。后续开发必须按设计实现，因此原型要让正常企业用户和开发人员都能看懂系统边界、入口、权限和业务闭环。

### 0.1 项目级架构层级

设计必须稳定表达以下层级，不能混在同一套导航里：

1. **平台层**：产品本身的管理层，负责平台账号、平台角色、租户/系统授权、全局配置、全局日志、系统健康、部署和版本。平台层不直接配置系统业务字段，不直接办理系统业务审批，不直接修改业务数据。
2. **系统层**：用户创建出的某个业务系统，例如车辆资产管理系统。系统层负责当前系统的信息、组织架构、角色、模块、字段、页面、工作配置、AI Agent 配置、流程、字典、仪表盘、数据源、对外应用和日志管理。日志管理是一个入口，内部区分登录日志和业务日志。
3. **运行态业务层**：普通用户日常使用业务数据的地方。按“顶部模块分组 + 左侧组内模块 + 右侧列表/详情”组织，包含业务列表、详情、新建/编辑、查询筛选、导入导出、附件、审批办理、待办、消息。
4. **配置态管理层**：管理员搭系统的地方。包括模块组、模块、字段、列表、筛选、场景、页面动作、发布、工作配置、流程、角色权限、仪表盘、字典、数据源、对外应用、日志。配置态不能伪装成业务运行态。
5. **权限与身份层**：统一平台账号，进入不同系统后映射为系统成员和系统角色。平台角色、系统角色、业务数据权限、字段权限、按钮权限、审批节点权限必须分开表达。
6. **流程与审批层**：流程配置在系统后台；审批办理在业务详情或待办中。审批类型、触发条件、节点属性、审批人、字段权限、状态回写、超时、日志必须能被设计看出来。
7. **数据与集成层**：模块数据、附件、导入导出、OpenAPI、数据源、外部应用、任务日志必须形成闭环，并明确权限、脱敏、失败反馈和审计记录。
8. **AI Agent 能力层**：平台后台配置模型和 Agent 授权，系统后台配置本系统 Agent 可访问模块、字段、动作、数据范围和确认策略。运行态提供 Agent 对话入口，用于录入权限内数据、查询统计、提取任务、生成日报草稿和总结项目进度。
9. **工作管理层**：项目、任务组、任务、日报、日历、统计和消息/待办联动。用于老板派任务、员工协作、每日工作记录、项目完成度跟踪和团队统计。

### 0.2 四套壳

在上述架构层级下，设计必须按四套壳表达：

1. 平台工作台。
2. 平台后台。
3. 系统业务页。
4. 系统后台。

硬规则：

- 业务系统运行态参考 CRM 类业务工作台骨架：顶部模块分组、左侧组内模块、右侧列表/详情。
- 业务详情从右侧打开并保留左侧列表上下文，不做居中普通弹窗。
- 审批属于业务详情，不在左侧导航里。
- 新建属于列表按钮或右侧抽屉，不在左侧导航里。
- 平台工作台和平台后台分离。
- 系统业务页和系统后台分离。
- 系统后台只有“返回首页”回业务首页。
- 默认展示超级管理员全量功能，同时标注 che/sys_admin_vehicle/platform_member/platform_admin_root 的权限裁剪。
- 设计验收必须从最终目标倒推：这是给正常企业用户长期使用的完整系统，不是低代码 demo。生成前必须主动检查平台层、系统层、普通用户、管理员、配置、运行、审批、权限、日志、导入导出是否形成闭环，不能等用户指出一个问题才补一个问题。
- 不只检查“页面有没有”，还要检查“布局是否像真实企业后台”。禁止用通用卡片、通用 stepper、通用权限矩阵糊成所有页面。
- 组织架构、模块树、流程画布、导入导出、详情 tab 必须按业务场景设计专属结构，不能只用说明卡片或示意表格占位。

## 1. 输出与风格

- 输出静态 HTML 原型，可直接浏览。
- 首页 `index.html` 必须能跳转全部页面。
- 中文界面。
- 高密度、克制、成熟企业后台，不做营销页，不做大留白。
- 不暴露技术 ID、JSON schema、完整 secret、moduleId、recordId。
- 表格行高约 42-46px，1440×900 首屏业务列表至少 8 行。
- 卡片圆角 6-8px；页面背景浅灰，内容区白色，主色蓝色。
- 后台配置页面要高密度、可扫描，避免大块说明卡、空面板和无意义留白。
- 左树右表、左列表右详情、左画布右属性这类页面必须控制比例：左侧树/列表通常 240-280px，最大不超过主内容宽度 30%；右侧必须保留足够表格/表单宽度。
- 任何“树”都必须像树：有父子层级、缩进、展开/收起、选中态、节点数量/状态，不得用 stepper 或普通卡片代替。
- 任何“流程画布”都必须像画布：节点之间有连线、箭头、条件分支标签和选中态，不得只是节点卡片网格。
- 任何“弹窗/抽屉态”都必须有独立状态页面或可见触发结果，不能把弹窗内容直接常驻在列表下方。

禁止出现：

- 禁止使用“名称/类型/说明/角色/参数映射 + 数字序号”这类占位数据。
- 系统业务页左侧出现“审批处理”菜单。
- 系统后台左侧出现业务数据页。
- 平台后台配置系统业务字段。
- 旧版平台工作台左侧“我的系统/Flow/应用/日志”导航。
- 独立“导出中心”导航。
- 业务列表下方常驻“导入预检查/导出后台任务”大面板。
- 用权限矩阵表格代替附件、打印记录、金额配置、操作记录、流程节点属性等专属内容。
- 用 stepper 代替部门树、模块树、流程图。

## 2. 角色入口

| 角色 | 账号 | 可见 | 不可见 |
|------|------|------|--------|
| 平台管理员 | platform_admin_root | 平台工作台、平台后台、授权系统 | 无，按全量展示 |
| 平台普通成员 | platform_member | 平台工作台、授权系统、平台待办、平台消息 | 平台后台、系统后台 |
| 系统管理员 | sys_admin_vehicle | 系统业务页、系统后台 | 平台后台 |
| 普通成员 | che | 授权业务模块、待办、消息 | 系统后台、平台后台 |

登录后按角色进入对应首页。che 任何页面都不能出现后台入口。platform_member 可以进入平台工作台和授权系统，但不能看到平台后台入口；platform_admin_root 比 platform_member 多平台后台管理能力。

统一登录页规则：

- 真实登录页只保留账号、密码、MFA/验证码、登录、注册/找回密码等必要入口。
- 不在登录页右侧展示系统选择、架构说明、权限边界、平台/系统卡片或业务统计。
- 原型可以保留“演示身份切换”控件，但它必须明显是原型辅助，不能伪装成真实产品登录功能。
- 登录页必须展示注册、找回密码、企业 SSO 或验证码登录等通用基础入口。
- 注册可引导创建系统；注册人创建系统后自动成为该系统超级管理员。
- 注册并创建系统、找回/重置密码必须是可进入的页面流程，不要只做成右侧抽屉或不可见辅助入口。

后台权限规则：

- 平台后台入口、平台后台菜单、页面按钮、日志范围、配置项编辑能力，都来自平台角色配置。
- 平台超级管理员是内置默认账号 `platform_admin_root`，只有一个，拥有平台全权限，不需要也不能通过普通角色配置获得。
- 系统后台入口、系统后台菜单、模块权限、按钮权限、列表字段、详情字段、导出权限、数据范围，都来自系统角色配置。
- 创建系统的人自动成为该系统超级管理员，拥有本系统全部权限，不需要配置普通角色。
- 除超级管理员外，用户能不能进入后台、能改哪些功能、能看哪些字段，都必须能在角色权限配置中看出来。
- 账号模型必须明确区分：平台账号、系统成员映射、系统角色、系统超级管理员授权来源。平台内置超级管理员不等于某个系统的超级管理员；系统超级管理员只在该系统范围内生效。
- 多角色权限合并规则：菜单/模块/动作默认允许并集，显式拒绝优先；数据范围先取角色并集，再受租户、系统和模块边界兜底；字段权限以角色字段权限为基础，审批节点字段权限可以临时开放或收紧指定字段并记录快照。

### 3.1 登录与注册

### 3.2 平台工作台

顶部主导航固定：

- 仪表盘
- Flow
- 应用
- 工作

右侧固定：

- 系统切换
- 创建系统
- 待办
- 消息（右侧抽屉）
- 个人信息

页面：

| 文件 | 页面 |
|------|------|
| `platform/dashboard.html` | 平台仪表盘 |
| `platform/flow.html` | 平台 Flow |
| `platform/apps.html` | 平台应用 |
| `platform/work.html` | 平台工作管理 |
| `platform/todos.html` | 平台待办 |

平台后台入口只对 platform_admin_root 或具备平台后台权限的平台管理员显示，放在个人信息菜单或明确管理入口中，不作为平台工作台主导航。个人信息菜单不放“授权系统/进入系统”入口；进入权限内系统统一使用顶部“系统切换”。

平台 Flow 和应用要表达为平台级入口：

- `platform/flow.html`：顶部保留平台导航，内容区展示流程库、我发起的流程、我参与的流程、流程状态筛选和新建流程入口。
- 平台 Flow 必须有专属配置和运行结果原型：触发源、影响系统、节点连线、幂等键、重试/补偿、平台任务、运行批次和 traceId；不能复用通用说明抽屉。
- `platform/apps.html`：展示已授权系统/应用卡片、应用状态、负责人、最近访问、进入应用、配置授权入口。
- 平台用户可以从平台工作台创建系统；创建入口必须清楚展示系统名称、编码、租户模式、模板、创建后进入系统后台配置引导。
- 平台用户通过顶部系统切换进入权限范围内的系统；无权系统要显示禁用原因。
- 系统切换抽屉必须是真实可操作列表：系统名称、租户、当前标记、系统角色、授权状态、进入/申请/禁用按钮、无权原因。切换后必须重新加载租户/系统/成员/角色上下文、顶部模块分组、左侧模块、字段权限、数据范围、待办和消息数量。
- 平台应用页不能重复放“系统切换”按钮；平台普通成员只能进入已授权系统、查看授权结果或发起申请，不能新增/配置系统授权；新增系统、系统授权配置只对平台管理员或被授权的授权管理员开放。
- 平台账号进入系统前必须存在系统成员映射、系统角色和有效数据范围；平台内置超级管理员 `platform_admin_root` 不等于系统超级管理员，不能绕过系统成员上下文直接查看或修改业务数据。
- 直接访问无权限页面必须显示无权限态或 403 反馈，包含缺失权限、当前角色、申请授权入口、requestId；不能只依赖隐藏菜单。
- 模块组不是业务数据父级：模块组只负责运行态顶部模块分组、组内模块导航、排序、可见角色和发布关系；业务数据归属 `systemId/tenantId/moduleId`，不得按 `appId` 归属。
- 对外应用不是系统内模块父级：对外应用只负责 OpenAPI 接入、appKey/secret、scope、回调、限流、调用来源和审计来源，不得与模块组混叫“应用”。
- 平台待办通过顶部右侧入口进入待办工作台，不在左侧重复出现。
- 平台消息通过顶部右侧入口打开消息中心抽屉，消息按一条一条的消息流展示，不能做成普通表格页面。

### 3.4 系统业务页

系统业务页使用 CRM 类业务工作台骨架：

- 示例分组：车辆管理、合同管理、客户管理。
- 点击“车辆管理”后，左侧显示该分组下模块：车辆档案、维保记录、驾驶员。
- 右侧主区显示当前模块列表或详情。
- 模块分组下的模块不直接铺在顶栏。
- 左侧每个模块必须指向独立模块列表页或明确的模块占位页；禁止把高级筛选、列设置、新建、详情等状态页伪装成模块入口。

系统后台不显示业务列表和审批办理页。系统级 AI Agent 配置是后台一级能力，负责当前系统可使用的模型来源、模块、字段、动作、数据范围、确认策略、失败降级和审计策略；平台模型授权和系统第三方模型配置必须在这里能看出边界。日志管理是后台一级入口，页面内部用页签或分区管理登录日志和业务日志，不在左侧拆成两个菜单。

工作配置必须是系统后台一级配置页，不只藏在模块管理的“工作管理”行或抽屉里。工作配置不要做统计卡片，不直接维护状态和标签选项；它主要维护项目任务、普通任务、日报的字段列表、字段属性、权限和看板取数规则。页面至少包含：

- 项目任务字段列表：字段名、字段类型、是否必填、列表显示、筛选、导出、权限、是否可用于看板。
- 普通任务字段列表：字段名、字段类型、是否必填、列表显示、筛选、导出、权限、是否可用于看板。
- 日报字段列表和规则：日报状态、今日完成、明日计划、风险协助、关联项目、关联任务、可见范围、自动统计来源和人工确认。
- 字段类型中，下拉单选、多选、状态、标签等选项类字段必须绑定数据字典；颜色、图标、语义、排序、默认项和停用历史不在工作配置里重复维护。
- 看板方案：项目任务看板和普通任务看板只能选择已发布字段中的下拉单选或多选字段来构建列、泳道或分组；卡片字段来自字段列表。
- 发布检查：字段停用、字典停用、字典版本变更、看板列字段变更、历史数据展示和权限影响。

系统信息页必须表达单租户/多租户配置：

- 租户模式：单租户、多租户。
- 单租户模式：隐藏租户切换，默认租户不可见，用户直接进入系统业务页。
- 多租户模式：展示租户切换、默认租户、租户管理员、租户角色映射、租户级域名、租户级配额、租户级日志。
- 平台层决定某个系统是否被授权启用多租户；系统层配置当前系统内部租户、默认租户和数据隔离策略。
- 切换租户模式前要提示影响范围：历史数据、角色权限、OpenAPI、导入导出、仪表盘、数据源、日志。

列表页的导入、导出不能只是按钮，必须有可见反馈：

- 运行态列表页只保留工具栏入口，不允许在表格下方常驻展示导入预检查、导出任务面板。
- 点击“导入”打开右侧抽屉或居中流程弹窗，采用向导：选择文件 → 字段匹配 → 预检查 → 错误行 → 确认导入 → 批次结果。
- 点击“导出”打开下拉/弹窗/抽屉，先选择导出范围、字段、格式和是否后台任务，再提交。
- 导出任务进度通过 toast、顶部消息、任务结果弹窗或消息页体现；不是列表页下方的长期功能区。
- 导入：下载模板、上传文件、字段匹配、预检查、错误行预览、确认导入、导入批次结果。
- 导入预检查要显示总行数、可导入行、失败行、重复行、失败原因。
- 导入完成后提供批次详情、错误明细下载、按批次回滚入口；回滚不可用时要显示原因。
- 导出：全部导出按当前场景和筛选条件；导出选中按当前勾选数据；导出字段受字段权限和列设置影响。
- 大导出表现为后台任务：提交成功提示、任务状态、完成消息、下载入口、失败原因。
- 待办/消息中要能看到导入完成、导出完成、导入失败等通知。

## 5. 详情与审批骨架

详情从右侧打开，保留左侧列表上下文。不要做居中普通弹窗。

详情打开形态要求：

- 详情工作区从右侧贴顶贴底展开，建议从顶部导航下沿到页面底部贯通，不要像普通卡片一样上下留大空隙。
- 宽度按业务复杂度给足，桌面端建议占视口 70%-82%，或采用左侧列表窄化 + 右侧详情主工作区；不能让详情内容被压成窄卡片。
- 详情头部 sticky：模块标签、标题、收藏、上一条/下一条、转移/编辑/删除/打印/更多始终在顶部可见。
- 关键摘要条紧跟标题，字段要贴合车辆业务，不要出现与车辆无关的“客户/金额”占位；可用部门、负责人、车辆状态、年检到期、最近维保、审批状态。
- 审批面板在右侧固定宽度 280-340px，和详情 tab 并列；审批按钮区在面板底部或紧跟当前节点，不要漂在页面底部随机位置。

详情工作区结构：

1. 顶部模块标签：车辆档案。
2. 主标题：京A·12345 / 丰田凯美瑞。
3. 收藏、上一条、下一条。
4. 顶部按钮：转移、编辑、删除、打印、更多。
5. 灰底关键摘要条：客户/部门、关联对象、日期、金额/状态、负责人。
6. 下方标签页：详细资料、团队成员、金额/比例设置、附件、打印记录、操作记录。
7. 左侧内容区展示当前标签内容。
8. 右侧审批流程信息面板。

审批面板包含：

- 当前节点卡：审批状态、节点名称、节点说明。
- 处理人/超时：当前处理人、候选处理人、超时剩余。
- 审批动作区：同意、拒绝、转办、加签、恢复、更多操作。
- 审批历史时间线：发起、流转、处理、退回、撤回等历史记录。
- 查看历史审批流程入口。
- 禁止用 stepper 代替审批历史或当前节点卡。

审批和业务状态联动要在详情里表达：

- 审批中：编辑、删除、转移按规则禁用，按钮上有短原因。
- 审批通过：业务状态自动变更，并在操作记录中留下流程结果。
- 审批拒绝或撤回：数据回到可编辑/草稿类状态，详情顶部状态同步变化。
- 当前登录人不是处理人时，审批按钮隐藏或 disabled，并提示“当前节点由某某处理”。

规则：

- 拒绝、撤回、终止必须填写原因。
- 审批中禁止删除或按规则禁用，并展示原因。
- 待办点击后进入对应业务详情/审批详情。
- 审批不在左侧导航中出现。

详情 tab 内容要求：

- 详细资料：车辆基础信息、归属信息、生命周期信息分组表单，字段值要与顶部摘要一致。
- 团队成员：负责人、驾驶员、协作人、审批人、权限角色、加入时间，不能复用角色权限表。
- 金额/比例设置：如果车辆业务没有强金额场景，要改为“费用/预算/分摊”并展示维保预算、保险费用、折旧比例、部门分摊。
- 附件：附件名、类型、上传人、上传时间、版本、预览/下载操作。
- 打印记录：模板名称、模板版本、打印人、时间、结果、预览/下载。
- 操作记录：时间线或日志表，包含操作人、动作、前后值、审批结果、追踪 ID。
- 每个 tab 都必须是专属业务数据结构，禁止复用通用 `matrix` 或权限表格。

## 6. 系统后台配置细节

- 成员分配。
- 菜单/模块权限。
- 页面动作权限。
- 字段权限。
- 数据权限。
- 权限预览。

权限配置：

| 区域 | 内容 |
|------|------|
| 模块权限 | 车辆档案、维保记录、驾驶员 |
| 动作权限 | 查看、新建、编辑、删除、转移、导入、全部导出、导出选中、批量编辑、打印 |

`system-admin/modules.html`：

- 左侧模块树：车辆管理 / 车辆档案 / 维保记录 / 驾驶员。

- 主按钮：新建模块。
- 左侧模块树必须是真树：模块分组、模块、子模块有层级、缩进、展开/收起、状态、最近发布版本；禁止用 stepper 或普通卡片代替。

`system-admin/module-create.html` 必须展示七步配置链：

1. 基础信息。
2. 模块字段。
3. 列表。
4. 筛选。
5. 场景。
6. 页面动作。
7. 发布。

字段配置抽屉示例：

| 分组 | 配置项 |
|------|--------|
| 基础 | 显示名称、字段编码、字段类型、排序 |
| 展示 | 表单显示、详情显示、列表显示、表单占宽 |

| 来源 | 字典、关联模块、子表、手动选项 |
| 列表 | 可搜索、可筛选、可排序、可导出 |
| 权限 | 默认可见、默认可编辑、审批节点字段权限 |

字段类型必须覆盖主流无代码/低代码能力，不只展示少数示例：

- 基础：单行文本、多行文本、手机号、邮箱、URL、身份证号、数字、百分比、金额、日期、日期时间、日期范围、时间、时间范围、开关。
- 选项：单选、多选、级联选择、标签、状态。
- 组织：人员、部门、组织/租户。
- 媒体：附件、图片、文件组、签名、条码/二维码。
- 业务：自动编号、关联数据、引用字段、子表、地址、地理位置、评分、进度。
- 高级：公式、汇总、查找、聚合、JSON、密码/密钥、系统字段、AI 填充字段（后续 Agent 能力启用后）。

字段类型注册表必须作为开发契约的一部分表达，每种字段类型至少声明：

- 存储形态：数据库类型、JSON 结构、关联键、附件引用或计算字段来源。
- 筛选操作符：等于、包含、范围、为空、属于部门树、人员范围、多选包含、相对日期等。
- 默认值与校验：必填、唯一、范围、格式、表达式校验、跨字段校验。
- 权限能力：列表显示、详情显示、编辑、导出、脱敏、审批节点临时可见/可改。
- 导入导出：模板列、字段匹配、错误反馈、脱敏导出和历史停用选项展示。

字段配置必须按字段类型展示专属配置，不得只用一张通用表格：

- 金额：币种、精度、千分位、负数规则、脱敏。
- 数字/百分比：精度、单位、范围、默认值、统计口径。
- 选项/字典：选项来源、颜色、图标、默认项、停用项历史展示。
- 关联数据：目标模块、显示字段、值字段、筛选条件、单选/多选、反向关联。
- 子表：子表列、行权限、最小/最大行数、汇总字段、导入导出方式。
- 公式/汇总：表达式、依赖字段、预览结果、错误定位、重算策略。
- 人员/部门：选择范围、多选、是否包含停用成员、数据权限联动。
- 附件/图片：数量、大小、类型、预览、水印、下载权限。
- 系统字段：只读、审计、列表/详情可见、导出脱敏。

必须画出两个字段示例：

- `车辆状态`：单选下拉，绑定字典“车辆状态”，可筛选。
- `驾驶员`：关联模块“驾驶员”，显示字段“姓名”，单选。

列表配置：

- 默认列、列宽、固定列、默认排序、是否可导出。
- 列表配置必须是专属配置界面：列清单、显示开关、拖拽排序、列宽、固定列、默认排序、权限/导出开关，不能复用通用权限矩阵。

筛选配置：

- 快捷搜索字段。
- 高级筛选字段。
- 控件类型。
- 操作符。
- 默认值。
- 筛选配置必须是专属配置界面：筛选字段、控件类型、操作符、默认值、是否快捷搜索、是否高级筛选，不能复用通用权限矩阵。

场景配置：

- 全部车辆、在用车辆、待年检、维保中、我负责的。
- 场景名称、筛选条件、默认排序、可见角色。
- 场景配置必须展示场景列表、条件组、排序、可见角色、默认场景、复制/停用操作，不能复用通用权限矩阵。

页面动作：

- 新建、编辑、删除、转移、导入、全部导出、导出选中、批量编辑、打印。
- 动作位置、权限、禁用规则、二次确认、是否写日志。
- 页面动作配置必须展示动作位置、按钮文案、图标、权限点、禁用规则、二次确认、日志记录、是否批量，不能复用通用权限矩阵。

导入导出配置放在模块配置内，不新增独立左侧导航：

- 导入模板字段、必填校验、唯一校验、重复策略、预检查规则、错误行反馈。
- 导出字段、字段顺序、脱敏策略、导出范围、导出格式、后台任务阈值。
- 导入导出配置要有版本号，发布后运行端使用已发布版本。

打印模板配置放在模块配置内，由“打印”动作引用：

- 模板列表：模板名称、适用模块、版本、状态、最近发布、操作。
- 模板设计：左侧字段/子表/图片/签章组件，中间打印页面预览，右侧属性面板。
- 模板绑定模块字段，不出现不知道取哪个字段的模板。
- 打印前必须有预览；支持下载或导出 PDF。
- 打印记录进入详情页“打印记录”标签，记录模板版本、操作人、时间和结果。

发布：

- 主字段检查。
- 默认列检查。
- 默认场景检查。
- 动作权限检查。
- 角色覆盖检查。
- 导入导出配置检查。
- 打印模板检查。
- 发布失败原因和影响范围。

配置版本和发布：

- 模块字段、列表、筛选、场景、页面动作、打印模板、导入导出配置都要有草稿/已发布状态。
- 发布前展示影响范围：影响哪些角色、哪些列表、哪些详情字段、哪些导出字段、哪些打印模板。
- 运行端只使用已发布版本，未发布草稿不影响普通用户。
- 历史数据和历史打印记录要能看到当时使用的配置版本。
- 提供回滚入口；回滚前展示将恢复的版本和影响范围。

### 6.4 流程管理

`system-admin/flows.html` 用于配置流程，不是办理审批入口。

流程管理页面推荐结构：

- 上方：流程筛选和流程列表/版本列表，支持按模块、审批类型、触发事件、状态、版本、创建人、更新时间筛选。
- 下方或主工作区：流程设计器，采用左节点库、中间画布、右属性面板三栏结构。
- 节点库宽度 220-260px；右侧属性面板宽度 320-380px；中间画布占主要空间。
- 画布节点必须有连线、箭头、条件分支标签，例如“年检到期 < 30 天 / 是 / 否”“金额 > 5000 / 进入会签”。
- 节点选中后右侧属性面板随节点类型变化，不同节点不能都只有同一套字段。

必须包含：

- 流程列表筛选：绑定模块、触发事件、状态、版本、创建人、更新时间。
- 审批类型：车辆信息变更、车辆停用、批量转移、外部同步失败处理。
- 触发事件：新建、编辑、删除、状态变更、字段值满足条件、批量操作。
- 节点库：开始、条件、审批、抄送、外部 API、结束。
- 流程画布。
- 右侧节点属性。
- 发布检查。
- 流程模拟运行。
- 审批人预览。

节点库至少包含：

- 开始
- 审批
- 条件分支
- 并行网关
- 抄送
- 字段更新
- 外部 API / Webhook
- 定时器 / 超时
- 子流程
- 结束

审批类型配置必须独立表达，不只是画布里的一个节点：

- 审批类型列表：车辆信息变更、车辆停用、批量转移、外部同步失败处理。
- 审批类型字段：绑定模块、触发动作、适用场景、业务状态变更、通知方式、是否启用、版本。
- 审批类型详情可进入对应流程版本列表和流程画布。

审批节点属性：

- 审批方式：或签、会签、顺序会签。
- 审批人来源：成员、角色、部门负责人、字段中的人员、发起人上级、上一节点处理人。
- 表单字段权限：可见、可编辑、必填、隐藏。
- 超时设置。
- 驳回策略。
- 转办/加签/撤回/退回开关。

发布检查错误态：

- 无开始/结束。
- 审批人为空。
- 字段权限冲突。
- 条件循环。
- 外部 API 未测试。

流程版本规则：

- 已发布流程不可直接修改，只能复制为新草稿。
- 新流程实例使用最新已发布版本，老流程实例继续按老版本快照运行。
- 流程绑定规则必须包含绑定模块、触发事件、适用场景、优先级、互斥规则、启停状态和幂等键。
- 同一业务事件命中多个流程时，要明确并行触发、按优先级选择或互斥阻断；不能在开发时临时判断。
- 每个流程实例必须复制运行快照：流程版本、节点配置、审批人规则、字段权限、状态回写、提交时业务字段值、附件清单。
- 每个流程任务必须记录任务快照：节点、候选处理人、领取人、到期时间、意见、补录字段、附件、处理结果和 traceId。
- 高级运行能力必须在原型和 API 契约中同时露出边界：手动插入节点、转办、加签、候选人领取、委托、子流程启动/回调/父流程恢复、外部 API 重试和补偿，必须有状态机、任务版本、实例版本和审计记录。
- 流程设计器画布必须保证节点不被裁切：中间画布最小宽度、横向滚动、缩放或可折叠属性面板至少落地一种；不能在 1440×900 下裁掉超时提醒、结束归档等节点。
- 发布前模拟不同发起人、不同字段值会走到哪些节点、由哪些人审批。
- 审批类型配置要能绑定模块、触发动作、业务状态变更和通知方式。
- 画布示例不能只有开始、条件、审批、结束几个孤立节点，必须展示至少一个条件分支、一个抄送/通知节点、一个外部 API 或字段更新节点，并通过连线体现走向。
- 流程能力目标是覆盖企业级工作流、审批流、办公流的大多数常见场景，包括请假、报销、采购、用印、合同审批、资产领用、工单派发、任务协作、跨部门会签。
- 节点库还要考虑填写表单、任务、通知、等待、定时器、并行/合并网关、数据创建/更新、子流程、Webhook、异常兜底、终止。
- 右侧属性必须体现审批方式、审批人来源、字段权限、超时、退回策略、转办/加签/撤回/退回、状态回写、日志和通知。
- 流程模拟必须能解释为什么走到某节点、候选人是谁、哪些字段可见/可改、超时后怎么处理。

### 6.5 AI Agent 配置与运行入口

AI Agent 是新增产品需求，当前原型必须把“后台配置”和“运行态使用”都画出来，但不能做成绕过权限的噱头按钮：

- 平台后台新增“AI Agent / 模型配置”能力域，配置本地模型、外部模型、API 地址、密钥、额度、并发、日志脱敏、数据出境策略。
- 平台可购买或开通模型授权，再分配给具体系统使用。
- 系统后台可选择使用平台授权模型，也可在权限允许时配置外部第三方模型。
- 系统后台必须有独立的“AI Agent 配置”页，配置系统 Agent 可访问模块、字段、动作、数据范围、确认策略、失败降级和审计策略。
- 运行态顶部提供 AI Agent 入口，能解析用户内容，录入权限内模块数据；保存前必须展示解析结果、字段映射、置信度、影响范围并人工确认。
- 运行态 Agent 对话可查询统计、趋势、待办、任务、日报、项目进度和业务数据；返回结果必须受当前用户系统角色、数据范围、字段权限和脱敏规则限制。
- 工作管理内提供工作 Agent，用于从消息、待办、会议纪要、聊天内容和业务日志中提取任务，生成日报草稿，总结项目进度。
- Agent 所有查询、写入、失败、模型调用和人工确认都要记录日志。
- 平台级 Agent 和系统级 Agent 共享能力边界，但数据范围、授权模型、审计日志和可执行动作必须隔离。

### 6.6 字典、仪表盘、数据源、对外应用

字典管理：

- 字典类型列表。
- 字典项表格。
- 示例：车辆状态，含在用、维保中、闲置、停用。
- 字典项颜色、图标、语义、排序、默认项、启用/停用、被字段引用。
- 字典分类、字典编码、系统内置标记、版本和发布。
- 普通字典、树形字典、级联字典、状态字典、标签字典、字段选项字典都要有不同展示。
- 状态字典用于状态类下拉字段，例如项目任务状态、普通任务状态、日报状态；状态项至少包含颜色、图标、状态语义、排序、默认项、是否终态、是否允许停用。
- 状态字典不是普通选项表，必须支持业务流转约束：`allowedTransitions`、`terminal`、`rollbackAllowed`、`flowLocked`、停用后历史显示和流程占用说明。
- 标签字典用于多选标签字段，例如工作任务标签；标签项至少包含颜色、图标、分组、适用对象、是否可做看板泳道、是否参与预警。
- 字段选项字典用于普通下拉/单选/多选字段；选项项至少包含显示名、值、颜色、图标、排序、默认项、停用历史。
- 字典项支持父子层级、颜色、图标、默认项、停用项历史显示。
- 字典引用影响分析：被哪些字段、筛选、流程条件、仪表盘、导入模板、看板列、看板泳道、日历标记引用。
- 草稿修改不影响运行端，发布后运行端使用新版本。

仪表盘管理：

- 组件库。
- 画布。
- 属性面板。
- 数据源绑定。
- 可见角色。
- 发布预览。

数据源：

- 系统内、外部 API、数据库直连。
- 筛选：类型、状态、用途、最近测试结果、负责人。
- 详情：连接配置、认证、测试记录、被引用位置、失败原因。

对外应用：

- 应用列表。
- AppKey 脱敏。
- Secret 状态和轮换。
- IP 白名单。
- 授权范围。
- 授权字段。
- 参数映射。
- 调用日志筛选。

### 6.6 日志

后台日志必须在同一个“日志管理”入口内区分登录日志和业务日志，不能用一张泛“系统日志”混合安全审计和业务审计。平台后台和系统后台都保留“日志管理”一级入口，页面内用页签或分区管理登录日志和业务日志。

登录日志必须有筛选：

- 时间范围
- 账号/姓名
- 登录方式：密码、MFA、SSO、验证码
- 登录结果：成功、失败、锁定
- IP、地点、设备
- 风险类型：异地、失败过多、异常设备
- 关键词

业务日志必须有筛选：

- 时间范围
- 操作人
- 对象/模块
- 业务类型：字段变更、审批、导入导出、OpenAPI、后台作业、AI Agent
- 结果
- IP
- 追踪 ID
- 关键词

操作：

- 查询
- 重置
- 全部导出
- 导出当前结果
- 列设置
- 详情抽屉

日志详情：

- 日志分类：登录日志或业务日志。
- 请求参数。
- 变更前后。
- 错误原因。
- 关联业务对象。
- 追踪 ID。

日志类型至少覆盖：

- 登录日志。
- 业务操作日志。
- 审批日志。
- 导入导出任务日志。
- OpenAPI 调用日志。
- 后台作业日志。
- AI Agent 查询、写入和人工确认日志。
- 错误日志。

### 6.7 待办与消息

平台待办、系统待办、平台消息、系统消息都必须有筛选和状态操作，不能只是空列表。

待办页：

- 布局：左侧待办类型，右侧待办列表，和模块列表一样是可扫描的列表工作台。
- 左侧类型：全部待办、审批待办、提醒待办、今日需处理、超时/即将超时、抄送待阅、任务失败等。
- 筛选：来源平台/系统、来源模块、事项类型、状态、到期时间、处理人、关键词。
- 列：来源、事项标题、业务对象、当前节点、发起人、处理人、到期/剩余、状态、操作。
- 操作：进入详情、同意/拒绝快捷入口、转办、标记已处理、批量已读。
- 待办点击进入对应业务详情右侧工作区，审批按钮仍在详情右侧审批面板中。

消息中心：

- 入口：顶部消息按钮打开右侧抽屉，不切换主页面，不占用模块列表区域。
- 布局：像手机消息一样一条一条消息流展示，每条消息包含未读状态、来源、标题、摘要、时间和标签。
- 筛选：系统、租户、模板、来源、消息类型、已读状态、时间范围、关键词。
- 类型：审批通知、导入完成、导出完成、系统异常、权限变更、配置发布、任务提醒、日报提醒、Agent 结果。
- 操作：标记已读、全部已读、归档、展开全文。关联业务对象的跳转由整条消息点击承担。
- 如果消息关联某个模块、系统、任务、项目或日志，整条消息点击即可跳转；不要在消息卡片里再堆“进入详情、打开任务、查看日志”等重复小按钮。没有权限时跳转禁用并说明原因。
- 审批消息点击进入对应业务数据的审批详情；模块消息点击进入该模块的数据详情；任务/日报消息点击进入对应任务或日报；系统任务消息点击进入任务日志或配置对象。
- 消息本身是完整内容，不需要再做表格详情页；点开消息可在抽屉内展开全文。

### 6.8 工作管理

工作管理把项目、任务组、任务、日报、日历和统计整合成一套协作能力，当前原型必须展示可确认骨架。主流结构建议拆成四个主标签：仪表盘、项目任务、普通任务、日报。

页面必须覆盖：

- 仪表盘：我的任务、我派发的任务、今日日报、逾期风险、项目进度、今日预警、当月完整工作日历。项目/今日预警与月历采用上下布局，保证两块都能完整阅读。
- 项目任务：项目列表、项目详情、任务组、项目任务列表、项目任务看板、项目任务日历、任务详情、指派、多人协作、标签、优先级、截止时间、完成度、评论、回复、附件、验收、完成时间和预警。列表和看板通过按钮互斥切换，列表有分页，看板不分页并通过向下滚动自动加载。
- 普通任务：普通任务列表、普通任务看板、快速新建一行任务、后续补项目/任务组/业务对象/标签/截止时间、普通任务详情、状态和提醒。列表和看板通过按钮互斥切换，列表有分页，看板不分页并通过向下滚动自动加载。
- 日报：我的日报列表、日报筛选、手动填写日报、自动生成今日日报草稿、日报详情、日报模板、日报可见范围、评论反馈。
- 日历：按日/周/月展示任务截止、项目里程碑、日报填写情况、逾期和今日需处理。
- 统计：按人、项目、标签、状态、日期统计任务完成、逾期、日报提交和项目风险。

工作管理规则：

- 老板/管理者可以派发任务、看团队统计和授权范围内日报。
- 员工维护自己负责或参与的任务，填写日报，查看自己的日历。
- 项目负责人维护项目、任务组、项目任务和项目日报。
- 任务可独立存在，也可归属项目、任务组、系统、模块、业务对象；普通任务可以只有一行描述，后续再补项目和业务对象。
- 工作主导航必须明确拆出“项目任务”和“普通任务”两个标签，不能把两类任务混在一个“任务”标签里。
- 项目任务列表和看板是同一批任务的不同视图，看板列、泳道或分组来自工作配置里已发布的下拉单选或多选字段；普通任务可以后续补关联项目。
- 项目任务和普通任务的列表/看板必须互斥显示，不能并列堆在同一屏；列表使用分页，看板使用滚动加载。
- 任务列表、任务看板、任务日历是同一批任务的不同视图，不能重复成多套任务数据。
- 日报页只展示我的日报列表，并提供日期、状态、项目、关键词等筛选项；手动填写日报和自动生成今日日报草稿作为操作入口。
- 日报可从任务、待办、消息、日志和业务对象生成草稿，但草稿素材不在日报列表页常驻铺开。
- 任务关联业务对象时，跳转和字段展示仍受对应系统权限控制。
- 工作配置只配置项目任务字段列表、普通任务字段列表、日报字段列表、字段属性、字段权限、卡片字段、看板取数字段和发布回滚；状态、标签、颜色、图标等选项统一在数据字典配置。

### 6.9 AI Agent

AI Agent 当前原型必须展示两个层面：

- 平台/系统后台配置：模型、授权、额度、脱敏、数据出境、模块/字段/动作/数据范围、确认策略和日志。
- 运行态对话入口：可录入权限内数据、查询统计、提取任务、生成日报草稿、总结项目进度、解释异常。
- 每次对话和写入必须记录策略快照：Agent 策略版本、模型授权版本、提示词版本、当前用户权限快照、字段脱敏快照、工具调用明细、外部发送数据快照和人工确认人。

Agent 写入规则：

- 解析对话后展示目标系统、目标模块、字段映射、关联对象、负责人、截止时间、标签、置信度。
- 用户确认前不能保存。
- 低置信度字段必须要求补充。
- 写入后记录对话、确认人、模型、提示词版本和日志。

Agent 查询规则：

- 查询统计、列表、趋势、待办、任务、日报、项目进度都必须受权限和脱敏控制。
- 返回结果必须显示口径，例如系统、租户、模块、时间范围和筛选条件。
- 批量修改、导出、发起流程必须二次确认。

### 6.10 配置依赖影响分析

模块发布、字典发布、流程发布、工作配置发布、AI Agent 策略发布都必须进入统一依赖影响分析，而不是各自孤立检查：

- 字段被哪些列表、筛选、场景、导入模板、导出模板、打印模板、流程条件、流程表单、仪表盘、OpenAPI、AI Agent、看板引用。
- 字典被哪些字段、状态流转、看板列/泳道、日历标记、流程条件和导入模板引用。
- 流程被哪些模块、按钮、状态回写、待办、消息、日志和数据锁定规则引用。
- 发布事务边界：哪些配置必须同版本发布，哪些可以灰度，哪些失败后可回滚，哪些需要阻断发布。
- 影响分析必须展示失败项、修复入口、可回滚性、历史数据展示策略和 traceId。

## 7. 状态与权限

关键页面至少体现：

- 加载中。
- 空状态。
- 无权限。
- 禁用。
- 错误提示。
- 保存成功。
- 发布成功。

开发前必须把这些状态落成统一组件和接口语义，原型中至少要有可见样例：

- 加载中：列表骨架屏、详情摘要骨架、抽屉局部 loading、导入导出任务进度；禁止整屏白屏。
- 空状态：无数据、筛选无结果、消息为空、待办为空分别给出不同文案和操作，例如新建、清空筛选、刷新、去配置。
- 无权限：菜单无权限隐藏；直接访问页面显示无权限页；字段无权限脱敏；按钮无权限隐藏或禁用并说明短原因。
- 错误态：网络失败、接口失败、配置发布失败、流程模拟失败、导入预检查失败都要显示错误原因、追踪号和重试入口。
- 禁用态：审批中、流程锁定、跨状态批量、字段停用、字典停用、无导出权限等场景要显示禁用原因。
- 后台任务态：导入、导出、AI Agent 写入、发布检查都要有排队中、处理中、成功、部分成功、失败和可追踪记录。
- 统一后台任务契约必须包含 `taskId`、`bizType`、`idempotencyKey`、`status`、`progress`、`retryable`、`cancelable`、`resultFile`、`errorFile`、`traceId`、`auditLogId`、`createdBy`、`createdAt`、失败原因和部分成功明细。
- AI Agent 写入、导入、导出、发布检查、流程模拟都必须使用统一任务/结果模型；成功、失败、部分成功都要能从消息、待办、日志或任务反馈入口追踪回业务对象。

全系统状态颜色必须统一，设计中要能看出这些颜色来自可配置状态字典，而不是各页临时取色：

- 灰色：待处理、未开始、草稿、待提交等低强调状态。
- 蓝色：处理中、审批中、当前系统、当前节点等推进中状态。
- 橙色：待确认、待验收、临期、待续期、AI 低置信度等需要关注但不是错误的状态。
- 绿色：完成、通过、成功、有效、健康等正向结果。
- 红色：失败、拒绝、驳回、逾期、停用、暂停等异常或阻断状态。
- 自定义标签可以使用独立颜色，但不能覆盖上述核心状态语义。

权限规则：

- 无查看权限：菜单不显示或显示无权限页。
- 无新建权限：隐藏新建按钮。
- 无编辑权限：隐藏编辑按钮。
- 无导出权限：隐藏导出入口。
- 无打印权限：隐藏打印入口。
- 数据状态不允许操作：按钮 disabled，并给短提示。
- 前端隐藏只是体验，页面要表达后端仍会兜底校验。
