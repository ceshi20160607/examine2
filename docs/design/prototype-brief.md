# Open Design 主 Brief（全量整合版）

> 这是一份可直接交给 Open Design 生成原型的完整 brief。
> 请按本文生成一套完整、统一、现代的企业后台原型。

## 0. 输出要求

- 输出目录：`docs/design/prototypes/redesign/`
- 输出形式：可直接浏览的静态 HTML 原型，包含统一 CSS/JS 或每页内联样式均可。
- 语言：中文。
- 风格：现代、克制、密度合理的企业后台，不做营销页，不做大留白，不做接口调试页。
- 组件气质：接近 Naive UI / Ant Design / Linear / Notion / Stripe Dashboard 的成熟后台体验。
- 重点：普通业务用户顺手使用，管理员清楚配置，不暴露技术 ID、JSON、moduleId、appKey 明文等调试信息。

## 1. 产品定位

unexamine 是一个可配置业务系统平台。

平台要让不会写代码的管理员完成：

1. 创建业务系统。
2. 配置模块组。
3. 在模块组下创建业务模块。
4. 配置字段、列表、表单、详情、页面动作。
5. 配置仪表盘、数据源、字典、流程、权限、对外应用。
6. 邀请成员使用。
7. 让普通用户在运行态完成业务数据的新建、查询、筛选、详情、导出和审批。

本次原型以“车系统”为演示业务系统：

- 系统名：车系统
- 模块组：车辆管理
- 组内模块：车辆档案、维保记录、驾驶员
- 示例成员：plat_admin、che
- 示例角色：系统管理员、车辆操作员、只读审计员

## 4. 主流设计原则

### 4.1 后台工作台密度

后台页面应该服务高频操作和信息判断：

- 标题区简洁。
- 操作区紧凑。
- 表格区优先。
- 不用大卡片堆叠承载简单控件。
- 不用大面积说明文字挤压业务数据。
- 同类操作合并成按钮组、下拉菜单或抽屉。

业务列表首屏必须优先展示表格，而不是被场景、搜索、筛选、批量提示挤满。

### 4.2 控件使用

- 主按钮每页只保留一个。
- 常用操作放显眼位置，低频操作进“更多”或下拉菜单。
- 高级筛选、列设置、详情优先用右侧抽屉。
- 危险操作要弱化并确认，不放在行内主按钮。
- 表格列宽、固定列、排序状态要清楚。
- 批量操作只在勾选后出现，不提前占位。

### 4.3 视觉规范

- 主色：蓝色系，用于主按钮、选中态、链接。
- 成功：绿色。
- 警告：橙色。
- 危险：红色。
- 页面背景：浅灰。
- 内容面板：白色。
- 卡片圆角：6-8px。
- 表格行高：约 42-46px。
- 页面字体：14px 正文，20px 左右页面标题。
- 1440×900 下，业务列表首屏至少展示 8 行数据。

## 6. 重点页面设计要求

### 6.0 运行态业务页骨架（强制 · 优先于本节其它描述）

**本节只规定结构，不规定 1000px 等具体尺寸——由 Design 输出 token 与比例。**

| 序号 | 结构 | 必须 |
|------|------|:----:|
| A | 顶栏显示**模块组**（+ 仪表盘） | ✅ |
| B | 点击模块组 → **左侧**展示组内**模块**列表 | ✅ |
| C | **右侧**为当前模块**业务列表** | ✅ |
| D | 列表上方：**搜索** + **场景**；**导出**在场景行**右侧** | ✅ |
| E | 点击列表行 → **列表右侧**出现**详情**（列表与详情同屏） | ✅ |
| F | 详情顶部：**重要信息摘要** + **编辑 / 删除**（及权限内动作） | ✅ |
| G | 详情中部：**标签页**切换各信息分区 | ✅ |
| H | **审批信息**与标签页**内容区**同高并列（通常详情右栏） | ✅ |

**验收页：** `system/runtime-list.html` 必须演示 A–H 全部结构点。

## 6.1 车辆档案列表

文件：`system/runtime-list.html`

这是最重要的业务列表页，必须像真实业务工作台，不像临时数据表。

### 布局

从上到下：

1. 运行态顶栏。
2. 左侧组内模块导航。
3. 标题行。
4. 单行紧凑工具栏。
5. 按需出现的选中条。
6. 表格。
7. 分页。
8. 右侧抽屉。

### 标题行

高度约 48px。

左侧：

- 标题：车辆档案
- 小号摘要：当前场景、筛选结果、排序状态

右侧：

- 只放一个主按钮：新建车辆

禁止：

- 标题区和工具栏同时出现两个“新建”。
- 用大段说明文字占据首屏。

### 单行工具栏

高度约 44px。控件从左到右：

1. 场景选择：`场景：待年检` 下拉。
2. 最多 2 个快捷场景按钮，例如 `在用`、`维保中`。
3. 搜索框，placeholder：`搜索车牌、品牌型号、驾驶员`。
4. 高级筛选按钮，筛选后显示数量 badge。
5. 已应用筛选 chips，例如 `状态：在用`、`年检≤30天`，过多折叠。
6. 列设置按钮。
7. 导入按钮。
8. 导出下拉，包含：
   - 全部导出
   - 导出选中

规则：

- 搜索框回车或图标触发，不额外放一个占位很大的“快捷搜索”按钮。
- 场景不能单独横铺一整行胶囊。
- 场景下拉至少包含：全部车辆、在用车辆、待年检、维保中、我负责的。
- 选择项目/选择系统如需出现，只能放顶栏或标题行小型下拉，不独占一行。
- 全部导出按当前场景和筛选条件导出全部匹配数据。
- 导出选中仅在勾选后可用，未勾选时 disabled。

### 选中条

未勾选时不显示。

勾选后出现紧凑 selection bar，高度不超过 40px：

`已选 3 条`、`转移`、`删除`、`导出选中`、`批量编辑`、`清除选择`

规则：

- 禁用原因用 tooltip 或短句，例如：`含 1 条在用车辆，不可删除`。
- 不要把所有限制规则写成长段黄色提示。
- 转移、删除、导出、批量编辑受权限和数据状态控制。

### 表格列

| 顺序 | 列 | 要求 |
|------|----|------|
| 1 | 复选框 | 表头全选 + 行选择，固定左侧 |
| 2 | 序号 | 分页连续序号，固定左侧 |
| 3 | 车牌号 | 主识别字段，可点击打开详情抽屉 |
| 4 | 品牌型号 | 示例：丰田凯美瑞 |
| 5 | 车辆状态 | 标签：在用、维保中、闲置、停用 |
| 6 | 归属部门 | 示例：行政部、运营部 |
| 7 | 驾驶员 | 空值显示“未分配” |
| 8 | 购置日期 | 可排序 |
| 9 | 年检到期 | 可排序，30 天内到期使用提醒态 |
| 10 | 最近维保 | 可排序 |
| 11 | 操作 | 详情、编辑、更多，固定右侧 |

表格要求：

- 1440×900 首屏至少展示 8 行数据。
- 表头 sticky。
- 左侧复选框、序号、车牌号可固定。
- 操作列固定右侧。
- 行点击打开右侧详情抽屉。
- 危险操作放“更多”中，不作为行内主按钮。

### 高级筛选抽屉

右侧抽屉，宽度 420-480px。

字段：

- 车辆状态
- 归属部门
- 驾驶员
- 购置日期范围
- 年检到期范围
- 最近维保范围

按钮：

- 查询：主按钮。
- 重置：次按钮。
- 保存为场景：弱按钮或更多动作，不与查询同级抢主操作。

提交后关闭抽屉，在工具栏展示筛选 chips。

### 列设置抽屉

右侧抽屉。

内容：

- 显示/隐藏
- 拖拽排序
- 列宽
- 固定列
- 保存为我的表头

### 详情抽屉

右侧抽屉。

字段：

- 车牌号
- 品牌型号
- 车辆状态
- 归属部门
- 驾驶员
- 购置日期
- 年检到期
- 最近维保
- 备注

底部：

- 编辑

无编辑权限时隐藏编辑。

## 6.2 建模页面

文件：`system/admin-modeling.html`

> **配置项逐项清单（字段抽屉、列表/场景/动作、映射）：** 必读 [`config-spec.md`](./config-spec.md) §2–§10。Open Design 不得只做空 Tab。

定位：管理员配置某个业务模块的字段、列表、表单、详情、动作、菜单与发布。

页面要求：

- 顶部显示模块上下文：车辆管理 / 车辆档案。
- 顶部右侧：发布为主按钮，保存草稿为次按钮。
- 六个 Tab（见 config-spec §2）；**至少字段抽屉 + 场景表 + 动作勾选** 有真实内容。

### 6.2.1 字段配置抽屉（必须在原型中打开一条示例）

编辑「车辆状态」字段时，抽屉须可见：

| 分组 | 配置项 |
|------|--------|
| 基础 | 显示名称、字段编码、类型=单选下拉、排序 |
| 展示 | 表单显示☑、详情显示☑、列表显示☑、表单宽度=半行 |
| 数据 | 必填☑、只读☐、**唯一☐** |
| 下拉来源 | **数据字典 → 车辆状态** |
| 列表 | 可搜索☐、**可筛选☑**、可排序☐ |

编辑「驾驶员」字段时，抽屉须可见：**关联模块=驾驶员 · 显示字段=姓名 · 单选**。

### 6.2.2 其余 Tab 最低内容

| Tab | 至少展示 |
|-----|----------|
| 列表配置 | 8 列顺序表 + 固定左列=车牌 |
| 筛选配置 | 快捷搜索 3 字段；高级筛选 4 字段 |
| 场景配置 | 「全部」「在用」「待年检」+ 条件摘要列 |
| 页面动作 | export_all / export_selected / import / transfer / delete 勾选态 |
| 菜单发布 | 归属模块组=车辆管理；发布检查清单 |

必须体现：

- 列表页的场景、列设置、筛选字段 **来自此处配置**。
- 导出属于页面动作，不是独立导出中心。
- 对外应用/导入/流程中的「映射到模块.字段」与字段编码一致（见 config-spec §9）。

- 成员来自平台用户，不创建第二套登录账号。
- 成员可以拥有多个系统角色。
- 停用成员不删除历史业务数据。
- che 是普通成员，只能进入运行态。

## 6.5 角色权限

文件：`system/admin-roles.html`

定位：配置当前系统内角色能做什么。

布局：

- 左侧：角色列表。
- 右侧：角色详情和权限配置。

角色示例：

- 系统管理员
- 车辆操作员
- 只读审计员

权限分区：

| 权限区 | 内容 |
|--------|------|
| 模块权限 | 车辆档案、维保记录、驾驶员；查看、新建、编辑、删除、导出 |
| 字段权限 | 字段可见、字段可编辑 |
| 数据权限 | 全部、本部门、本人负责、自定义范围 |
| 动作权限 | 转移、批量编辑、导入、全部导出、导出选中 |

规则：

- 角色页不维护用户基础信息。
- 可以展示已绑定成员数和查看成员入口。
- 权限配置要能解释 che 为什么能看列表但看不到后台。

## 6.8 平台 Flow 配置

文件：`platform/plat-admin-flow.html`

定位：配置跨系统或平台级流程。

内容：

- Flow 列表：名称、编码、状态、触发方式、最近发布、操作。
- 画布入口：审批、条件、抄送、外部 API 节点。
- 详情区：版本、发布状态、调用情况。

规则：

- 平台 Flow 不绑定单一系统模块。
- 平台 Flow 可以通过平台应用授权对外开放。

## 6.9 平台应用配置

文件：`platform/plat-admin-apps.html`

定位：配置平台级对外应用。

内容：

- 应用列表：应用名称、AppKey 脱敏、状态、授权 Flow 数、最近调用、操作。
- 详情区：绑定平台 Flow、scope 授权、参数映射。

参数映射表：

- 接口参数名
- 来源类型
- 来源值
- 类型
- 必填

规则：

- AppKey/secret 不明文完整展示。
- 平台应用用于开放平台 Flow 或平台能力。
- 不要和系统后台的“对外应用”混淆。

## 6.10 系统对外应用

文件：`system/admin-external-app.html`

定位：当前系统对外访问入口。

内容：

- 应用名称。
- 状态。
- 凭证脱敏。
- 授权范围：可访问的业务模块和动作。
- 参数映射。
- 调用日志入口。

规则：

- 系统对外应用不是模块父级容器，不能在应用下创建模块。
- 它可以授权外部系统访问当前系统内指定业务模块的指定动作，例如查询车辆档案、写入维保记录。

## 6.11 流程配置

文件：

- `system/admin-flow.html`
- `platform/plat-admin-flow.html`

系统 Flow 内容：

- 绑定模块。

- 节点面板：审批、条件、抄送、外部 API。
- 画布区。
- 节点属性区。

平台 Flow 内容：

- 不绑定单一业务模块。

规则：

- 系统 Flow 和平台 Flow 的边界要清楚。
- 流程设计器不要做成 JSON 编辑器。

## 7. 状态与权限要求

每个关键页面至少体现这些状态中的一部分：

- 加载中。
- 空状态。
- 无权限。
- 禁用。
- 错误提示。
- 保存成功。
- 发布成功。

权限规则：

- 无查看权限：菜单不显示或进入后显示无权限页。
- 无新建权限：隐藏新建按钮。
- 无编辑权限：隐藏编辑按钮。
- 无导出权限：隐藏导出入口。
- 无转移权限：隐藏转移操作。
- 数据状态不允许操作：按钮 disabled，并给短提示。

## 9. 禁止项

- 禁止把业务页面做成接口调试页。
- 禁止暴露 moduleId、recordId、JSON schema、完整 secret。
- 禁止出现独立“导出中心”导航。
- 禁止把模块挂在“应用”下面。
- 禁止平台侧栏重复出现待办/消息文字菜单。
- 禁止 che 看到系统后台或平台后台入口。
- 禁止成员和角色混在同一个页面 Tab。
- 禁止列表页顶部控件占满首屏。
- 禁止场景单独铺满一整行大胶囊。
- 禁止搜索框、场景、选择项目/系统分别独占大区域。
- 禁止一个页面出现两个同级主按钮。
