## 审阅清单

- [ ] **四套壳分离**：平台工作台、平台后台、系统业务页、系统后台导航完全分开。
- [ ] **平台工作台**：顶部仪表盘、Flow、应用；右侧待办、消息、个人信息。
- [ ] **平台后台**：左侧平台信息、组织架构、角色管理、仪表盘管理、配置管理、日志管理。
- [ ] **系统业务页顶部**：参考 CRM 骨架，顶部展示系统/应用入口、仪表盘、模块分组、待办、消息、个人信息和工具图标，当前分组高亮。
- [ ] **业务分组布局**：点击模块分组后，左侧显示该分组下模块，右侧显示当前模块数据列表。
- [ ] **详情打开方式**：详情从右侧打开并保留左侧列表上下文，不做居中普通弹窗。
- [ ] **详情骨架**：详情顶部有模块标签、主标题、关键摘要、转移/编辑/删除/打印/更多按钮。
- [ ] **详情标签页**：车辆详情使用详细资料、维保记录、授权驾驶员、附件、打印记录、操作记录；其他业务模块使用各自专属 tab，不用通用矩阵凑内容。
- [ ] **详情审批面板**：详情右侧有审批流程信息、当前节点、处理人、历史流程入口和审批按钮。
- [ ] **系统后台**：左侧系统信息、组织架构、角色管理、模块管理、工作配置、AI Agent 配置、流程管理、字典管理、仪表盘管理、数据源、对外应用、日志管理。
- [ ] **返回关系**：系统后台只有返回首页回业务数据首页，不和业务页混用导航。
- [ ] **角色边界**：che 看不到系统后台和平台后台；sys_admin_vehicle 可进系统后台但不可进平台后台；platform_member 只能进平台工作台和授权系统；platform_admin_root 可进平台后台。
- [ ] **系统切换**：顶部系统切换是唯一多系统入口，包含当前系统、角色、租户、进入/申请/禁用原因，切换后刷新角色、模块、字段权限、数据范围、待办和消息。
- [ ] **系统成员映射**：平台账号进入系统前必须有系统成员映射、系统角色和有效数据范围；平台内置超级管理员不能绕过系统权限直接看或改业务数据。
- [ ] **无权限访问**：隐藏菜单之外，直接访问无权限页面必须显示无权限态/403、缺失权限、当前角色、申请入口和 requestId。
- [ ] **模块组模型**：模块组只负责顶部分组、左侧组内模块、排序、可见角色和发布关系；业务数据归属 systemId/tenantId/moduleId，不按 appId 归属。
- [ ] **对外应用模型**：对外应用只负责 OpenAPI 接入来源、appKey/secret、scope、回调、限流和审计来源，不作为系统内模块父级。
- [ ] **平台授权边界**：平台普通成员只能查看/申请授权，不能新增或配置系统授权；平台授权配置只对平台管理员或授权管理员开放。
- [ ] **列表能力**：业务列合理、序号、勾选、收藏、表头排序、高级筛选、列设置、全部导出、导出选中、批量操作限制。
- [ ] **导入导出反馈**：导入有模板下载、字段匹配、预检查、错误行、任务状态和批次结果；导出有全部导出、导出选中、后台任务、完成消息和下载入口。
- [ ] **模块配置**：创建模块页包含基础信息、字段、列表、筛选、场景、页面动作、发布，且有真实控件。
- [ ] **打印模板配置**：模块配置内能看到模板列表、字段绑定、模板版本、打印预览、导出 PDF 和详情打印记录。
- [ ] **配置版本发布**：字段、列表、筛选、场景、动作、导入导出、打印模板有草稿/已发布、发布影响和回滚入口。
- [ ] **角色权限**：角色页包含成员分配、模块、字段、数据、动作权限和权限预览。
- [ ] **有效权限计算**：原型和 brief 明确多角色合并、显式拒绝优先、数据范围并集、字段权限与审批节点权限冲突处理、后端兜底。
- [ ] **有效权限返回结构**：有效权限详情包含 permissionVersion、sourceRoleIds、denyPolicyIds、dataScopeExpression、systemMemberId、字段权限矩阵、按钮禁用原因和解释链路。
- [ ] **流程配置**：流程管理包含审批类型、触发事件、节点库、节点属性、流程模拟、审批人预览、版本快照、发布检查和错误态。
- [ ] **流程高级运行策略**：转办、委托、加签、候选人领取、手动插入节点、子流程、外部 API 重试/补偿在原型中有配置和状态机样例。
- [ ] **流程快照**：流程绑定、优先级、互斥、幂等键、实例快照、任务快照和 traceId 已明确。
- [ ] **待办消息**：待办和消息都有来源、类型、状态、时间、关键词筛选，并能进入业务详情、任务结果或日志详情。
- [ ] **日志检索**：平台日志和系统日志都有时间、操作人、对象/模块、类型、来源、结果、IP、关键词筛选。
- [ ] **真实内容**：配置页没有“名称/类型/说明/角色/参数映射 + 数字序号”这类占位数据。
- [ ] **组织架构布局**：左侧是真部门树，宽度合理，右侧员工列表可扫描，不用 stepper 或卡片代替树。
- [ ] **树节点交互**：组织树、角色树、模块树、字典分类和待办类型都能选择节点并刷新右侧列表/配置语义，不能只是静态左栏。
- [ ] **流程画布**：流程节点有连线、箭头、条件分支标签、节点库和右侧属性面板，不是节点卡片网格。
- [ ] **流程画布宽度**：流程画布在 1440×900 下不裁掉节点；必要时使用最小画布宽度、横向滚动、缩放或折叠属性面板。
- [ ] **导入导出交互**：运行态列表下方不常驻导入导出面板，导入导出通过弹窗/抽屉/下拉和任务反馈完成。
- [ ] **详情精细度**：详情右侧工作区贴顶贴底、宽度足够，tab 内容是专属业务数据，不复用权限矩阵。
- [ ] **关键配置入口**：模块场景、页面动作、发布到业务页、工作字段、工作看板、流程类型、流程模拟、字典发布、AI Agent 发布检查都有可开发页面或抽屉，不只是 toast。
- [ ] **平台 Flow 专属设计**：平台 Flow 不复用通用说明抽屉，必须展示触发源、影响系统、节点连线、重试/补偿、运行批次、平台任务和 traceId。
- [ ] **注册初始化引导**：注册创建系统后进入系统后台初始化引导，能看到组织、角色、模块、字段、流程、字典、邀请成员和发布前检查。
- [ ] **关键运行操作**：流程节点属性、审批通过/驳回/转交/加签、AI 写入确认、导入导出、日志导出均有可开发抽屉或后台任务承接，不只是 toast。
- [ ] **行操作去重**：列表整行点击为详情主动作后，操作列不再重复放“详情”按钮，只保留配置、处理、编辑、更新、查看日志、转移、导出等差异动作。
- [ ] **通用状态**：加载、空、无权限、错误、禁用、后台任务态在原型和 brief 中有统一样例。
- [ ] **后台任务契约**：导入、导出、发布检查、流程模拟、AI 写入等长任务有 taskId、bizType、idempotencyKey、status、progress、resultFile/errorFile、traceId、auditLogId、失败明细和重试/回滚边界。
