# 设计范围裁决（Design vs Build）

> **agentId:** pm  
> **日期:** 2026-06-15  
> **回答：** 审批流 / 对外 API 映射 / 角色三维权限 — 哪些现在必须在 Design 定下来，哪些可以开发分期。

---

## 总原则

| 层级 | Design（ui-spec + 原型）必须有什么 | Build（实现）再做什么 |
|------|-----------------------------------|----------------------|
| **IA** | 有哪些配置页、入口在哪、与谁解耦 | — |
| **交互形态** | 节点_palette、权限三个 Tab、参数映射表长什么样 | 每个枚举的全部校验规则 |
| **MVP 剧本** | 车系统能走通的一条示例路径 | 全量节点类型、复杂映射引擎 |
| **原型** | **每类页面 1 份**（结构 + 代表性示例） | **不是**每个字段、每个对话框都做 HTML |

**结论：** 你提的三点 **都有必要在 Design 里出现**（页面 + 信息结构 + MVP 示例），但 **不必在 MVP 原型里做全量细节**；细节写在 `ui-spec.md`，契约阶段再冻 API 字段。

## 1. 审批流（多层 + 多节点类型）

### 产品目标（全量愿景）

支持主流审批能力：

| 节点/能力 | 说明 |
|-----------|------|
| 多层审批 | 多节点串行/并行 |
| 条件分支 | 按字段值、表达式走不同支路 |
| 普通审批 | 指定角色/成员/主管 |
| 抄送 | 仅通知不阻塞 |
| 外部 API 调用 | 节点触发 HTTP 回调 |
| 业务数据上动态加签 | 运行中在实例上追加节点 |

### Design 必须交付

| 项 | 交付物 |
|----|--------|
| 流程配置页 IA | `admin-flow.html`：左侧触发事件，中间**流程图画布**，右侧节点属性 |
| 节点类型 **Palette（面板）** | 画布旁或顶部：审批、条件、抄送、外部 API、（动态加签标注「运行态」） |
| 多层示例 | 车系统：新建车辆 → 条件(金额/状态) → 主管审批 → 抄送 |
| ui-spec | 每节点类型配置字段清单（见 ui-spec §5.8.7 扩展） |

### MVP 实现分期（Build）

| 能力 | MVP | 增强 |
|------|-----|------|
| 2~3 层串行审批 | ✅ | — |
| 条件分支（单字段） | ✅ | 复杂表达式 |
| 抄送节点 | ⭕ 配置+通知 | 已读回执 |
| 外部 API 节点 | ⭕ 设计有，实现可 stub | 重试、签名 |
| 运行态动态加签 | ❌ | 二期 |
| 并行会签/或签 | ❌ | 二期 |

### 原型要做到哪一步

- **要：** 流程画布 + 3 种节点图示（审批、条件、抄送）+ 一种外部 API 节点（灰色「增强」标签亦可）
- **不要：** 每种条件运算符一个弹窗 HTML

## 2. 对外 API 应用（参数映射）

### 产品目标

对外应用不仅能发 AK，还要能**按外部系统要求组装请求**：不同接口数据结构不同，通过**参数对应关系**（本系统字段 → 接口参数）配置。

### Design 必须交付

| 项 | 交付物 |
|----|--------|
| 列表 + 新建/编辑 | `admin-external-app.html` |
| **参数映射区** | Tab 或折叠：「请求参数映射」表格列：接口参数名、来源（模块字段/常量）、类型、必填 |
| 授权范围 | 可选模块、可选动作 |
| ui-spec | 映射行字段、校验提示、示例（车辆档案.车牌 → `plateNo`） |

### MVP 实现分期

| 能力 | MVP | 增强 |
|------|-----|------|
| 单模块字段 → 查询/写入参数 | ✅ | — |
| 多模块、嵌套 JSON 结构 | ❌ | 映射设计器 |
| 响应字段反写业务数据 | ❌ | 二期 |
| 转换函数（格式/计算） | ❌ | 二期 |

### 原型要做到哪一步

- **要：** 一张映射表示例 3~5 行 + 说明文案
- **不要：** 完整 JSON Schema 编辑器

## 3. 角色权限（模块 + 字段 + 数据）

### 产品目标

角色配置是三维的：

| 维度 | 内容 |
|------|------|
| **模块/动作** | 哪些模块、新建/编辑/删除/导出/审批… |
| **字段** | 模块内哪些字段可见、可编辑 |
| **数据范围** | 全部 / 本部门 / 仅本人 / 自定义条件 |

### Design 必须交付

| 项 | 交付物 |
|----|--------|
| 角色配置入口 | `admin-members.html` 角色 Tab → **编辑角色** 或独立 `admin-role-permission.html` |
| 三个子 Tab | 模块权限 \| 字段权限 \| 数据范围 |
| 车系统示例 | 「车辆操作员」：车辆档案模块动作 + 字段列勾选 + 数据范围=本部门 |
| ui-spec | 各 Tab 列定义、与成员绑定的关系 |

### MVP 实现分期

| 能力 | MVP | 增强 |
|------|-----|------|
| 模块+动作权限 | ✅ | — |
| 数据范围（全部/本部门/仅本人） | ✅ | 自定义 SQL 条件 |
| 字段可见/可编辑矩阵 | ⭕ 简版（按模块一张表） | 按角色批量模板 |
| 字段级脱敏 | ❌ | 增强 |

### 原型要做到哪一步

- **要：** 三 Tab 结构 + 车辆模块一行示例
- **不要：** 所有模块 × 所有字段整张矩阵 HTML

## 4. 原型：全量页面还是抽样？

### 策略（团队内部统一）

```
原型 P0 = 每类页面 1 个 HTML（结构正确）
ui-spec   = 全部字段、状态、边界（权威细节）
契约阶段  = API 与 ui-spec 对齐
Build     = 全量能力分期实现
```

### 当前 P0 清单（18 页）— 仍然有效

覆盖：**平台主干 + 车系统运行态壳 + 系统后台每类配置 1 页**。

### 本次补充（仍属 P0 原型，在 brief 中加厚）

| 页面 | 加厚内容（非新页） |
|------|-------------------|
| `admin-flow.html` | 节点 Palette + 多层画布示例 |
| `admin-external-app.html` | 参数映射表区块 |
| `admin-members.html` 角色 Tab | 模块/字段/数据三 Tab |

**不增加** 18 页以外的 P0 HTML，除非 ui-spec 新增独立页（如单独 `admin-role-permission.html`）；当前裁决：**角色三维权限放在 admin-members 角色编辑抽屉/页内**，不另开页。

### P1 原型（OD 时间够再做）

flow-todo、runtime-detail、plat-flow、admin-org…

## 5. 对你问题的直接回答

| 问题 | 回答 |
|------|------|
| 审批流多种节点要不要现在考虑？ | **要。** Design 定节点类型与画布 IA；MVP 先实现审批+条件+简抄送。 |
| 对外 API 参数映射要不要现在考虑？ | **要。** Design 必须有映射表 UI；MVP 先做字段→参数单行映射。 |
| 角色模块/字段/数据权限？ | **要。** Design 必须三 Tab；MVP 实现模块+数据，字段简版矩阵。 |
| 这些是否等开发才考虑？ | **产品形态不能等开发**；**全量引擎可以分期开发**。 |
| 原型要全部页面吗？ | **每类页面 1 份 P0**；细节在 ui-spec，不追求所有对话框 HTML。 |

## 7. 可配置仪表盘 + 数据源

### 产品目标

- 仪表盘由**配置**生成：统计、筛选按钮、图标样式
- **数据源**独立管理，供仪表盘组件绑定

| 数据源类型 | 说明 |
|------------|------|
| 系统内 | 模块/字段聚合；**公式计算**（COUNT/SUM/表达式） |
| 外部 API | 第三方 HTTP 接口 |
| 数据库直连 | 外部库只读查询（连接串+SQL） |

### Design 必须交付

| 页 | 原型 |
|----|------|
| 仪表盘配置 | `admin-dashboard-cfg.html` 组件面板+栅格+属性 |
| 数据源 | `admin-datasource.html` 三类型 Tab + 公式示例行 |
| 运行态仪表盘 | `dashboard-*.html` 展示**已配置**统计卡（非写死欢迎语） |

### MVP Build 分期

| 能力 | MVP | 增强 |
|------|-----|------|
| 统计卡+模块组卡 | ✅ | 拖拽布局 |
| 系统内数据源+简单公式 | ✅ | 复杂表达式 |
| 筛选按钮 | ⭕ | 多条件组合 |
| 外部 API 数据源 | ⭕ 配置 UI | 缓存、鉴权 |
| 数据库直连 | 设计有 | 实现增强 |
| 图表组件 | 占位 | 真实图表 |

系统后台维护字典类型与字典项；模块字段（下拉/单选）可**关联字典**作为选项来源。

### MVP Build

## 11. 对你本轮问题的直接回答

| 问题 | 回答 |
|------|------|
| 仪表盘要可配置统计/筛选/图标/数据源？ | **Design 必须**有仪表盘配置页+数据源页；运行态展示配置结果 |
| 数据源三种类型？ | **Design 全有**；MVP 实现优先系统内+公式，API/库直连分期 |
| 数据字典供字段下拉？ | **Design 必须**字典页+字段关联；MVP 实现字典 CRUD+绑定 |
| 系统基础参数图标域名？ | **Design 必须** `admin-basic` P0 |
| 是否等开发？ | **形态不等开发**；直连库、复杂公式、域名验证明细可分期 |
| 原型做多少？ | **每类 1 页** + 仪表盘运行态体现配置效果 |
