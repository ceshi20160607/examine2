# examine2 P20 Open Design 主流后台 UI Brief

状态：`uiux-draft-for-open-design`

来源：`pm-uiux-rework-after-user-feedback`

更新时间：2026-06-13

## 1. 本轮目标

P19 Open Design Codex 原型已被用户复核驳回。P19 解决了一部分概念边界，但整体仍像“需求点说明稿”，不是普通人能直接使用的主流企业后台。

P20 目标是重新生成一版可评审的主流 SaaS 后台 UI 原型，必须体现：

- 顶部全局栏。
- 左侧当前角色/当前工作空间导航。
- 右上角审批、待办、消息、日志、用户基础信息和退出。
- 不同角色登录后看到不同首页、不同导航、不同主操作。
- 平台、系统、运行台和对外应用的边界清晰，但不要用原型切换器冒充真实系统导航。

参考方向：

- Ant Design Layout：顶部主导航通常包含 Logo、一级导航和右侧用户/设置/通知等区域；侧边导航支持多级结构和折叠。
- Ant Design Pro / ProLayout：适合中后台系统的 Header + Sider + Content 框架。
- NNGroup 左侧垂直导航原则：左侧导航适合复杂、可增长的信息架构，便于扫描和定位。

## 2. P19 明确失败点

P20 必须避免：

- 不要在真实产品导航中常驻显示 `P / S / R` 三个工作空间切换按钮。
- 不要把“平台管理 / 系统管理 / 系统运行台”做成原型演示切换器。
- 不要只证明概念分开，而忽略主流后台壳层、右上角任务区、用户入口和退出。
- 不要让所有角色都在同一个页面里切换查看。
- 不要把卡片、指标、列表随意堆在一起。
- 不要把系统选择、Flow、应用、日志、审计做成“页面列表”而缺少真实工作流。
- 不要把顶部栏只做成标题和搜索；右侧必须有任务和用户操作。

## 3. 产品定位

examine2 是一个统一入口与自建业务系统平台：

- 平台层：统一登录、平台组织、平台账号、平台权限、平台级 Flow、平台级对外应用、平台日志、平台审计、平台待办、平台消息。
- 自建系统管理层：系统管理员搭建自己业务系统的成员、角色、字典、模块、字段、页面、菜单、系统内应用配置、流程事件绑定、系统日志、系统审计。
- 业务运行层：普通业务用户进入自己所在系统，使用授权模块处理业务数据、待办、消息、文件和导出。
- 对外集成层：平台级应用用于外部系统或其他系统调用能力，系统内应用配置用于当前系统启用平台级应用能力。

## 4. 总体壳层

### 4.1 顶部全局栏

所有登录后的工作台都使用同一类顶部全局栏，但内容按角色和当前上下文变化。

左侧：

- 产品 Logo：统一业务平台。
- 当前上下文：
  - 平台管理员显示“平台管理”。
  - 系统管理员显示“车队运营系统 / 系统管理”。
  - 普通业务用户显示“车队运营系统 / 业务运行”。
  - 集成管理员显示“平台开放中心”。
- 系统切换入口：只在有多个系统时显示，进入系统选择中心。

中部：

- 全局搜索。
- 平台态搜索系统、账号、应用、流程、日志。
- 系统态搜索成员、模块、字段、页面、业务数据。
- 普通运行态只搜索授权模块和可见数据。

右侧：

- 审批图标：显示待审批数量。
- 待办图标：显示待办数量。
- 消息图标：显示未读数量。
- 日志 / 审计快捷入口：按当前上下文进入平台日志或系统日志。
- 帮助入口。
- 用户基础信息：头像、姓名、当前身份、所属组织。
- 用户菜单：个人中心、切换身份、退出登录。

右上角任务区是硬要求，不能缺失。

### 4.2 左侧导航

左侧只展示当前角色、当前上下文可用的业务菜单。

通用要求：

- 支持展开 / 收起。
- 收起后显示图标，不显示大量文字。
- 当前菜单高亮。
- 不显示无权限菜单。
- 不把上百上千系统放进左侧导航。
- 系统切换通过顶部入口或系统选择中心完成。

禁止：

- 禁止左侧显示 `P 平台管理 / S 系统管理 / R 系统运行台` 这种原型切换器。
- 禁止同一个左侧导航同时混入平台管理、系统管理、普通业务运行台的菜单。

## 5. 角色登录落点

### 5.1 平台管理员

默认落点：平台工作台。

顶部上下文：`平台管理`

左侧导航：

- 平台首页
- 系统中心
- 平台组织
- 平台账号
- 平台角色与权限
- 平台级 Flow
- 平台级应用
- 平台待办
- 平台消息
- 平台日志
- 平台审计
- 运维监控

首页必须体现：

- 平台系统总数、运行状态、异常系统。
- 平台账号、待处理开通、账号风险。
- 平台级应用调用量、异常调用、即将过期凭证。
- 平台 Flow 待办、失败流程、超时流程。
- 最近平台审计。

平台管理员不默认进入某个系统的业务数据。

### 5.2 系统管理员

默认落点：当前系统管理首页。如果有多个系统，先进入系统选择中心。

顶部上下文：`车队运营系统 / 系统管理`

左侧导航：

- 系统首页
- 成员与部门
- 角色与权限
- 字典管理
- 模块与字段
- 页面与菜单
- 系统内应用配置
- 流程事件绑定
- 系统待办
- 系统消息
- 系统日志
- 系统审计

首页必须体现：

- 当前系统状态、我的身份、系统编号。
- 搭建进度：成员、角色、模块、字段、页面、菜单、流程绑定。
- 下一步建议：例如“先配置模块字段”“页面未发布”“成员未授权”。
- 最近系统配置活动。
- 快捷入口：进入运行台、邀请成员、新建模块、发布页面。

系统管理员不能看到平台账号创建、平台组织、平台应用密钥等平台能力。

### 5.3 普通业务用户

默认落点：当前系统业务运行台。如果有多个系统，先进入系统选择中心。

顶部上下文：`车队运营系统 / 业务运行`

左侧导航：

- 工作台
- 我的待办
- 授权模块分组
  - 车辆业务
  - 维保与保险
  - 司机任务
- 常用数据
- 文件 / 导出
- 我的消息
- 个人中心

首页必须体现：

- 我的待办。
- 常用模块。
- 最近处理数据。
- 系统消息。
- 快速新建入口。

普通业务用户不能看到：

- 成员与部门。
- 角色与权限。
- 字段设计。
- 页面与菜单配置。
- 流程事件绑定配置。
- 系统日志审计管理入口。

### 5.4 集成管理员 / 对外应用管理员

默认落点：平台开放中心或有权限的系统对外授权页。

顶部上下文：`平台开放中心`

左侧导航：

- 开放首页
- 对外应用
- 凭证管理
- 授权范围
- IP 白名单
- 限流策略
- 调用日志
- 风险审计

首页必须体现：

- 应用数量、异常调用、凭证到期、限流命中。
- 最近调用日志。
- 高风险授权变更。
- 快速创建对外应用。

## 6. 系统选择中心

用于上百上千系统场景，不能进入左侧导航。

入口：

- 顶部当前上下文的“切换系统”。
- 登录后多个系统时默认进入。
- 平台首页的“进入系统”。

布局：

- 页面标题：选择系统。
- 搜索框：搜索系统名称、编号、创建人。
- 筛选：最近访问、收藏、我的角色、系统状态、创建时间。
- 视图：默认表格，可切换紧凑卡片。
- 表格字段：收藏、系统名称、系统编号、状态、我的身份、最近访问、待办数、创建人、操作。
- 操作：进入运行台、进入管理、查看系统信息、收藏。
- 分页：20 / 50 / 100，总数和跳页。

空态：

- 无系统：暂无可进入的系统。
- 有创建权限：显示创建系统。
- 无创建权限：提示联系管理员开通。

## 7. 关键页面要求

### 7.1 平台首页

必须是成熟后台首页，不是说明页。

区域：

- 顶部指标条。
- 平台待办与审批。
- 系统运行概览。
- 平台级应用调用趋势。
- 平台 Flow 概览。
- 最近审计列表。

主按钮：

- 创建系统。
- 创建平台账号。
- 创建对外应用。

### 7.2 系统管理首页

必须像“搭建业务后台”的控制台。

区域：

- 系统状态。
- 搭建进度。
- 配置建议。
- 快捷入口。
- 最近配置变更。

主按钮：

- 新建模块。
- 邀请成员。
- 配置页面。
- 进入运行台。

### 7.3 普通运行台首页

必须像真实业务人员工作台。

区域：

- 我的待办。
- 常用模块。
- 快速新建。
- 最近数据。
- 我的消息。

主按钮：

- 新建业务数据。
- 处理待办。

禁止出现管理配置入口。

### 7.4 平台级应用

独立于 Flow。

包含：

- 应用列表。
- 凭证管理。
- 授权范围。
- IP 白名单。
- 限流策略。
- 调用日志。

列表必须有筛选、分页、操作列、详情抽屉。

### 7.5 平台级 Flow

独立于应用。

包含：

- 流程模板。
- 流程实例。
- 待办审批。
- 流程日志。

### 7.6 系统内应用配置

表达当前系统如何启用平台级应用能力。

不能和流程事件绑定合并。

### 7.7 流程事件绑定

表达当前系统模块事件如何触发流程。

不能和系统内应用配置合并。

### 7.8 日志与审计

必须分层：

- 平台日志。
- 平台审计。
- 系统日志。
- 系统审计。

每个列表必须有：

- 时间范围。
- 操作者。
- 对象。
- 动作。
- 结果。
- 来源。
- requestId / 追踪 ID。
- 详情抽屉。

## 8. 列表与表单规范

列表：

- 顶部为页面标题、说明和主按钮。
- 搜索和筛选放在列表上方。
- 高级筛选可展开。
- 表格有真实列名、操作列、分页。
- 列配置、保存视图、导出按权限显示。
- 不使用大面积空白卡片撑页面。

抽屉：

- 新建、编辑、详情统一右侧抽屉。
- 复杂创建系统使用步骤页面或步骤抽屉。
- 抽屉底部固定取消、保存。
- 保存失败不关闭。

顶部任务浮层：

- 审批：展示平台或系统待审批。
- 待办：展示我的待办。
- 消息：展示未读消息。
- 日志：快速进入当前上下文日志。
- 用户菜单：个人中心、切换身份、退出登录。

## 9. 视觉方向

要求：

- 主流企业 SaaS 后台。
- 类似 Ant Design Pro、飞书/钉钉管理后台、简道云后台的成熟感。
- 顶部白底或浅色，左侧浅色或深色均可，但必须稳重。
- 信息密度适中。
- 列表、表单、抽屉、任务浮层要像真实系统。
- 不要营销 Hero。
- 不要过度渐变。
- 不要大面积装饰图。
- 不要一屏只有少量大卡片。
- 不要把说明文案当主要内容。

## 10. 必须生成的页面

请生成一个自包含 HTML 原型，至少覆盖：

1. 平台管理员首页。
2. 平台系统中心 / 系统选择中心。
3. 平台账号。
4. 平台级 Flow。
5. 平台级应用。
6. 平台日志 / 审计。
7. 系统管理员首页。
8. 成员与部门。
9. 模块与字段。
10. 页面与菜单。
11. 系统内应用配置。
12. 流程事件绑定。
13. 系统日志 / 审计。
14. 普通业务用户工作台。
15. 授权模块数据列表。
16. 右上角审批 / 待办 / 消息 / 用户菜单浮层。
17. 新建 / 编辑 / 详情右侧抽屉。
18. 创建系统流程。

页面必须能通过点击导航切换，不只是静态截图。

## 11. 验收标准

| 项 | 标准 |
| --- | --- |
| 顶部栏 | 有 Logo、上下文、系统切换、搜索、审批、待办、消息、日志、用户菜单、退出 |
| 左侧导航 | 只显示当前角色/当前上下文菜单，支持折叠 |
| 角色区分 | 平台管理员、系统管理员、普通业务用户、集成管理员首页不同 |
| 系统选择 | 支持上百上千系统，不进左侧导航 |
| 平台/系统边界 | 平台能力与系统能力不混层 |
| Flow/应用 | 平台层独立，系统层配置也独立 |
| 普通用户 | 不看到管理配置入口 |
| 列表 | 筛选、分页、操作列、详情抽屉完整 |
| 右上任务区 | 审批、待办、消息、日志、用户菜单可打开 |
| 视觉 | 主流企业后台，不像需求说明稿 |
| 文案 | 中文清晰，按钮和状态能指导普通用户操作 |

## 12. 不通过条件

- 仍然显示 `P/S/R` 作为主要导航。
- 顶部右侧没有审批、待办、消息、日志和用户区。
- 不同角色只是切换同一套页面。
- 普通用户能看到字段设计、页面发布、权限配置。
- 系统列表进入左侧导航。
- 页面主要是说明文案或大卡片。
- 列表没有分页、筛选、操作列。
- 新建和详情交互不一致。
- 视觉不像主流后台系统。
