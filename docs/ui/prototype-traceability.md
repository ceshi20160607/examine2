# P16 原型流程追踪矩阵

状态：`draft-before-open-design-output`

更新时间：2026-06-13

## 1. 追踪规则

Open Design 原型冻结前，以下矩阵必须全部映射到页面、交互、权限和测试用例。若某条流程在原型中无法解释，PM 不得允许 frontend 进入最终页面实现。

## 3. 页面状态矩阵

| 状态 | 必须出现的页面 | 原型要求 | 不通过表现 |
| --- | --- | --- | --- |
| 空态 | 我的业务系统、业务运行首页、车辆档案列表、对外应用中心 | 说明当前为空、下一步做什么、主按钮在哪里 | 只显示空表格或“暂无数据” |
| 加载态 | 所有列表和详情 | 显示加载骨架或加载提示，不影响布局 | 页面闪烁或布局跳动 |
| 错误态 | 登录、列表、保存、发布、OpenAPI 日志 | 显示原因、重试、requestId 或恢复建议 | 只有技术错误或接口路径 |
| 无权限态 | 普通用户、缺权限管理员 | 入口隐藏或禁用，并用中文说明原因 | 普通用户看到不可用的管理入口 |
| 成功态 | 创建系统、开通成员、发布、保存记录、创建对外应用 | 提示成功并给出下一步 | 只弹出成功，无后续路径 |
| 危险操作 | 停用账号、删除模块、撤销授权 | 二次确认和影响说明 | 直接执行或只显示浏览器 confirm |

## 4. 原型冻结检查

原型冻结时必须确认：

- `P16-FLOW-001` 到 `P16-FLOW-013` 均能在原型中找到页面和交互。
- 普通业务用户视角单独检查，不用平台管理员视角替代。
- 对外应用流程单独检查，不和业务模块混在一起。
- 平台日志和系统日志在页面和文案上分层。
- 原型中的新建/编辑入口不是表格上方常驻大表单。
- 原型有分页、空态、错误态、无权限态和成功后的下一步。

## 5. 后续实现对齐

frontend 实现后必须补充 `docs/ui/prototype-implementation-diff.md`，逐条说明：

- 完全按原型实现的页面。
- 因 API 或技术限制调整的页面。
- 未实现的原型交互及原因。
- 需要 PM 重新裁决的差异。
