## 2. 本轮采用的产品口径

本轮使用用户确认后的架构，并采用 UI 风格建议：以“A 稳重企业控制台”为主，吸收“B 轻量协作工作台”的普通用户亲和度。

核心口径：

1. 平台用户只能在平台内创建、导入或受控开通，不能提供普通账号自助开通入口。
2. 面向新用户的入口是“创建系统”，系统创建人成为该自建系统管理员，但不自动获得平台管理权限。
3. 系统内创建应用配置，是为了让该系统使用平台级应用能力和 Flow 能力，实现对外或对内调用，以及模块事件触发流程。
4. 平台当前固定基础能力包含组织架构、Flow、应用、日志、审计、待办、消息和统一入口。
5. 每个自建系统也有系统级日志、审计、待办、消息，以及组织、权限、字典、模块、模块分组、应用配置、流程事件绑定和运行台。

## 3. 原型覆盖页面

- 登录与创建系统入口。
- 平台统一入口。
- 平台组织与权限。
- 平台级 Flow 与应用。
- 平台日志、审计、待办和消息。
- 自建系统首页。
- 系统组织与权限。
- 模块、字典、页面和模块分组。
- 系统内应用配置与流程事件绑定。
- 普通业务运行台。

## 4. 自检重点

本轮原型必须重点复核：

- 页面是否不再出现普通账号自助开通入口。
- “创建系统”是否清楚表达为系统初始化入口。
- 创建系统的人是否只成为系统管理员，不成为平台管理员。
- 平台固定基础能力是否表达清楚。
- 系统内基础能力是否表达清楚。
- 系统内应用配置是否清楚表达为使用平台应用和 Flow 能力，而不是模块分组。
- 普通运行台是否明显轻于管理后台，不暴露平台和系统配置入口。

## 5. 当前限制

- 这是架构对齐原型，不是最终高保真视觉稿。
- 原型使用静态数据，未接入真实接口。
- 用户复核通过前，frontend 不得基于该原型进入实现。
