## 3.1 用户复核未通过项

用户复核后指出，本版仍不能冻结为最终原型，原因如下：

1. “应用”概念仍被误读。本项目中应用应与系统、流程同级，是系统间调用、系统对外调用和外部使用项目内流程/模块能力的管理主体；当前原型仍把系统内业务配置对象表达为“应用/业务应用”，导致产品边界错误。
2. 左侧导航缺少折叠/展开交互，不符合主流后台工作台使用习惯。
3. 详情、新建、编辑的交互体系不一致。既然新建/编辑使用右侧抽屉，详情也应优先保持抽屉体系；除非对象复杂到需要完整工作区，不能无理由独立详情页。
4. 字段均为配置驱动，列表必须表达高级筛选、表头/列配置、保存视图、字段权限影响下的列可见和导出范围；当前表达不足。
5. 权限模型表达不足，必须同时包含字段权限、页面权限、数据权限、菜单权限、动作权限和导出/OpenAPI 字段范围。
6. 平台层应区分平台管理和平台普通登录；系统层应区分系统管理和系统普通登录/运行台；当前原型表达仍不够清晰。
7. 一个账号属于多个系统时，登录后必须有系统选择页、默认进入策略和切换系统入口；当前原型没有作为主流程表达。

结论：本版只能作为中间草稿，不能作为 PM/UIUX 冻结原型，frontend 不得基于本版进入最终实现。

## 4. 仍然不是最终前端

该文件仍是可点击 HTML 原型，不是生产前端代码，不调用真实后端接口，也不能替代浏览器 E2E。

前端实现前，PM/UIUX/frontend/test/reviewer 必须先评审：

- 普通用户是否能自然理解“登录后去哪里、能做什么、不能看什么”。
- 平台层、系统层、运行台、平台级对外应用是否清楚分离。
- 初始需求中的流程、文件、导出、OpenAPI、运维审计是否在信息架构中有入口和边界。
- 哪些能力进入 P16 实现，哪些明确作为后续增强。

## 5. 下一步

必须先按用户复核意见重新梳理产品术语和 UI 原型：

- 冻结“应用/系统/流程/模块/运行台/调用方”术语表。
- 重做多系统登录分流、平台管理/平台普通态、系统管理/系统普通态。
- 重做应用中心，让应用承载系统间/系统对外调用，并能授权流程和模块能力。
- 重做左侧导航折叠、详情抽屉、高级筛选、表头配置和完整权限模型。

PM/UIUX 评审通过后，frontend 才能基于新版原型拆分页面级任务，并补充 `docs/ui/prototype-implementation-diff.md`。未完成真实前端实现、真实浏览器连续剧本、clean build、review 和部署验证前，`frontendUsable=false`、`fullProjectDeployable=false` 继续保持。
