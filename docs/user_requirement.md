# Unexamine 基础需求（第 16 次重构基线）

本文件只记录用户已经明确的产品目标和开发边界，不记录此前任何一次重构的完成状态。94 张原名表及用途以 [表意义.md](表意义.md) 为准；`un_module_scence` 等原有拼写不擅自改动。[old_table1.sql](old_table1.sql) 只研究早期字段和审批思路，其中的建表、删表和数据语句不得执行。旧实现、旧接口文档和旧验收记录不作为需求或完成证据。

## 产品目标

这是一个平台层与业务系统层组成的可配置业务系统。平台管理员建立业务系统和租户；系统成员进入租户后，通过模块、字段、表单、场景、流程和审批配置来创建及流转业务数据。系统还包含工作管理、数据源与仪表盘、KPI、打印、文件、公告、AI 配置，以及通过应用标识和密钥控制的对外接入。实现以基础功能完整可用为先，不预建尚未实施的复杂能力。

## 数据模型

- 以《表意义.md》的 94 张表为本轮基础表边界，保留表名及各表的业务用途；按真实业务旅程设计必要字段和简单关系。不建立只有主键的占位表，也不复用第 15 次 SQL 作为新需求。
- 早期 SQL 有字段参考价值但不是可执行迁移。缺失的字段按目标功能补齐；表和所有字段写中文备注，数据库时间字段使用 `*_time`，Java 属性使用 `*Time`。
- 第 16 次使用独立项目库 `unexamine_r16`。以前的数据库和测试数据不作为本轮验收证据；若之后改动已有数据，提供迁移步骤，不直接删表重建。

## 后端业务范围

- 基础列表须有分页、必要筛选、允许字段的排序和表头配置；模块记录须支持场景及场景配置、字段和表单布局、新建、保存、详情及权限范围。不能只保存配置而不执行对应查询。
- 平台、系统、租户、模块、流程、审批、工作、数据展示、打印、应用和公共资源按《表意义.md》中的表用途划分业务所有权。审批与通用流程各自保留定义和运行数据，不混为一套表。
- 后端完成所有当前基础功能所需接口，核对成功结果、真实持久化、越权拒绝和失败结果，再由用户验收。之后才在 `font_web/` 开发一个前端，并验收真实页面。
- 复用本机 Docker MySQL 3306 和 Redis 6379；后端固定 9999。产品只运行一个后端和一个前端，不增加 Nginx 或新数据库容器。

## 工程与分层

- 仓库根目录的 `back/` 是后端 Maven 工程，业务模块统一命名 `examine-*`，由 `examine-web` 组合成一个服务。`examine-plat` 管平台，`examine-sys` 管业务系统和租户，`examine-dashboard` 管仪表盘和 KPI。各模块在自己的业务包下平级放 `base` 与 `manage`，不建 `foundation`、`identity` 聚合模块或多余目录。
- 代码生成器按业务表生成 `base` 的 Entity、Mapper、`IService` 和 `ServiceImpl`。基础 CRUD 不能只是空接口与空实现：参照提交 `70a3979a` 的 `examine-core/src/main/resources/simple`，应在 Service 中有 `queryPageList`、`addOrUpdate`、`queryById`、带字段布局的 `information`、`deleteByIds` 的真实实现。Controller 接收 HTTP 参数并调用 Service；特殊规则、授权和跨表编排放同业务包的 `manage`，不把 CRUD 查询与保存逻辑堆进 Controller。新代码和模板须有适当的中文业务注释、`@Tag` 和 `@Operation`。
- 先从表和模板建立可复现的生成链，再开发业务接口；不从旧 Controller 或旧 SQL 复制业务实现。简单 CRUD 不增加多余抽象。
