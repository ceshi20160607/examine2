# Unexamine 基础需求

## 依据与边界

- [表意义.md](表意义.md) 中的 94 张表及其中文用途，是本轮数据模型的原始定义。建表时使用原表名，不改名、不合并、不用别的表代替；其中 `un_module_scence` 的拼写也保持原样。
- 本文只整理这些表对应的基础业务需求，不预设尚未确定的字段、关系、状态或接口。字段和约束在实施对应功能时根据业务行为确定，写入版本 SQL 并验证。
- [old_table1.sql](old_table1.sql) 只供理解早期审批行为；其中的旧数据和删表语句禁止执行。
- 清理前的需求汇编、表模型、代码、验收记录和任务编排都不是本轮需求依据。若本文与《表意义.md》冲突，以后者为准。

## 基础业务

1. **平台管理**：平台账号登录；管理平台成员、部门、角色、菜单、数据权限、配置、登录与操作日志、消息。使用 `un_plat_*` 原表。
2. **公共能力**：文件、公告和 AI 配置分别使用 `un_common_file`、`un_common_notice`、`un_common_ai`。
3. **业务系统与租户**：平台创建业务系统；系统管理租户、成员、部门、菜单、角色、数据权限、配置、日志和消息。使用 `un_sys_*` 原表。系统成员与租户成员按原表分别处理。
4. **可配置模块**：管理员配置模块分组、模块、字典、字段、菜单、动作、规则、查询字段、租户扩展、场景、成员及关联；用户使用模块记录和扩展数据，并能查看变动。使用 `un_module_*` 原表。模块审批 `un_module_examine` 与模块流程 `un_module_flow` 保持两个独立概念。
5. **流程**：配置流程、节点、连线、版本和绑定；运行实例、待办、候选人、操作、异常、事件及定时任务。使用 `un_flow*` 原表。流程版本发布后不可变；实现时需要验证发布和运行行为。
6. **审批**：配置审批、分组、高级配置、异常处理、人员、节点和节点字段；运行审批实例及节点人员。使用 `un_examine*` 原表。审批与通用流程各自保留数据边界，不用一套表覆盖另一套。
7. **应用接入**：受控访问应用及其事件配置使用 `un_app`、`un_app_event`。
8. **工作管理**：项目、参与人、任务组、任务、任务字段、任务成员、历史、每日日志及评论使用 `un_work_*` 原表。
9. **数据展示**：仪表盘、组件、组件字段、使用人员使用 `un_dashboard*`；数据源及配置使用 `un_data_source*`；KPI 与用户使用 `un_kpi*`。
10. **打印**：打印模板使用 `un_print`。

## 开发顺序与验收

- 先建立最小可运行工程和第一个真实业务入口，再按平台身份、系统租户、模块、审批与流程、其他功能逐步实施。表的名称集合以《表意义.md》为准；物理表随其业务功能和字段定义一起落地，不造只有 `id` 的空壳表。
- 每个功能必须同时检查实际页面行为、数据库持久化、授权边界和失败处理。编译成功或接口返回 200 不代表功能完成。
- SQL 中表和每个字段都写中文备注；时间列用 `*_time`，Java 属性用 `*Time`。对已有数据做字段变更时提供迁移，不直接删表重建。
