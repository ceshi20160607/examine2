## RES-2026-06-15-001（产品模型澄清）

来源：用户直接输入，PM 已纳入 knowledge 冻结。

### 1. 导出（Export）

- 导出**不是**与模块、流程同级的独立功能域。
- 导出与页面动作同一配置体系：新建、编辑、删除、转移、添加团队成员、状态（特定状态字段）变动等。
- **配置了某动作权限 → 即可对该业务数据执行导出**（在动作/权限模型中挂载，非单独「导出中心」同级菜单）。

### 2. 账号与注册

- **平台用户只能在平台里创建**（统一认证用户表）。
- **未登录注册**：直接注册一个**系统**，注册人自动成为该系统**超级管理员**（同时创建平台账号 + 系统）。
- 所有可登录用户存**平台用户表**；系统内成员是对平台用户的**扩展**（组织、角色、数据范围、可扩展特殊字段等），不是第二套登录账号。

### 3. 平台登录后信息架构

平台用户登录后可见（按权限裁剪）：

| 区域 | 内容 |
|------|------|
| 平台基础 | 基础信息、个人相关 |
| 我的系统 | 拥有/可进入的系统列表 |
| Flow | 三类：①基础审批 ②事件触发审批 ③大流程（表单+审批） |
| 应用 | 平台视角应用入口（与系统内应用配置区分展示） |
| 日志 / 待办 / 消息 | 平台级或跨系统汇总（按权限） |

**选择某个系统后：**

- 默认进入该系统**仪表盘统计页**
- 展示权限范围内的**模块及功能**
- 若有系统管理权限 → 进入**系统后台**：系统基础信息、组织结构、角色权限、模块菜单、功能配置、流程配置、应用配置、日志、恢复默认/清空数据

**平台管理员**额外可见：**平台后台管理设置**（普通平台用户不可见）。

### 4. 代码生成器

- 沿用 v1 `examine-generator`，参考 `.oldbk/backend/examine-generator/`（命令即配置，生成各模块 `base/`）。

### 5. 默认平台管理员种子账号

- 用户名：`plat_admin`
- 密码：`123123aa`
- 写入 `sql/init.sql` 种子数据（Gate 后 dba 执行）。

## RES-2026-06-15-002（设计审阅反馈 · 平台 IA 与系统配置模型）

来源：用户设计审阅反馈 2026-06-15，PM 已纳入 prd / ui-spec / design-rework。

### 1. 平台待办/消息 — 不重复导航

- **顶栏**：待办、消息以**图标+角标**呈现，点击打开面板或进入列表页。
- **侧栏**：**不得**再出现「待办」「消息」菜单项（避免与顶栏重复）。
- 侧栏保留：我的系统、Flow、应用、日志。

### 2. 平台管理端须有可浏览内容

- 平台管理员通过 **平台后台** 进入独立管理区。
- MVP 至少包含：**概览**（统计卡片）、**平台用户管理**、基础配置。
- 禁止仅有侧栏占位、主区空白的「假管理端」。

### 3. 自建系统配置模型（模块为中心）

**建模主链：**

模块分组 → 模块 → 字段 → 页面动作 → 菜单 → 发布

- **模块分组**：模块的组织分类（菜单/仪表盘分组），不是字段分组。
- **不是**「应用包含模块」的容器模型。

**流程配置（系统后台独立菜单）：**

- 绑定模块
- 触发事件：新建 / 编辑 / 删除 / 字段值变动（可配条件）
- 审批类型与审批流程配置

**应用（系统后台 · 应用接入）：**

- 用于将**本自建系统**关联到**平台级应用**
- 支持通过平台级应用进行**对外**或**系统内**受控 API 调用
- 入口在系统后台；配置对象是「本系统 ↔ 平台应用」绑定与授权范围
- 与「模块分组/模块」解耦

### 4. 设计 Gate

- 上述 IA 须在 `ui-spec` 冻结；原型可分期补 HTML，但**不得**与 RES-002 冲突。
- 原 `admin-modeling.html`「应用与模块」表述作废。

## RES-2026-06-15-003（模块组导航 + 对外应用 · 用户澄清）

来源：用户设计审阅第二轮 2026-06-15。修正 RES-002 中理解偏差。

### 1. 模块组 = 运行态顶栏 + 左侧二级导航

- 多个模块（例：3 个）归属**一个模块组**。
- **顶栏**显示模块组名称（如「车辆管理」）。
- **点击组名**后，**左侧栏**展示该组下的模块列表；右侧为当前模块业务页。
- **配置顺序**：先建模块组 → 再在组下建模块 → 字段 → 页面动作 → 菜单 → 发布。
- 不是字段分组；不是应用包含模块。

### 2. 应用 = 自建系统对外访问入口

- 应用提供**本系统对外**入口，外部系统通过该应用进行访问调用。
- 配置在系统后台；与模块组/模块**解耦**。
- **废止** RES-002 中「应用=关联平台级应用」的单一表述；平台层可做全局策略，但产品心智是**本系统对外应用**。

### 3. 需求文档

- 已回写 `docs/user_requirement.md` 附录 A。
- 后续角色以附录 A + 本 RES 为准。

### 4. Open Design 前置 Gate

- 见 `phase-1-internal-design-complete.md`：团队内部完成设计包后，再请用户调用 Open Design。

## RES-2026-06-15-005（平台 Flow/应用 + 业务列表高级能力）

来源：用户设计补充 2026-06-15。

### 1. 平台层 Flow 与平台层应用（可独立配置）

**两层并存，不得混为一谈：**

| 层级 | Flow | 应用（对外） | 配置入口 |
|------|------|--------------|----------|
| **平台** | 跨系统/平台级流程（大流程、事件编排） | **平台对外应用**：OpenAPI 客户端、AK/scope | **平台后台** |
| **系统** | 绑定模块的审批流 | **系统对外应用**：本系统业务数据/能力出口 | **系统后台** |

**关键链路：**

- 平台层 **Flow** 与 **应用** 均在**平台后台**单独配置，与系统后台解耦。
- **平台 Flow 可通过平台应用对外开放**（应用授权 scope 含流程触发/回调/查询类能力）。
- 侧栏「Flow」「应用」是**运行态入口**（汇总/快捷进入）；**配置**在平台后台。

**与 RES-003 关系：** 系统「对外应用」仍保留；本 RES **补充**平台级 Flow+应用，不替代系统层对外应用。

### 2. 业务列表（运行态）— 高级表格体验

模块列表页必须具备（`user_requirement §6.4` 对齐）：

| 能力 | 说明 |
|------|------|
| **高级搜索** | 顶部快捷搜索 + **高级搜索抽屉**（多字段组合条件） |
| **列表场景** | 管理员在建模配置默认场景；用户可**保存视图/场景**（筛选+列组合） |
| **表头自定义** | 列显示/隐藏、顺序、列宽、固定列；**用户级**可保存个人表头 |
| **序号列** | 表头第一列：行序号（分页连续编号） |
| **勾选列** | 表头第二列：全选/单选复选框 |
| **批量操作** | 选中后浮层或工具栏：**编辑、转移、删除、导出**（按动作权限显隐） |
| **导入** | 工具栏 **导入**（模板下载、预检、错误行反馈 → Build 分期可简） |
| **详情** | 点击行 → **右侧详情抽屉**；复杂详情可跳转整页 |

**配置侧（系统后台 · 建模）：**

- **列表/表头配置**：默认列、可隐藏列、默认排序、是否启用高级搜索字段。
- **列表场景配置**：预设场景名 + 默认筛选 + 默认列集（例：「在用车辆」「待维保」）。
- **页面动作**：新建、编辑、删除、转移、导入、导出等与权限同一体系（RES-001）。

### 3. Design vs Build 分期

| 项 | Design（ui-spec + 原型须体现 IA） | MVP Build 可简 |
|----|-----------------------------------|----------------|
| 平台后台 Flow/应用配置页 | ✅ 须有页面结构与示例 | 仅 1 条平台 Flow + 1 个平台应用绑定示例 |
| 列表高级搜索抽屉 | ✅ 原型须可点开 | 2~3 个字段组合即可 |
| 表头设置面板 | ✅ | 列显隐+顺序 |
| 保存场景/视图 | ✅ 入口+列表示例 | 存用户偏好即可 |
| 批量转移 | ✅ 按钮+确认态 | 单目标字段简版 |
| Excel 导入向导 | ✅ 工具栏入口+步骤占位 | 同步简导入或仅预检占位 |
| 详情右侧抽屉 | ✅ `runtime-list` 须演示 | 字段只读列表 |

### 4. 原型 v3 缺口

当前 v3 `runtime-list` 仅简易搜索+导出；`platform/flow|apps` 为 P1 占位。**签字前建议补 v3.1** 或接受 notes 中标注「列表/平台配置待补原型」。

## RES-2026-06-15-006（业务列表合理布局与批量操作限制）

来源：用户设计补充 2026-06-15。

### 1. 列表页必须是业务工作台，不是数据调试表

业务模块列表页须按真实业务操作组织信息密度和交互层级。页面默认展示用户最高频判断所需字段，并把检索、场景、列设置、导入导出、批量操作和详情抽屉放在同一工作流中。

### 2. 车辆档案列表展示列

`runtime-list.html` 至少体现以下列：

| 列 | 要求 |
|----|------|
| 复选框 | 表头全选 + 行选择；未选中时批量操作不可用 |
| 序号 | 分页连续序号，固定在复选框后 |
| 车牌号 | 主识别字段，可点击打开详情抽屉 |
| 品牌型号 | 常用识别字段 |
| 车辆状态 | 字典标签：在用、维保中、闲置、停用 |
| 归属部门 | 用于转移与权限判断 |
| 驾驶员 | 当前绑定人员 |
| 购置日期 | 支持表头排序 |
| 年检到期 | 支持表头排序，临期需有提示态 |
| 最近维保 | 支持表头排序 |
| 操作 | 查看详情、编辑；危险操作不放单行主按钮 |

### 3. 检索、场景与表头设置

| 能力 | 必须体现 |
|------|----------|
| 快捷搜索 | 搜索车牌、品牌型号、驾驶员 |
| 高级筛选 | 抽屉或侧栏；包含状态、归属部门、驾驶员、购置日期、年检到期、最近维保范围 |
| 场景 | 展示「全部车辆」「在用车辆」「待年检」「维保中」「我负责的」；支持保存当前筛选和列配置为场景 |
| 列设置 | 显示/隐藏、拖拽排序、列宽、固定列；保存为我的表头 |
| 表头排序 | 购置日期、年检到期、最近维保列展示升降序入口；排序状态可见 |

### 4. 导出与批量操作限制

导出必须区分：

- **全部导出**：不依赖勾选，按当前检索条件和当前场景导出全部匹配数据。
- **导出选中**：仅在勾选后可用，导出当前选中行。

勾选后的批量条必须根据权限和数据状态限制可操作项：

| 操作 | 启用条件 | 禁用/提示 |
|------|----------|-----------|
| 转移 | 已选中且有转移权限；选中车辆未处于锁定流程 | 无权限隐藏；存在流程锁定行时禁用并提示 |
| 删除 | 已选中且有删除权限；仅允许闲置/停用等可删状态 | 包含在用/维保中车辆时禁用并提示 |
| 导出选中 | 已选中且有导出权限 | 无权限隐藏 |
| 批量编辑 | 已选中且字段允许批量变更 | 不允许批量改唯一字段如车牌号 |

未勾选时，批量条显示为不可用提示或不显示；工具栏仍保留「全部导出」。

### 5. 详情与布局

- 点击行或「详情」打开右侧详情抽屉，抽屉展示车辆基础信息、状态、归属、驾驶员、年检与维保摘要。
- 抽屉底部放「编辑」「关闭」；无编辑权限时只显示关闭。
- 列表主体应优先横向展示关键业务列；高级筛选和列设置用抽屉，不挤占主表格。
- 顶部布局建议：标题与摘要 → 场景/快捷搜索/高级筛选 → 批量条或工具栏 → 表格 → 分页。

### 6. v3.1 原型要求

签字前用 Open Design 生成 v3.1，至少补齐：

- `system/runtime-list.html`：上述完整业务列表、筛选、场景、列设置、批量限制、全部导出、导出选中、详情抽屉。
- `system/admin-modeling.html`：列表列配置、排序字段、筛选字段、场景配置、动作权限配置。
- `platform/plat-admin-flow.html` 与 `platform/plat-admin-apps.html`：平台 Flow/应用配置页。

## RES-2026-06-15-007（列表顶部密度优化与用户角色拆分）

来源：用户基于 v3.1 车辆档案截图反馈，2026-06-15。

### 1. 业务列表首屏应优先服务数据判断

v3.1 已补齐场景、检索、高级筛选、列设置、导出、勾选和批量操作，但顶部区域过高，导致首屏被控件占满。v3.2 需要在不删能力的前提下重新组织层级：

| 控件 | v3.2 处理 |
|------|-----------|
| 场景 | 改为紧凑下拉/分段选择；最多展示 2~3 个常用场景，其余进入更多场景 |
| 快捷搜索 | 搜索框内置搜索图标或回车触发，不再强制单独放“快捷搜索”按钮 |
| 高级筛选 | 保留入口，筛选面板使用右侧抽屉；已应用条件用 chips 展示 |
| 选择项目/系统 | 放在顶栏或标题行小型下拉，不单独占一整行或大卡片 |
| 新建 | 页面只保留一个主按钮，避免标题区和工具栏重复 |
| 批量操作 | 仅勾选后显示紧凑 selection bar；禁用原因用 tooltip 或短提示 |

列表页布局目标：1440×900 首屏至少展示 8 行业务数据，用户第一眼看到业务表格，而不是大面积筛选和场景控件。

### 2. 用户/成员与角色必须拆页

用户/成员管理解决“谁可以进入系统”；角色权限解决“能做什么”。二者职责不同，不能长期放在同一页面 Tab 中。

系统后台侧栏调整为：

首页引导 → 基础参数 → 数据字典 → 数据源 → 仪表盘配置 → 模块组 → 模块 → 建模 → **成员管理** → **角色权限** → 流程 → 对外应用

平台后台也拆分：

- `plat-admin-users.html`：平台账号管理。
- `plat-admin-roles.html`：平台后台权限角色管理。

系统后台拆分：

- `admin-users.html`：当前系统成员管理、邀请、停用、分配角色。
- `admin-roles.html`：当前系统角色配置，包含模块权限、字段权限、数据权限、动作权限。

平台角色不配置车系统字段权限；系统字段权限只在系统角色页维护。

### 3. v3.2 Brief 要求

`docs/design/prototype-brief.md` 升级为 v3.2，供用户手动调用 Open Design 生成：

- `system/runtime-list.html`：紧凑列表布局。
- `system/admin-users.html` / `system/admin-roles.html`：系统成员和角色拆页。
- `platform/plat-admin-users.html` / `platform/plat-admin-roles.html`：平台用户和角色拆页。
- `system/admin-modeling.html`：继续保留列表列、筛选、场景、动作配置，但布局更紧凑。
