# P16 多角色反思与原型重做规则

状态：`frozen-before-next-prototype`

更新时间：2026-06-13

## 1. 本轮结论

本轮用户复核成立：P16 高级原型仍不能冻结。问题不是页面细节少几个控件，而是 PM、Analyst、UIUX、Frontend、Reviewer 没有先把产品术语、工作区模型、登录分流、权限表达和主流后台交互沉淀成硬闸门。

当前必须撤回 `p16-codex-advanced-prototype.html` 的主原型地位。它只能作为历史草稿，不允许 frontend 基于它进入最终页面实现。

## 2. 根因

### 2.1 术语没有冻结

“应用”被继续解释成系统内业务应用/模块容器，导致页面把“应用配置中心、业务应用、模块”混成一层。

用户当前澄清后的项目术语必须以此为准：

| 术语 | 含义 |
| --- | --- |
| 系统 | 业务空间，承载成员、角色、模块、字段、页面、菜单、业务数据、系统内流程、日志和运行台。 |
| 应用 | 与系统、流程同级的调用管理主体，用于系统间调用、系统对外调用、外部系统使用项目内流程/模块/文件/后续其它能力。 |
| 流程 | 可在系统内触发，也可被应用授权给外部或其它系统使用的能力，包含模板、版本、实例、待办和审批历史。 |
| 模块 | 系统内部承载字段、页面、菜单和业务数据的对象。系统内部不得再把模块或模块分组称为“应用”。 |
| 运行台 | 普通用户处理被授权模块数据、待办、附件和导出的工作区。 |

### 2.2 登录和工作台模型没有成为主流程

原型没有把以下场景作为第一优先级：

- 平台登录。
- 系统直登。
- 多系统用户登录后的系统选择。
- 平台普通态和平台管理态。
- 系统普通态和系统管理态。

### 2.3 主流后台交互没有成为验收标准

左侧导航折叠、统一抽屉体系、高级筛选、表头配置、保存视图、权限预览等能力被当作“细节”，而不是可用后台的基础能力。

### 2.4 权限只停留在角色/菜单层

原型没有充分表达：

- 页面权限。
- 操作权限。
- 字段可见权限。
- 字段可写权限。
- 数据范围权限。
- 导出字段范围。
- 应用调用字段/动作/流程范围。

## 3. 下一版原型必须满足的硬规则

### 3.1 应用规则

1. “应用”只用于调用管理主体，不用于系统内模块组织。
2. 应用必须能授权：
   - 某个系统的数据。
   - 某个模块的动作。
   - 某些字段范围。
   - 某些数据范围。
   - 某个已发布流程。
   - 文件、消息或后续其它可开放能力。
3. 应用必须包含 appKey/secret、scope、IP 白名单、限流、过期策略、签名、幂等、调用日志和 requestId 追踪。
4. 页面文案不得出现“系统内业务应用”。系统内只允许“模块”“模块分组”“运行菜单”等表达。

### 3.2 登录分流规则

1. 平台登录后：
   - 有平台管理权限：进入平台管理态，并能进入“我的系统”。
   - 无平台管理权限：进入平台普通态，只显示我的系统、最近访问、个人信息和退出。
2. 系统直登后：
   - 普通成员：直接进入该系统运行台。
   - 系统管理员：进入系统首页，可切换“运行台/系统管理”。
3. 多系统用户登录后必须先进入系统选择页，展示系统名称、状态、本人角色、最近访问、待办数、默认入口。
4. 进入系统后顶部必须常驻当前系统、租户、成员角色和切换系统入口。

### 3.3 导航规则

1. 左侧导航必须支持展开/折叠。
2. 折叠态保留图标、当前选中态、tooltip 和展开按钮。
3. 导航必须分为：
   - 平台入口。
   - 系统运行入口。
   - 系统管理入口。
   - 应用/开放入口。
4. 普通用户无管理权限时，不显示管理入口，而不是显示一堆禁用菜单。

### 3.4 抽屉一致性规则

1. 同一业务对象的新建、编辑、详情优先使用同一套右侧抽屉容器。
2. 详情抽屉只读展示，右上角提供“编辑”；点击后在同一抽屉切换编辑态。
3. 抽屉底部固定操作区，按权限和业务状态渲染按钮。
4. 复杂对象需要独立工作区时，UI/UX 必须说明原因，否则判定交互割裂。

### 3.5 列表规则

每个核心列表必须包含：

- 关键字搜索。
- 常用筛选。
- 高级筛选。
- 已生效条件 chips。
- 重置。
- 表头/列配置。
- 排序。
- 分页。
- 保存视图。
- 批量操作。
- 空态、加载态、错误态、无权限态。

动态模块列表的高级筛选和列配置必须由 schema、字段权限和用户列偏好共同决定。

### 3.6 权限规则

原型必须逐页表达：

- 菜单权限。
- 页面权限。
- 按钮/动作权限。
- 字段列表可见。
- 字段详情可见。
- 字段表单可写。
- 字段可筛选。
- 字段可导出。
- 应用可读/可写字段范围。
- 数据权限：本人、所在部门、本部门及下级、全部、自定义。

角色授权页必须有“权限效果预览”，可模拟普通用户实际看到的导航、按钮、字段和数据范围。

## 4. 下一版原型必须演示的连续剧本

1. 平台普通用户登录，只看到我的系统和个人入口。
2. 平台管理员登录，进入平台管理态，创建“车”系统。
3. 多系统用户登录，进入系统选择页，选择“车”。
4. 系统管理员进入“车 / 系统管理”，开通 `che` 成员。
5. 系统管理员创建车辆档案模块、字段、页面、菜单、权限和发布版本。
6. 系统管理员配置字段权限、页面权限、数据权限，并预览 `che` 的权限效果。
7. 普通用户 `che` 登录或系统直登，进入“车 / 业务运行台”。
8. `che` 在车辆档案列表使用高级筛选、表头配置、分页。
9. `che` 使用右侧抽屉新建车辆档案、查看详情、编辑、提交。
10. 审批人处理流程待办。
11. 集成管理员创建应用，授权外部或其它系统调用“车”系统车辆档案数据和某个流程。
12. 外部或其它系统通过应用调用成功。
13. 平台日志、系统日志和应用调用日志可通过 requestId 分层追踪。

## 5. Reviewer 必须 fail 的条件

任一条件成立，reviewer 必须判定失败：

- 应用概念仍被做成系统内业务应用或模块分组。
- 多系统用户没有系统选择页或默认进入规则。
- 平台普通态、平台管理态、系统普通态、系统管理态混在一起。
- 左侧导航不可折叠。
- 新建、编辑、详情交互体系不一致且无说明。
- 核心列表没有高级筛选、表头配置或保存视图。
- 字段权限、页面权限、数据权限缺失。
- 普通用户看到平台管理、系统建模、字段设计、页面发布或权限配置入口。
- 只用构建通过、局部页面 smoke 或管理员链路证明可用。

## 7. 历史旧口径清理闸门

术语冻结时必须扫描并修正 `AGENTS.md`、PRD、API、UI 设计、前端路由与页面文案中的历史旧口径，例如“业务应用”“应用配置”“应用运行台”等。

如果某处实际表达的是系统内模块、模块分组或运行菜单，必须改名；如果表达的是对外/跨系统调用管理，才允许继续叫“应用”。不得只用新增规则覆盖旧文档遗留歧义。
