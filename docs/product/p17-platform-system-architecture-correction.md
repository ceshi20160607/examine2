# P17 平台/系统/应用/流程架构修正

状态：`accepted-with-user-clarification`

更新时间：2026-06-13

## 1. 本轮用户修正

上一版低成本原型仍然没有理解清楚平台和自建系统的关系，尤其把平台级应用、系统内应用配置、模块和模块分组继续压成了过于简单的层级。

用户当前澄清后的理解以本文为准，用于下一版 UI/UX 和前端重构前的术语冻结。

## 2. 总体架构

平台不是普通后台，也不只是系统列表。它更接近统一登录/SSO 入口，但比通用 SSO 多了平台级能力：

- 统一登录与系统入口。
- 平台组织架构。
- 平台权限与平台功能。
- 平台级应用。
- 平台级流程。
- 平台日志。
- 平台审计。
- 平台待办。
- 平台消息。
- 运维和能力治理。

平台用户只能在平台内由有权限的管理员创建、导入或受控开通。对外不提供普通账号自助开通入口；对外入口应是“创建系统”。创建系统时初始化系统、创建人账号和系统管理员身份，创建人成为该自建系统管理员，但不自动获得平台管理权限。

自建系统是用户自己创建的业务系统后台。它用于配置该系统自己的组织、用户部门、权限、字典、模块、模块分组、页面、菜单、应用能力使用方式、流程事件绑定、日志、审计、待办、消息和运行台。

## 3. 核心概念

| 概念 | 正确定义 | 不能混淆为 |
| --- | --- | --- |
| 平台 | 统一登录入口和平台级能力中心，管理平台组织、平台权限、平台级应用、平台级流程、系统入口、审计运维 | 某个业务系统后台 |
| 平台用户 | 只能由平台内有权限的管理员创建、导入或受控开通，可按授权创建系统或管理平台能力 | 公开注册用户 |
| 创建系统入口 | 面向新用户的入口，创建系统并初始化系统创建人和系统管理员身份 | 普通账号自助开通入口 |
| 自建系统 | 用户创建的业务系统后台，用于配置本系统组织、用户部门、角色、字典、模块、模块分组、页面、菜单、运行台和系统内能力 | 平台本身 |
| 平台级应用 | 平台级能力，用于系统间调用、系统对外调用、外部使用系统数据、模块动作、流程或后续能力 | 系统内模块、模块分组 |
| 系统内应用配置 | 某个自建系统内创建/启用的应用配置，用于让该系统使用平台级应用能力和流程能力，配置对外或对内调用、功能范围、事件绑定、授权范围、入口展示、调用策略 | 平台级应用实体本身、模块分组 |
| 平台级流程 | 平台能力，可被系统使用或被应用开放给外部/其它系统 | 单个模块字段 |
| 系统内流程绑定 | 在某个系统内，将模块事件绑定到流程，例如新增后审批、提交后审批、变更后审批 | 平台流程定义本身 |
| 模块 | 自建系统里的业务数据对象，例如车辆档案，包含字段、列表、表单、详情、动作和数据 | 应用 |
| 模块分组 | 模块多时用于组织系统页面和菜单，例如车辆业务、门店业务 | 应用 |
| 运行台 | 普通用户处理模块数据、待办、流程、文件和导出的工作空间 | 管理后台 |

## 4. 平台侧信息架构

平台侧应至少包含：

1. 统一登录/系统入口：登录、选择系统、最近访问、个人信息、退出。
2. 创建系统入口：创建自建系统，初始化系统创建人和系统管理员身份。
3. 平台组织：平台用户、部门、岗位；平台用户只能平台内创建、导入或受控开通。
4. 平台权限：平台角色、平台功能权限、平台数据范围。
5. 系统管理：创建自建系统、系统状态、系统管理员、系统能力开关。
6. 平台级应用：应用凭证、调用方、授权策略、IP 白名单、限流、签名、调用日志。
7. 平台级流程：流程模板、版本、发布、可被系统引用的流程能力。
8. 平台待办与消息：平台任务、平台通知、平台能力审批提醒。
9. 平台日志与审计：登录、应用调用、流程调用、系统创建、异常追踪。

## 5. 自建系统侧信息架构

进入某个自建系统后，应至少包含：

1. 系统首页：系统配置进度、健康检查、下一步任务。
2. 系统组织：系统用户、部门、成员、岗位。
3. 系统权限：系统角色、菜单权限、页面权限、动作权限、字段权限、数据权限。
4. 字典管理：该系统可用的字典和值集。
5. 模块管理：模块、字段、列表、表单、详情、动作。
6. 模块分组与菜单：模块多时组织页面，发布到运行台。
7. 系统内应用配置：在系统内创建或启用应用配置，让该系统使用平台级应用能力和流程能力，配置对外或对内调用、具体功能、授权范围、事件绑定和入口。
8. 流程事件绑定：配置某个模块在新增、提交、修改、删除、状态变更等事件下走哪条流程。
9. 系统待办与消息：该系统内流程待办、业务提醒、消息通知。
10. 业务运行台：普通用户看到的模块页面、待办、文件、导出。
11. 系统日志与审计：成员、权限、模块、流程、数据变更和系统内调用日志。

## 6. 下一版 UI 原型必须体现

1. 登录后先进入平台统一入口或系统选择，不直接把平台管理和系统管理混在同一左侧菜单。
2. 登录页不出现普通账号自助开通入口；新用户入口是“创建系统”。
3. 创建系统成功后，创建人成为该系统管理员，但不能获得平台管理权限。
4. 平台侧有平台组织、平台权限、平台级应用、平台级流程、平台日志、平台审计、平台待办和平台消息。
5. 自建系统侧有系统组织、系统权限、字典、模块、模块分组、系统内应用配置、流程事件绑定、系统日志、系统审计、系统待办和系统消息。
6. 系统内“应用配置”不能再画成模块分组，也不能和平台级应用中心混成同一个页面。
7. 流程不是只在列表里出现一个入口，必须能在系统模块事件上绑定，例如“车辆档案提交后走车辆审批流程”。
8. 普通用户运行台只展示模块页面、待办和个人入口，不展示平台级应用、平台组织、系统建模、权限配置。

## 7. 当前原型裁决

`docs/ui/prototypes/p17-low-cost-ui-prototype.html` 只能作为低成本结构草稿，已暴露以下问题：

- 平台级应用和系统内应用配置没有分清。
- 平台级流程和系统内流程事件绑定没有表达完整。
- 平台组织架构和平台权限没有成为一级平台能力。
- 系统内组织架构、字典、模块分组和应用配置不足。
- 视觉风格只是结构草稿，不满足最终 UI 质量。

下一版应先做“架构正确 + 风格选择”的 UI 方向稿，再进入具体页面原型。
