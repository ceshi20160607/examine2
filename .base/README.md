# 通用工程模板

本目录是一套可独立复制的工程模板源码。它定义工程如何运行，不包含任何具体项目的需求、目录名、技术栈、状态或历史结论。

## 可移植性边界

模板必须满足以下条件：

- 不知道目标项目名称。
- 不知道目标实例目录名称。
- 不绑定需求、源码、测试、证据等项目目录。
- 不绑定语言、框架、数据库或代码生成工具。
- 不引用任何已经实例化的工程目录。
- 复制完成后，项目实例运行时不依赖模板源目录。

具体路径、技术栈、需求来源和当前阶段全部由实例的 `INSTANCE.md` 绑定。

## 模板结构

```text
README.md
CONDUCTOR.md
INSTANCE.template.md
agents/
  README.md
  {role}/role.md
skills/README.md
workflows/lifecycle.md
templates/engineering-node.md
session/state.template.json
```

各目录职责：

| 位置 | 公共职责 |
|---|---|
| `CONDUCTOR.md` | 调度、状态、Gate、角色启动和升级规则 |
| `agents/{role}/role.md` | 角色的公共职责、边界、技能和产出契约 |
| `skills/README.md` | 无状态技能的触发、输入、输出和判定规则 |
| `workflows/lifecycle.md` | 从需求理解到用户验收的工程循环 |
| `templates/engineering-node.md` | 每个工程节点统一、可阅读的产出格式 |
| `session/state.template.json` | 实例状态文件的初始结构 |

## 实例化

1. 将本目录的全部内容复制到目标项目选定的工程实例目录。
2. 将 `INSTANCE.template.md` 复制为 `INSTANCE.md`，填写项目名称、路径绑定、技术约束和当前工程节点。
3. 将 `session/state.template.json` 复制为 `session/state.json`，初始化阶段和 Gate。
4. 仅当项目有特殊规约时，在对应角色目录创建 `update.md`。
5. 项目运行只读取实例目录中的文件，不回读模板源目录。

实例角色的加载顺序固定为：

```text
agents/{role}/role.md
  -> agents/{role}/update.md（可选）
  -> 本次任务启动包
```

后加载内容只能补充或收紧公共契约。若要放宽公共 Gate、改变角色权责或覆盖用户决策权，必须形成明确决策记录，不能静默覆盖。

## 公共角色

| 角色 | 唯一主责 |
|---|---|
| `conductor` | 驱动工程循环，维护状态和 Gate |
| `pm` | 产品目标、范围和产品决策 |
| `analyst` | 需求理解、来源追踪和未决问题 |
| `uiux` | 信息架构、交互设计和可用性 |
| `planner` | 工程节点、依赖关系和交付顺序 |
| `dba` | 数据域、模型、迁移和生成边界 |
| `backend` | 服务端业务行为和集成实现 |
| `frontend` | 用户界面、交互状态和真实接口绑定 |
| `test` | 独立验证、回归证据和验收判断 |

角色不靠聊天记忆协作。所有输入、决定、产出、问题和证据都必须落盘并由路径连接。

## 公共与实例的分界

可以进入公共模板的内容：

- 跨项目成立的角色边界。
- 可重复执行的技能契约。
- 通用工程 Gate 和产出格式。
- 已经在实际项目中验证过的流程改进。

只能留在项目实例的内容：

- 项目需求、业务术语、角色旅程和原型。
- 项目路径、技术栈、账号和环境配置。
- 当前任务、进度、问题、证据和决策。
- 对公共角色的项目特殊扩展。

## 模板回收

项目经验不会自动进入公共模板。只有同时满足以下条件，才可以作为候选改进合并到模板源：

- 至少适用于多个项目或明确属于领域无关规则。
- 已在项目实例中实际执行并产生正向证据。
- 能表述为角色、技能、流程、Gate 或产出格式的一项稳定规则。
- 删除所有项目名称、路径、业务术语和技术栈假设后仍然成立。
