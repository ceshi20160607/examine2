# examine2 工程实例配置

本目录是 `examine2` 当前项目的工程实例。它由仓库内的 `.base` 公共模板实例化而来，但运行时是自包含的：角色、技能、流程、状态和项目扩展全部从本目录读取，不回读 `.base`。

## 实例身份

- 实例名称：`examine2-engineering`
- 项目目标：重新构建一个可配置的业务管理系统平台
- 当前阶段：`requirements-rebuild`
- 当前节点：`S1 需求理解`
- 下一 Gate：需求理解产出经过项目角色评审
- 当前状态：禁止业务编码

## 路径绑定

| 逻辑名称 | 当前项目路径 | 状态与用途 |
|---|---|---|
| 工程实例根 | `.cursor/` | 当前有效的角色、技能、流程、状态和工程产出 |
| 项目输入根 | `docs/` | 人可读需求、配置、流程和粗略设计 |
| 服务端源码根 | `backend/` | 尚未创建，设计 Gate 通过后使用 |
| 前端源码根 | `frontend/` | 尚未创建，设计 Gate 通过后使用 |
| 数据库资产根 | `sql/` | 尚未创建，数据库设计完成后使用 |
| 当前工程证据根 | `.cursor/session/` | 节点状态、评审、问题和证据 |

## 权威输入

| 优先级 | 路径 | 用途 | 冲突处理 |
|---|---|---|---|
| 1 | `docs/user_requirement.md` | 当前产品需求主来源 | 由 analyst 标记冲突，pm 裁决或升级用户 |
| 2 | `docs/temp_flow.md` | 人可读功能和流程梳理 | 用于发现遗漏，不覆盖已确认需求 |
| 2 | `docs/temp_flow_persion.html` | 角色和流程参考 | 用于角色旅程交叉检查 |
| 3 | `docs/design/prototypes/index.html` | 粗略设计参考 | 不是最终需求或实现契约 |
| 配置 | `docs/user_setting.md` | 本地环境和账号配置 | 只按任务最小读取，不复制敏感值到工程文档 |

`.oldbk` 已删除，旧代码不再是需求来源或实现来源。

## 项目技术约束

- 项目文本统一使用 UTF-8。
- 数据库规划和设计先于服务端基础代码生成。
- 基础持久化代码由 MyBatis 代码生成工具生成，具体配置和版本在设计阶段确认。
- 生成代码只负责基础数据访问；业务行为在明确的业务层手写实现。
- 前端必须绑定真实接口、权限和状态，静态页面不能作为功能完成证据。

## 角色扩展

公共角色契约已经复制到：

```text
.cursor/agents/{role}/role.md
```

本项目特殊规约位于同一角色目录：

```text
.cursor/agents/{role}/update.md
```

读取顺序是 `role.md -> update.md -> 本次任务启动包`。`update.md` 只写本项目增量，不复制公共契约。

## 当前硬 Gate

在需求理解、设计、数据库方案和首个实现节点都明确前：

- 不创建或修改 `backend/**`。
- 不创建或修改 `frontend/**`。
- 不创建或修改 `sql/**`。
- 不把历史产出、生成 CRUD、接口成功或构建成功认定为最终目标完成。

只有用户本人或用户指定的验收人可以签署最终系统验收。

## 模板维护边界

`.base` 是模板源，不是本实例运行输入。只有明确执行“公共模板维护”任务时，才评审并修改 `.base`；普通项目节点只修改当前实例和项目产出。
