# 工程生命周期

默认生命周期由六个阶段组成。实例可以增加节点，但不能绕过前置 Gate。

```text
S0 实例初始化
  -> S1 需求理解
  -> S2 设计完成
  -> S3 实现
  -> S4 调试与集成
  -> S5 用户验收
  -> 模板改进评审
```

## S0 实例初始化

产出：实例配置、路径绑定、技术约束、权威输入清单、初始状态。

退出条件：所有占位项已填写，模板与项目特殊规则分开，下一节点明确。

## S1 需求理解

负责角色：analyst 主责，pm 裁决，其他角色按专业边界评审。

产出：

- 需求总账。
- 角色旅程清单。
- 产品边界。
- 术语和业务规则。
- 开放问题与决策记录。

退出条件：人能理解最终系统的目标、角色、入口、结果和边界；每项后续工作可追踪到需求和旅程。

## S2 设计完成

负责角色：uiux、dba、backend、frontend、test 分别产出专业契约，pm 处理产品冲突。

产出：

- 流程和信息架构。
- 交互及界面状态。
- 技术架构和模块边界。
- 数据模型、迁移和生成边界。
- 接口、权限、状态和副作用契约。
- 测试与验收设计。

退出条件：首个实现节点不再需要猜测关键需求；需要用户确认的设计已经真实确认。

## S3 实现

负责角色：planner 切分任务，dba、backend、frontend 实现，test 独立验收。

每个任务必须绑定需求、角色旅程、数据、权限、状态、失败路径、输出和证据。生成代码仅作为基础设施，不能代表业务完成。

退出条件：任务级验收通过，真实业务结果可读回，状态记录同步。

## S4 调试与集成

负责角色：test 主导问题复现和回归，各实现角色修复自己边界内的问题。

产出：问题总账、集成证据、失败状态覆盖、回归报告、可运行交付说明。

退出条件：关键角色旅程从真实入口完成，跨层数据一致，失败可理解、可追踪、可恢复。

## S5 用户验收

工程团队提供试用说明、验收清单、已知限制和运行系统。用户或指定业务负责人完成最终验收。

退出条件：有真实签字记录，或明确记录未通过项及下一工程节点。任何自动化结果都不能代替用户签字。

## 节点循环

每个阶段内部都执行：

```text
声明节点
  -> 校验输入和 Gate
  -> 角色执行
  -> 独立验证
  -> 关闭问题或升级
  -> 更新状态
  -> 声明下一节点
```

每一步使用 `templates/engineering-node.md`，使负责人可以直接判断项目走到哪里、理解到什么程度、下一步为什么成立。
