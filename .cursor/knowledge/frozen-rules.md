# 冻结规则（必须 / 禁止）

> 来源：`docs/user_requirement.md` + v1 部署反馈 + `.oldbk/backend` 已验证结构。  
> **默认生效**，PM 无权单方面废止；冲突须 `escalated` → 用户。

---

## 一、产品必须（MUST）

### 1.1 定位

- 面向**普通企业团队**长期使用，不是接口调试台、不是低代码演示
- 管理员（不写代码）能完成：建系统 → 建应用/模块 → 配字段/页面/菜单/权限/流程 → 邀请用户 → 导出/OpenAPI
- 普通用户能完成：登录 → 进自己的系统 → 业务 CRUD → 审批 → 附件 → 导出

### 1.2 双层架构

- **平台层**与**自定义系统层**必须分离，菜单/权限/数据不可混
- 平台层：系统创建、平台账号、平台角色、对外应用全局策略、平台审计、运维
- 系统层：成员、部门、角色、模块组、模块、建模、发布、仪表盘/业务功能、系统内流程/文件、系统审计（**导出为动作权限，非独立域**）
- 业务数据必须带 `systemId`；多租户时带 `tenantId`；模块数据带 `moduleId`。`moduleGroupId` 只用于导航/发布关系；`externalAppId/appKey` 只用于 OpenAPI 调用来源和审计；禁止用 `appId` 表示业务数据父级
- 系统 A 与系统 B 数据隔离

### 1.3 账号与成员（统一认证）

- **平台用户表**是唯一登录主体存储（类统一认证中心）
- **平台用户只能在平台创建**；禁止在系统层创建独立登录账号
- **未登录注册**：用户注册的是**一个系统**（非仅平台账号），注册人自动成为该系统**超级管理员**（同时落平台用户 + 系统 + 成员关系）
- **系统成员**是对平台用户在某系统内的**扩展**（组织、角色、数据范围、可扩展业务字段），不是第二套账号体系
- 系统内「添加成员」= 将已有平台用户扩展为该系统成员，或邀请后于**平台侧**完成账号创建再关联；不得绕过平台用户表
- 进入系统后接口须携带真实成员上下文，禁止前端伪造权限

### 1.4 导出（动作级，非模块级）

- **导出不是**与模块、流程同级的独立产品功能
- 导出挂在**页面动作/操作权限**体系，与新建、编辑、删除、转移、添加团队成员、特定状态字段变更等**同一类配置**
- 配置了某动作（含导出）且有权访问该业务数据 → 才可导出；UI 不得单独做「与模块平级的导出中心」除非作为动作入口聚合

### 1.5 入口与导航

**平台登录后**（按权限裁剪），用户可见：

- 平台基础信息、**我的系统**、**Flow**（三类见 domain-model）、**应用**、日志、待办、消息

**选择系统后：**

- 默认进入该系统**仪表盘统计页**，展示权限内模块与功能
- 有系统管理权限 → **系统后台**：基础信息、组织结构、角色权限、模块组/模块、功能配置、流程配置、对外应用、日志、恢复默认/清空数据

**平台管理员**额外可见：**平台后台管理设置**

**普通业务成员**（无系统管理权限）：

- 进入系统后只见仪表盘与权限内业务功能，不见系统后台配置入口

- 配置态（系统后台/建模）与使用态（仪表盘/业务功能）**分入口**
- 禁止空白调试页；禁止未授权用户看到平台后台或系统后台

### 1.6 术语（强制区分）

| 中文 | 含义 | 禁止简称 |
|------|------|----------|
| 模块组 | 运行态顶部分组、组内模块导航、排序、可见角色、发布关系 | 不得叫业务应用，不作为业务数据父级 |
| 对外应用 | 外部系统接入、appKey/secret、scope、回调、限流、调用来源和审计来源 | 不得作为模块父级，不得与模块组都叫「应用」 |

表前缀：`un_openapi_` 用于对外应用；旧 `un_app_*` 仅历史参考，MVP 不新建。

### 1.7 权限

- 角色是**权限模板/用户画像**，不写死角色名；页面由真实权限+菜单决定
- 系统创建人/系统超管映射系统内管理权限，**不得**扩展为平台 `PLAT_*` 权限
- 前端按钮与后端接口权限一致；**后端必须兜底校验**

### 1.8 流程与数据

- 平台 Flow 分**三类**（见 domain-model）：基础审批、事件触发审批、大流程（表单+审批）
- 流程运行使用**发布版本快照**；改模板不影响已发起实例
- 拒绝/撤回/终止**必须**填写原因
- 关键操作可追溯；平台日志与系统内日志**分层**，不得混为一谈

### 1.9 前端部署

- 默认 API 走浏览器同源 `/api/v1/...`，不写死 localhost
- 中文界面；技术 ID（moduleId/externalAppId/appKey）**不得**作为普通用户主界面文案；旧 `appId` 不再作为业务数据父级
- 须有真实 `frontend/dist/` 可部署产物，不是仅 SDK/类型通过

### 1.10 验收剧本（首期锚点）

「车系统 / che 成员」端到端剧本为 **P0 验收**，不得用管理员 alone 或 API smoke 替代。

## 二、产品禁止（MUST NOT）

- 把「接口通」「build 过」等同于「用户会用」
- 普通用户登录后进入平台空壳或工程调试台
- 配置页像 Postman：裸露 API 编号、schema、权限编码
- 平台超管绕过系统权限直接改业务数据（无审计只读运维除外）
- 未冻结 UI 就从 API 堆页面
- 把导出做成与模块/flow 平级的独立产品域（应为动作权限）
- 在系统层创建绕过平台用户表的登录账号
- PM 在 test/e2e/你试用未通过时宣布 `accepted` / 可打包

## 三、技术必须（MUST）

### 3.1 后端结构（见 backend-structure.md）

- Maven 多模块：`examine-core|plat|module|flow|upload|app|generator|web`
- `base/` = **MyBatis-Plus 生成器**，`manage/` = 业务手写
- 禁止 Agent 手写大批量 base CRUD
- 对外 Controller 只在 `manage.controller`；`examine-web` 不堆业务

### 3.2 数据库

- 表名 `un_` + 模块前缀；禁止 `un_platt_`
- 先 `sql/init.sql` → 再跑 generator → 再写 manage
- **种子数据**：平台内置超级管理员 `platform_admin_root` / `123123aa`（须写入 init.sql）

### 3.3 代码生成器

- **必须**使用 `examine-generator`（参考 `.oldbk/backend/examine-generator/`）
- 命令即配置；生成各模块 `base/`；禁止 Agent 手写大批量 base

### 3.4 API

- 冻结后改字段/枚举/错误码须走契约评审，禁止实现侧私改
- 系统进入接口（如 SYS-001 语义）返回系统/租户/成员/有效权限

## 四、流程必须（MUST）

### 4.1 Gate 顺序

```
prd_frozen → design_user_approved（仅用户） → api_frozen → build → user_script_passed
```

- **`design_user_approved` 前禁止** 创建/修改 `backend/`、`frontend/`、`sql/`
- Open Design 原型 + `user-approval.md` 是你签字闸门

### 4.2 协作

- Worker **新会话**，只读落盘文件，不传聊天上下文
- 问题走 `registry.jsonl`；P0 open → Gate 不得过
- 每任务 **task-accept** 验收；实现者 ≠ 验收者

### 4.3 完成定义

- `fullProjectDeployable=true` 须同时：e2e 车系统剧本 + 你试用无 P0 + clean build 证据
- 缺一即为 `false`，不得打包

---

## 五、PM 禁止（MUST NOT）

- 未经 test / task-accept / e2e / 你试用宣布阶段完成
- 关闭自己提出的 P0 issue 而无 verifier
- 代替你在 `design_user_approved` 上签字
- 把 escalated 问题标为 closed
- 扩大 MVP 范围而不 escalated
