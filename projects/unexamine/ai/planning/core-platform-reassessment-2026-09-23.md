## 结论

保留现有 Java/Vue、数据库、已生成 Base、通用记录存储以及已有动作、Flow、应用、工作台代码；围绕真实跨能力使用链整合公共层。再做一次整仓重建会丢掉有用的权限、迁移和业务实现，但沿 B15 的统计页面继续局部修补也不会解决平台与系统、统一动作和公共页面未贯通的问题。先暂停无关的 B15 功能扩展，按下面的依赖顺序重新准入短任务包。已写代码和已验证的局部贡献全部保留，后续必须重新证明它们能在总旅程中协同工作。

## 一套产品骨架

| 能力边界 | 复用和必须完成的工作 |
| --- | --- |
| 平台与系统 | 统一账号，明确平台成员、部门、角色、权限；系统成员与平台账号显式映射，系统和租户另有部门、员工、角色、数据范围。平台主页、平台后台、系统运行态、系统后台各有清楚入口；跨上下文访问必须重新判权。复用现有表与认证服务，补连续的开通、邀请、选人和角色预览链。 |
| 固定通用能力 | 任务、项目、工作日志、待办、消息、审计日志、后台作业、文件及通知按平台或系统作用域共享服务和页面。现有 B14 等代码是复用候选，不因有表/API 就认定完成；来源、对象跳转、权限、失败重试和普通用户工作入口要联合验证。 |
| 可配置模块 | 系统 → 模块组 → 模块 → 字段/页面/动作/发布版本。用户创建模块由元数据、通用记录和值/索引/关系运行时承载；不为每个自定义模块生成一套物理表、Java Manage 或独立 Vue CRUD。字段拖拽、属性面板、页面预览与运行页使用一致的类型协议和渲染器。 |
| 动作 | 固定增删改查/详情，加上可命名动作。`cfg_module_action` 可作为定义入口；按实际缺口增加有序动作效果配置及发布快照，覆盖字段/状态变更、负责人转移、目标模块新建或转化、关联与后续事件。编辑器通过选择字段、目标模块、映射和值来源来配置。统一执行器负责上下文、授权、校验、版本、幂等、事务、审计和可靠事件；各效果处理器只实现其不可配置的业务约束。无需为每个模块建立 Manage；真实特殊规则才写该领域的 Manage。 |
| Flow 与审批 | Flow 绑定动作或事件并定义生效模式、条件和版本；审批引擎只管理定义、实例、节点、人员、任务、超时、重复审批人策略、动态加节点及恢复。审批通过后的业务变更回到同一动作执行器，外部调用走可靠作业；不能让 Flow 直接写模块记录。 |
| 应用开放 | 平台应用和系统应用按资源、动作、字段、数据范围、租户与调用身份授权；读走统一查询，写走统一动作。微信、企业微信、飞书、钉钉的自建应用适配共用授权与回调协议，提供方差异留在适配器。真实外部租户/凭据缺失时只记录对应阻塞。 |
| AI Agent | 模型、Agent、版本、提示词、工具授权、知识/上下文、系统归属和发布由管理员在页面配置；平台 Agent 不凭平台身份直接进入系统数据。查询使用同一字段/数据权限；写入先给结构化候选及影响预览，经人确认后调用同一动作执行器，留下审计与消息。现有 AI 基础只能算复用候选，完整使用闭环仍待验收。 |

配置界面以点击、选择、拖拽和结构化条件/映射编辑为主；JSON 可以是内部持久化格式或业务字段值，但不是配置动作、Flow、页面和 Agent 的操作方式。

## 生成器怎样真正节省开发量

现有 `projects/unexamine/tools/regenerate-base.ps1` 已是一条命令：校验工作区和迁移、复用项目 MySQL、生成固定表 Base 两遍检查确定性、比对 Manage 文件哈希并可编译。当前配置为 18 个模块、170 张表、680 个生成文件。它目前**按配置整体重生成**，没有“指定模块只生成该模块”的命令参数；依赖 Docker MySQL，Docker 故障时不能声称已运行成功。

固定能力的新表按“设计表和中文备注及 `*_time` 字段 → 增量迁移并保留旧数据 → 写入 `base-codegen.json` → 执行生成命令 → 只编写必要领域服务/控制入口/页面 → 真实业务验证”进行。Base 仅覆盖实体、Mapper 和基础 Service，不替代授权、动作效果、审批、渠道协议及用户界面。先复用现有生成器；若整套生成反复成为实测瓶颈，再给它增加可确定性验证的指定模块模式，不单独为优化命令消耗多个产品任务包。生成目录不可手改，不能重生成覆盖手写业务代码。

## 依赖顺序与任务包

每包按源码现状估算不超过 240 分钟，只有一个可观察的业务结果，包含真实身份、API/数据库、页面和失败分支；未通过则记录准确断点，不把局部测试称为完成。需要拆小的能力继续拆，不删原需求。

1. **公共身份与壳：** 同一账号在平台、系统、租户正确切换；管理员能开通员工、部门、角色，普通成员只能看到授权模块。固定导航、人员选择器和权限预览成为其他功能的公共入口。先核实 B03/B02 现有实现与真实页面，按缺口补全。
2. **模块与动作最小纵向链：** 在两个不同模块用相同的字段表单、列表、详情、发布和动作编辑器完成新增、状态变更、转移及跨模块转化；同一执行器在直执行和审批后执行两种模式下都只产生一次结果。复用已有 B01/B04/B05/B06/B07 代码并收敛分散入口，按实际缺口补动作效果配置，而非复制另一套执行器。
3. **Flow 内核与工作入口：** 同一业务动作配置审批条件、审批人、超时、无审批人策略和动态节点；实例处理、待办、消息、审计、任务/工作日志在同一对象上可追踪。复验 B08—B10、B14 的真实集成，而不重复造任务、消息表。
4. **受控对外与 Agent：** 配置应用授权后，外部身份能在授权范围查询/触发已发布能力；Agent 能在当前上下文查询、提出动作候选并经人工确认执行。渠道凭据不能取得时保留模拟协议验证并明确真实联调阻塞；B11/B12/B16 不提前宣告完成。
5. **统计、治理与交付：** 统计数据源、仪表盘、KPI、平台服务和运维建立在上述相同上下文、发布和权限协议上；最后连续完成一条“创建系统 → 开通成员 → 配置两模块 → 执行动作/审批 → 工作台/应用/Agent/统计反馈”的完整旅程，核对 `docs/user_requirement.md` 的所有剩余要求。B15.1 的现有工作保留并在其依赖就绪后继续，不能用统计页验收代替整个平台验收。

下一次实施先用 `execution-context` 和当前源码/页面核对第 1 包的共享依赖，正式修订 `execution-control.json`、`spark-state.json` 的准入范围与验收后再改产品代码；不要把本文件当成自动完成 B15.1 的凭证。现有 Docker 故障只阻塞真实数据库、容器和浏览器验收；可独立的源码核对、契约收敛和非运行测试继续做，恢复后复用原有服务身份验证。
