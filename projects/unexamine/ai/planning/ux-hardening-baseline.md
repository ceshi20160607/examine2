# 产品体验 Hardening 基线

## 1. 状态纠偏

当前 56 个历史周期证明了功能、权限、数据、部署脚本和真实入口能够运行，但不能继续把“功能可执行”解释为“产品已经完整”。
`CYCLE-052` 证明的是同一 Vue 应用在桌面与移动断点能够完成指定旅程；用户对现有页面的直接反馈证明，信息架构、视觉层级、语言和操作密度仍未达到可正式使用的产品标准。历史证据保留，不删除、不改写；新增体验整改任务和周期完成后，项目才能重新声明整体完成。

## 2. 当前体验问题基线

| 问题 | 当前表现 | 目标状态 |
| --- | --- | --- |
| 工作空间边界 | 平台、系统运行态、系统后台的入口和导航语义混杂，顶部与侧边存在重复入口 | 用户始终知道自己处于平台、某个系统运行态还是后台；全局动作只在顶部出现一次，当前工作空间导航只在侧边出现一次 |
| 主任务不突出 | 刷新、导入、导出、AI、新建、视图、列设置等动作同时占据页面首屏 | 每页围绕一个主要用户任务组织，最多一个主按钮；低频动作进入次级菜单、抽屉或上下文操作 |
| 内部实现语言外泄 | 页面和演示数据出现 C45/C47、READY、ACTIVE、内部编码、默认主租户、显式共享等工程或验收措辞 | 默认界面只显示用户可理解的业务名称和状态；内部编码仅在有明确价值的详情或诊断区域出现 |
| 页面层级过多 | 后台菜单、模块树、编辑区、标签栏、字段类型面板同时争夺注意力 | 使用清楚的“选择对象—配置类别—编辑内容”路径；非当前步骤的面板折叠或按需打开 |
| 首页价值不足 | 平台首页大片空白或只展示单个技术指标；系统首页卡片更像验收样例 | 首页回答“我今天要处理什么、最近发生什么、从哪里继续”，内容来自真实权限和业务数据 |
| 运行列表过载 | 筛选、状态、视图、列设置、批量和大量行操作同时展示，并出现横向滚动 | 高频查询和新建优先，筛选与视图按需展开；整行进入详情，行内只保留不同语义的关键动作 |
| 移动端机械压缩 | 桌面动作区和层级直接纵向堆叠，底部导航遮挡内容，原始时间和状态格式直接暴露 | 移动端使用相同业务与配置但采用移动任务流，关键动作固定且不遮挡，信息按优先级重排 |
| 视觉语言不统一 | 首页过疏、配置页过密，卡片、边框、阴影、间距和状态表达缺乏统一节奏 | 统一 Token、页面骨架、密度、状态、反馈和空错加载状态；运行态与配置态同源但有清楚的信息重点 |

## 3. 目标信息架构

### 平台工作区

- 首页：待处理事项、未读消息、获权系统、最近访问和平台任务。
- 系统：只负责发现、创建和进入系统，不承载系统业务操作。
- Flow、应用、任务、AI、待办、消息：只展示平台层或用户获权聚合结果。
- 平台后台：身份源、平台组织权限、平台 Flow、平台应用、平台 AI、平台仪表盘和平台运维。

### 系统运行工作区

- 首页：当前系统与租户的待办、业务指标、最近记录和模块快捷入口。
- 业务模块：模块组与模块导航、列表、详情、新建编辑和配置动作。
- Flow、任务、待办、消息、文件、AI：只展示当前系统和租户上下文结果。
- 系统后台：从运行工作区明确进入，也能明确返回；不与普通业务导航混排。

### 系统后台

- 固定一级目录保持需求定义不变，但每个页面采用统一的对象选择、配置类别、编辑和发布路径。
- 模板配置只保留模块信息、模块字段、模块动作、模块 Flow、模块应用五类语义；页面、菜单、版本和发布留在对应类别内部。
- 高密度设计器只在桌面呈现；移动端给出清楚的只读结果或转到桌面提示。

## 4. 页面与交互规则

1. 页面首屏必须能回答“我在哪里、这里能做什么、下一步是什么”。
2. 每页最多一个主按钮；刷新不作为主任务；低频和危险动作不与主动作同权展示。
3. 顶部只承载全局搜索、全局待办消息、上下文切换和个人入口；侧边只承载当前工作空间导航。
4. 用户默认不需要理解内部 ID、英文状态码、测试周期编号、权限编码、原始 JSON 或数据库语义。
5. 列表默认点击整行查看详情，行内不再重复“查看”；操作超过三个时收敛到更多菜单。
6. 筛选、列设置和保存视图属于辅助任务，默认保持紧凑，不阻断用户阅读数据。
7. 表单按业务分组，错误就地解释并保留输入；详情按概览、关联、Flow、文件、评论和历史组织。
8. 空状态说明为什么为空并提供下一步；错误状态显示用户可执行的恢复动作和 requestId。
9. 桌面参考视口不得依赖页面级横向滚动完成核心任务；移动端不得出现固定导航遮挡正文。
10. 所有验收数据使用真实业务名称，测试标识只保存在证据和诊断信息中。

## 5. 整改工作流

1. 体验基线与设计语法：冻结问题清单、页面骨架、导航模型、Token、文案和状态规则。
2. 全局壳与工作空间：重构平台、系统运行态和后台的导航、上下文及返回关系。
3. 平台与系统首页：以用户任务和真实业务信息替代空白及验收卡片。
4. 模块运行主链：重构列表、详情、表单、动作和桌面/移动布局。
5. 平台与系统后台：重构设置目录、配置对象选择和保存发布路径。
6. 低代码配置台：重构模块、字段、页面、动作、Flow 和应用绑定的编辑节奏。
7. 全路由一致性：清理工程语言、统一状态和反馈，完成桌面、平板、移动与键盘验收。

## 6. 完成门禁

- 角色门禁：普通用户、系统管理员、平台管理员分别完成首要任务，不依赖开发人员解释入口。
- 清晰度门禁：首次进入页面能识别工作空间、页面目的和主动作；顶部与侧边不存在同义重复入口。
- 语言门禁：核心页面不存在测试周期编号、内部状态码、权限代码或实现说明作为主要文案。
- 密度门禁：桌面首屏主任务清楚，配置页非当前面板按需展开；移动端无导航遮挡和不可控横向溢出。
- 一致性门禁：相同按钮、状态、表格、表单、详情、空错加载反馈在全部页面使用同一设计系统。
- 旅程门禁：登录、平台首页、进入系统、模块列表、详情、新建编辑、待办审批、系统后台和模板配置均有真实入口截图、操作结果及必要的数据读回。
- 用户验收门禁：不能再以测试通过、HTTP 200、功能存在或能点击替代“页面清楚且愿意使用”的验收结论。
