# unexamine 当前产品与实施基线

状态：2026-10-09，依据当前需求全文和本轮用户确认整理，供整体审阅。**产品需求的唯一来源仍是 [`docs/user_requirement.md`](../../../../docs/user_requirement.md)**。本文件只把已确认的主线、实现边界和验收路径放在一起；如需修改产品规则，先改需求源，再更新任务与实现。旧设计、旧测试数据和旧完成报告不能覆盖这里引用的当前需求。

## 一、系统最终要让谁完成什么

unexamine 是一个可配置业务系统平台。平台用户可以创建、参与多个系统；系统管理员在后台配置组织、角色、模块组、模块、字段、页面、动作、Flow、应用、仪表盘和 AI，发布后普通成员在系统运行态使用这些模块处理业务数据。固定平台能力有各自的业务表；用户配置的模块共用元数据和业务记录结构。详见需求 §4、§5、§7、附录 A.14—A.19。

| 身份与空间 | 负责的事情 | 关键边界 |
| --- | --- | --- |
| 平台账号 | 注册登录、维护基本资料、创建或进入有权系统 | 平台统一管理基础用户信息；平台角色不自动取得系统业务权限。 |
| 平台后台 | 平台组织、角色、字典、系统管理、平台 Flow/应用/AI、审计与运维 | 只配置平台层；不能以平台管理员身份绕过系统成员和租户边界。 |
| 系统当前所属人 | 创建系统时产生，可转让给另一有效平台账号 | 对该系统隐式拥有全部数据查看和后台配置权限，不依赖角色；转让后原人立即失去这项隐式权限，手工授予的普通权限仍按角色计算。 |
| 系统成员／租户成员 | 在平台账号基础上保存每个系统、租户的组织和成员扩展 | 进入系统和租户必须有有效映射；单租户自动使用主租户。 |
| 系统后台 | 配置本系统组织、角色、模板、Flow、应用、仪表盘、AI、参数和开关 | 后台是配置空间；普通运行态不混入设计器和角色设置。 |
| 系统运行态 | 按模块组和模块导航，处理记录、Flow、任务、消息等日常业务 | 顶部模块组、左侧组内模块、内容区列表／表单／详情；只呈现有权内容。 |
| 应用 | 凭 appId/secret 向系统内外开放已发布能力 | 应用是受控接口入口，不是模块父容器或普通业务首页；配置人员用于数据范围，不冒充调用者。 |

## 二、一条可验收的产品主线

1. 用户注册平台账号，创建一个或多个系统，或经授权加入现有系统。创建系统时自动建立**主租户**，多租户开关默认关闭。系统当前所属人能直接进入后台完成初始配置。
2. 系统后台配置组织及角色、字典、模块组、模块与字段、列表／表单／详情、动作、Flow、应用、数据源／仪表盘和 AI；草稿经过校验和发布后才影响运行态。主租户发布公共配置，非主租户在允许范围内扩展。
3. 普通成员进入有权系统和租户。顶部选择模块组，左侧选择模块，在列表、表单、详情中创建、查询、编辑和流转记录；主记录、自定义字段值、关联、子表等由同一业务动作一致保存。导入、导出、打印、转移、转化、审批和 Flow 触发作为模块动作出现。
4. 系统管理员按需开启多租户，用户仅切换获权租户。来源租户可在多租户开启时显式共享同系统内指定模块的数据或范围。关闭开关只暂停非主租户入口和共享生效，重开恢复原有效配置。
5. 系统应用以已发布授权向其他系统及外部开放系统模块／Flow；平台应用开放平台能力／Flow。应用统一管理凭据、能力权限、数据范围和审计。应用调用、仪表盘、AI 和待办最终读取同一批有权业务数据，不能另造绕过权限的数据通道。AI 写入需人工确认。

这条主线只是贯穿验收入口，不代替需求中的文件、任务、工作日志、消息、审计、运维、按需配置的外部渠道、响应式页面等能力；它们分别完成并最终组合验收。

## 三、不能再误解的规则

### 1. 系统所属权与业务记录

- `un_sys_system.creator_account_id` 表示**当前系统所属账号**；转让时更新并审计。新所属人在各有效租户具有有效成员映射；双方旧系统会话失效。原所属人失去隐式最高权限，但不无故删除其人工配置的角色。
- 每条业务记录有系统、租户、模块、负责人和创建人。表单未配置、调用未填写、导入或应用创建时，缺少的负责人和创建人都补为**当时系统当前所属人**对应的有效系统／租户成员。显式提供者须校验有效成员映射。
- 记录的创建人字段与**实际操作者**不同：实际登录成员、应用凭据、请求和来源写在审计／调用日志里；不能拿应用配置中选定的数据范围人员冒充操作者。
- 对部门、成员、模块、字典等被引用对象执行停用、删除或改归属时，业务层先查引用并给出阻止、替换、转移或归档处理；部门转移只是该通用规则的例子。不得靠数据库触发器静默改数据。

### 2. 模块、动作和数据权限

一次模块动作先检查系统／租户、模块、**该动作**及字段权限，再计算可访问的数据。普通成员的数据范围取当前全部有效角色对“模块 + 动作”的授权并集，数据范围按记录**负责人及其当前组织归属**计算，不以记录存下的旧部门或“创建人等于我”代替负责人范围。系统当前所属人有独立的隐式全量权限。

多租户有效共享只扩充该动作可访问的**数据集合**，不会授予模块动作本身。最终可访问集合为“本租户角色负责人范围 ∪ 当前有效共享范围”，仍受系统、租户、账号状态和字段安全边界约束。共享记录保留来源租户归属，目标租户不能再共享给第三方，**共享记录不得转化**。转化只在同系统、同租户内按目标模块已发布规则创建独立记录，同一来源到同一目标模块最多成功一次。

### 3. 多租户开关与配置继承

| 场景 | 入口和数据 | 已保存状态 |
| --- | --- | --- |
| 新建系统／关闭多租户 | 只进入主租户，不显示非主租户和共享数据；非主租户旧会话失效 | 非主租户状态、业务数据、共享授权、历史保持原样。 |
| 开启多租户 | 按有效成员权限选择租户；有效共享重新生效 | 不要求平台预授权、租户合并、数据迁移或逐项重新启用。 |

主租户发布基础模块和配置。非主租户可以增加本租户模块和允许扩展的字段／页面等，但**模块只能挂在主租户已有模块组下**，不能自己创建独立模块组或改写主租户强制配置。发布、版本、回滚和依赖检查在主配置与扩展配置上都要有效。各租户的仪表盘页面和组件独立配置、独立发布；未发布时不显示其他租户的仪表盘。已授权的主租户数据源仍可由其他租户显式选用，并按当前租户重新取数。

### 4. 应用授权

- 系统应用从系统组织、平台应用从平台组织选择人员或部门；发布的授权固定资源、动作、字段、系统／租户和负责人数据范围。所选人员后来角色变化**不改变**应用授权。
- 所选人员停用或移出相应边界时，只剔除该人员；其他有效范围仍可调用，全部无有效范围时报错。所选部门停用或删除时整次调用报错，让管理员修正配置。
- 模块记录的查询按负责人或负责人当前所在部门匹配应用已发布范围。应用创建、更新不能借缺省负责人或改负责人写入范围外数据。缺字段时使用系统当前所属人补齐，然后仍检查应用写入范围。
- 平台应用使用平台组织范围并开放平台 Flow；系统模块／系统 Flow 由目标系统应用开放。系统之间调用目标系统能力，也通过目标系统的应用授权。签名、防重放、幂等、限流和调用审计都属于应用自身。

## 四、表、Base、manage 和页面如何分工

- 固定能力使用已设计的物理业务表；所有产品表统一以 `un_` 开头，平台为 `un_plat_*`、系统为 `un_sys_*`、Flow 为 `un_flow_*`，其他业务域按代码模块使用相应前缀。用户配置的业务模块使用 `un_cfg_*` 模块／字段／页面／动作／发布元数据，以及 `un_biz_*` 主记录、字段值、索引、关联和子表。运行时不为用户模块生成新物理表或 Java 类。
- 表是持久化结构：表和字段有中文备注，时间字段用 `*_time`，必要主键／唯一键／索引保留，**不建外键或触发器**。关联有效性、删除影响、状态流转由 manage 业务处理。
- 首装 SQL 按后端代码模块拆成源文件，工程工具生成 `db/init.sql`、`db/update.sql` 和 `db/final.sql`。固定表结构变动先完成 SQL 和空库检查，再运行工程生成器生成贴表 Base CRUD，最后适配 manage、API 和页面。常规单表访问经 Base Service，复杂跨表／动态查询按需要写明确的 Mapper／Repository；不把业务逻辑塞入 Base，也不为简单 CRUD 造额外封装。
- 后台提供可视化配置并发布；运行态 API 返回当前有权字段、字段类型、字段配置和页面配置，前端据此生成列表／表单／详情。主记录及自定义值由 manage 一次性保存与验证，不能靠页面自行拼接多次写入。
- 现有数据都是测试数据，本轮不为它们做迁移。已在独立空库验证统一命名后的 188 张产品表，并以相同结构重生成 Base；这只证明结构链可安装，**不证明所有产品功能可用**。

## 五、自定义仪表盘和数据源

仪表盘组件可直接绑定当前访问者有权限的已发布模块，也可绑定有权使用的已发布数据源。管理员可通过可视化配置选择模块、已发布的关联字段或子表关系、过滤条件、输出字段和统计口径，形成新的数据源并发布版本。数据源是查询配置，不产生新的业务模块或任意 SQL；不开放数据库直连或外部 API 数据源。主租户已发布的数据源可供有权的非主租户使用；预览、运行、下钻和导出都按当前访问者的租户、动作、字段、负责人及有效共享范围重新取数。跨系统数据通过目标系统应用授权访问。

平台或系统内的同一套 Flow 引擎也服务其他系统与外部系统。外部系统可在自己的界面通过获权应用接口配置、发布、发起、查询和办理审批；配置与每种运行操作分别授权。完全外部的审批人标识由调用方传入，与待办指定标识比较，并记录应用和外部审批人。Flow 节点调用外部 API 是流程动作，不属于仪表盘数据源。

## 六、页面与能力交付范围

平台主导航为仪表盘、系统、Flow、应用、任务、AI、待办、消息、个人中心，以及按权限可见的系统后台、平台后台。平台后台负责平台层配置，系统后台负责系统层配置；系统运行态聚焦业务模块。正常页面应以中文业务名称、可搜索选择器、可视化字段／页面／流程配置完成操作，不让普通用户填写技术 ID 或 JSON。桌面与移动端共用响应式 Vue 应用。

完整交付还要分别覆盖：字段类型与字典、模块动作和批量处理、Flow／审批／自动化、普通任务／项目任务／工作日志、待办／消息、文件／附件／打印、导入／导出、数据源／仪表盘／统计／KPI、AI 模型接入与人工确认、审计／运维／备份恢复。微信、企业微信、飞书和钉钉是应用后台按需配置的渠道；未配置不启用，也不阻塞核心系统交付。配置后应按具体产品形态完成真实联调，不能把本地模拟调用写成已实接。

## 七、代码取舍与实施顺序

| 处理 | 范围 | 判断 |
| --- | --- | --- |
| 保留并贯通 | 平台账号、系统成员映射、模块发布和通用记录结构、Flow、任务、消息、文件、应用凭据、仪表盘／AI 基础能力 | 主干可复用；必须用当前权限和真实业务读回重新验收，旧“完成”记录不抵扣。 |
| 改写错误语义 | 当前所属权、多租户模式、负责人范围、共享并集、应用数据范围、运行态导航 | 按本文件前述业务旅程组合验收，不继续旧局部补丁链。 |
| 删除失效设计 | 平台多租户准入、租户合并／迁移、单人跨系统身份映射、独立导出配置与报表运行入口 | 核对引用后删除 SQL、Base、manage、API、菜单和页面残留；不保留假兼容。 |
| 保留工程能力并收紧 | `template_base` 的需求入口、SQL 准备、Base 生成、任务绑定与证据校验 | 工程门禁只保证进入和证据完整性；产品验收必须真实操作、数据库读回、越权拒绝和页面重进。 |

顺序：**确认本基线和唯一需求源 → 固定表空库安装并生成 Base → 系统账号／所属权／租户 → 组织角色与模块组／双模块 CRUD → 动作／共享／Flow／工作 → 应用开放 → 仪表盘／AI／其余能力 → 全量页面和端到端验收**。每个可观察业务结果组成不超过 240 分钟估算的任务包；公共契约先稳定，文件不冲突的工作再并行，数据库夹具、生成和集成构建串行。每步按 `execution-context`、实际验收、`execution-verify` 记录，不能只更新状态或哈希宣称完成。

## 八、最终验收样例与当前状态

1. **身份与后台**：新用户创建系统和主租户；系统当前所属人不绑定角色仍可配置；转让后旧会话失效，原人重新登录只剩显式角色权限。
2. **多租户**：系统管理员直接开关；关闭时非主租户入口和共享数据消失但状态／数据／授权不变；重新开启恢复原有效范围；越权直接调接口被拒绝。
3. **双模块业务**：发布结构不同的两个模块，普通成员按模块组进入、保存主记录与自定义字段，重开列表和详情读回；负责人换部门后数据可见范围随当前组织变化。
4. **动作与共享**：本租户范围与有效共享范围并集可见；共享仍要动作授权，撤销立即失效，共享记录转化失败；导入、导出等在模块内执行并按权限过滤。
5. **应用**：发布人员／部门范围后使用 appId/secret 调用；角色变化不影响，异常人员逐个排除、失效部门报错；创建记录缺负责人／创建人按当前系统所属人补齐，并核对调用审计。
6. **组合能力**：Flow 审批与记录状态一致，任务／待办／消息指向同一对象；仪表盘数字和 AI 查询遵守同一权限，AI 写入需确认；桌面和移动页面完成业务闭环。

截至 2026-10-09：旧 `ai` 分析、周期和失效证据已清理。统一 `un_` 表名后的 188 张产品表已在独立空库安装并读回，Base 两次生成一致；前后端编译及仪表盘、后台任务、应用范围的局部 HTTP 集成测试通过。系统所属人无角色时的字段写入已按当前规则修正，应用字段由发布授权入口校验。系统所属权转移、多租户开关及完整页面业务旅程仍须在当前结构下组合验收。**结构和局部接口结果不等于整套系统已交付。**

当前没有等待产品裁决的问题。后续发现规则歧义时，先核对唯一需求源及已确认口径，再调整表、manage、页面和验收。
