# Unexamine 产品系统蓝图

> 本文是 `docs/user_requirement.md` 的实现蓝图，不是新的需求来源。任何冲突均以需求文档为准。

## 1. 产品判断

Unexamine 是一套可配置业务系统平台。用户面对的不是数据库、接口参数或配置表，而是一套从组织建立、业务建模、发布运行到持续经营的完整工作系统。

所有页面必须服从同一条业务主线：

`组织成员与权限 → 业务模块与动作 → 流程与触发 → 业务记录与工作项 → 待办、消息和指标 → 智能助手`

任何无法落在这条主线中的页面都不得继续作为孤立一级入口存在。

## 2. 四层产品空间

### 2.1 平台工作区

面向所有已登录用户，承载跨系统工作：仪表盘、系统、Flow、应用、任务、AI、待办、消息和个人中心。系统入口负责完成系统与工作空间上下文切换。

### 2.2 系统工作区

面向业务使用者，只读取已发布配置：

- 首页：当前系统公共仪表盘、我的工作摘要、最近业务。
- 业务：顶部模块组、左侧模块、列表/表单/详情及其动作。
- 工作：我的申请、待审批、抄送、普通任务和项目任务，来源仍各自独立。
- 分析：已发布仪表盘和 KPI，不建立重复报表入口。
- 助手：始终从当前页面、模块、记录或工作项获得上下文。

文件、评论、变更历史和流程状态属于业务记录详情，不再作为普通用户的孤立工作首页。

### 2.3 系统管理

将原有十多个平级入口收敛为四个管理工作域：

1. 基础与组织：系统信息、组织成员、角色权限、统一认证、字典和业务参数。
2. 业务建模：模块信息、字段、页面、动作、模块 Flow、模块应用、仪表盘和打印模板。
3. 连接与智能：应用授权、模型授权、助手能力及其数据范围。
4. 运行治理：审计、后台作业、健康、配额、备份与恢复。

二级对象只在所属工作域内出现。默认页面使用人员选择器、字段选择器、条件构造器和可视化画布；编码、ID、JSON、表达式仅在明确的高级设置中出现。

### 2.4 平台管理

只管理平台级身份、全局策略和平台能力，不能绕过系统成员、工作空间和数据权限直接修改系统业务。

## 3. 统一对象关系

| 主对象 | 必须关联 | 运行结果 |
| --- | --- | --- |
| 部门 | 上级部门、负责人、成员 | 人员选择、审批人解析、数据范围 |
| 成员 | 平台账号、部门、角色、工作空间 | 登录身份、字段权限、可见数据 |
| 模块 | 模块组、字段、页面、动作、发布版本 | 业务列表、表单、详情和操作 |
| 模块动作 | 权限、确认策略、Flow/应用/打印/转化配置 | 用户可执行的业务行为 |
| Flow | 业务对象、触发事件、节点、审批人规则、版本 | 实例、任务、审批历史和业务回写 |
| 数据源 | 已发布模块字段、关联、筛选、版本 | 仪表盘、KPI、导出和助手查询口径 |
| 仪表盘 | 数据源、组件、布局、权限、发布版本 | 系统首页、模块首页或个人首页 |
| 助手 | 模型授权、模块/数据源、动作、权限与确认策略 | 查询、建议和经确认的写操作 |

## 4. 必须交付的五条纵向业务链

### A. 建立组织

管理员建立部门树，添加或邀请成员，把成员分配到部门和角色；人员字段、审批节点和数据范围立即使用同一份成员目录。

### B. 建立业务

管理员创建模块组和模块，通过可视化方式配置字段、列表、表单、详情及动作，完成校验后发布不可变版本；运行态只读取已发布版本。

### C. 建立流程

管理员从模板或空白画布创建 Flow，绑定业务模块和事件，通过人员/角色/部门规则选择审批人，模拟并发布；业务用户从记录动作发起，审批结果回写业务状态并留下完整历史。

### D. 建立经营视图

管理员从已发布模块构建数据源，拖入指标、图表、排名、列表或待办组件，配置筛选和下钻后预览发布；系统首页立即显示发布结果。

### E. 使用智能助手

管理员选择模型、业务范围和允许动作并发布助手。业务用户无需填写模块编码或字段编码，助手从当前页面获得上下文；查询显示来源，写入或发起 Flow 必须先展示结构化变更并确认。

## 5. 产品语言与交互红线

- 默认界面不要求用户输入账号 ID、成员 ID、部门 ID、模块编码或 JSON。
- 空状态必须说明业务价值，并提供完成当前链路的一个主动作，不能展示大片禁用表单。
- 一个业务能力只能有一个主要入口；后台执行、文件和消息可以承载结果，但不能复制业务配置中心。
- 页面标题说明用户正在完成的业务目标，不以内部数据结构或技术动作命名。
- 全站中文术语统一：使用“流程”“工作空间”“成员”“业务模块”“智能助手”；英文仅保留不可替代的标准或品牌名称。
- 发布是完整链路：草稿 → 校验/预览 → 发布 → 运行 → 版本/回滚 → 影响与审计。

## 6. 端到端验收场景

以“客户运营中心”为首个可用性基线：

1. 管理员建立销售部、销售经理和销售成员并完成角色授权。
2. 管理员发布客户、联系人、商机和合同模块，字段与动作可在运行态直接使用。
3. 合同金额达到条件时发起合同审批，销售经理在待办处理并回写合同状态。
4. 首页展示新增客户、商机金额、合同审批和销售目标，所有指标可下钻到权限内记录。
5. 销售人员从客户页面直接询问助手并生成跟进计划；提交前看到变更预览，确认后生成任务和日志。

只有这五步使用真实角色、真实上下文和真实数据全部走通，才能判断系统已具备正式使用基础。测试通过、接口存在或页面可打开均不等价于完成。
