## 1. 控制关系与四小时含义

工程总控负责选任务、限制范围、依赖与资源协调、控制开发窗口、组织综合验证和判定验收；它按需要选择模型及宿主能力。Codex 的定时、任务或其他能力属于可选择的执行能力，不能反过来定义工程开发流程。把原定时配置复制进项目 JSON，并不等于工程总控已经控制了执行。

四小时是本轮开发窗口的上限。窗口内的既定任务提前开发完，就提前进入整理、综合验证与验收；到四小时则停止接入后续开发任务，在安全边界保存当前工作与未完成断点，转入本轮综合验证与验收。软计时不强杀正在提交的事务、迁移或不可中断操作，也不能以“先做完下一项”为由无限延长开发。验收结论形成之前，不能自动开始下一轮开发。

依据：唯一需求源 `docs/user_requirement.md:2772`、`:2784` 及用户本次澄清。源码中的 240 分钟目前是估算和排期容量，不能当成已实现的实际计时机制。

## 3. 项目实例与产品运行时

唯一需求源是 `docs/user_requirement.md`，原文按较新附录澄清处理冲突。A.13 规定工程、生成与测试边界，A.14—A.16 规定平台/系统/租户/应用/低代码数据边界，A.17 规定通用动作、公共页面、审批补充和四渠道要求。

`projects/unexamine/ai/` 是项目专属控制面；当前执行依据是 Spark 方案、状态与需求账本。B00—B19 是能力归属，编号子步骤是编辑边界，均不是实际四小时周期。已有 schedule/task graph/周期证据可以提供结构线索，不能恢复为当前执行入口或完成判定。

产品技术边界是 Java/Spring Boot 后端、Vue 前端、MySQL 和 Redis。固定平台能力使用物理表和生成 Base；管理员创建的低代码模块使用元数据、主记录、字段值、查询索引和独立关联表。不能把“代码生成 CRUD”理解为用户每创建一个模块就动态建表或生成 Java。

### 核心业务链

1. 统一平台账号通过显式成员映射进入系统/租户，权限合并后仍受系统、租户、共享、字段、渠道和数据范围硬限制。
2. 管理员按系统 → 模块组 → 模块创建配置，通过拖拽字段、页面、动作、Flow、权限和发布版本形成运行配置。
3. 普通用户通过运行导航进入公共列表、表单和右侧详情，保存调用 manage 业务入口。
4. `RuntimeDataService.createAction` 等方法构造可信动作输入并调用 `FoundationControlService.execute`；基础数据由生成 Base 保存。
5. 公共执行器根据绑定执行 DIRECT、AFTER_EXECUTION、AFTER_APPROVAL 或 FLOW_ONLY，保存幂等结果与持久化 outbox。`BusinessActionFlowExtension` 接入 Flow；`BusinessActionApprovalCoordinator` 锁定意图并在审批通过后恢复业务、重查限制，失败保存可解释结果。
6. Flow、应用、导入和 AI 应当消费同一动作与权限语义。通知、文件、工作任务、待办、仪表盘、审计和运维是相关完整需求，不能因核心主链演示成功而忽略。

生成器当前基础 Service 模板仅有 insert/select/update/delete，没有审批触发或业务动作钩子，且关闭基础 Controller 生成。可预设公共动作点的方向与需求相符；目前动作点真实位于 manage 公共执行器，不能把任意一次物理 insert/save 当成一次完整业务动作。

### 前端结构

现有平台、平台后台、系统运行态、系统后台壳层，以及 ProductListWorkspace、表单/详情抽屉、SchemaFormLayout、SchemaRecordTable/Detail、字段输入/展示和动作组件。ModuleFormDesigner 有字段类型区、拖拽画布、属性面板与预览；普通模块应通过已发布配置复用这些组件。

存在公共组件并不等于消费一致：`ModuleFormDesigner.vue:142` 对非共享类型使用禁用占位输入；`RuntimeWorkspaceView.vue:1825` 起又自行分支处理级联、人员、部门和关联，剩余类型回落普通输入。这说明预览与运行并未完整共用所有字段编辑能力。不能只统计类型清单或组件数量宣称字段链完成。

## 4. 源码可确认的接线差异

- `ApplicationBridgeService.java:414`、`:437` 的 CREATE/UPDATE 仍调用返回记录的兼容方法。`RuntimeDataService.java:888` 附近的 requireSavedRecord 在动作没有记录值时抛出 ACTION_RECEIPT_REQUIRED；AFTER_APPROVAL/FLOW_ONLY 需要动作回执。由此可以确认入口契约尚未统一；具体渠道、角色和模式行为须在对应既有步骤实测，不在本次阅读中冒充测试通过。
- 字段配置、发布校验、前端类型清单、公共输入器和运行页分支各有职责，但完整能力协议尚需逐项对齐。先区分未实现、未接通和未验证，不能据 unverified 状态推断全部代码不存在。
- FlowRuntimeService 已有任务处理、超时作业和动态加节点相关路径；这不证明超时竞态、同一审批人后续自动通过或完整节点矩阵达到要求。这些仍属于既定 B08—B10 的当前行为验证范围。
- 检索四渠道名称，当前主要命中 SSO 的 WECHAT/DINGTALK 通用 OAuth 配置路径，未找到能据此证明四渠道自建应用实际收发/回调链贯通的依据。应用授权桥梁与渠道实接是不同验收范围，B12 仍须实际验证。
- 项目根 README 仍声明历史全部完成，而 Spark 状态仍列有完整字段、页面、审批、应用与交付缺口。这是资料权威与完成口径不一致，不能用文档中的完成声明替代当前业务。
