# 按业务模块实施与验收后端

## 依据与边界

- 需求以 `docs/user_requirement.md` 和用户本轮说明为准；94 张原名表及用途以 `docs/表意义.md` 为准。
- `docs/old_table1.sql` 只查字段含义与早期审批规则，不执行其建表、删表或数据语句。
- 一个 `unexamine_r15` 隔离库、一个 9999 后端；所有基础后端能力经真实接口验收后，再开发前端。
- 模块归属和全部 94 张表的分组见 `business-modules.md`；每个模块交付可请求的接口、实际数据库结果、权限结果及错误结果。只建表、只生成 Entity 或只整理路由都不算完成。

## 业务边界与接口合同

需要分页的列表接收 `page`、`size` 和业务过滤参数；各域排序参数及页码响应字段以接口合同为准。`size` 有上限；排序字段从该资源公开的列白名单选择，未知字段返回 400，绝不拼接客户端 SQL。资源读写都依据会话、系统及租户范围校验。更新与删除先检查资源归属，不以客户端传来的租户 ID 直接授权。失败输入返回 400，无登录返回 401，无权限返回 403，资源不存在返回 404，状态冲突返回 409。

| 模块 | 业务闭环与接口 | 依赖 | 必须真实核对 |
| --- | --- | --- | --- |
| `identity` | 平台开通系统/租户、成员登录，维护组织、角色、菜单、数据权限、消息和日志 | `foundation` | 密码摘要、会话失效、跨租户拒绝、授权立即生效 |
| `commonresource` | 文件上传下载、公告发布、AI 配置按平台/系统/租户范围保存 | `identity` | 文件字节一致、公告可见时间、密钥不明文返回、范围拒绝 |
| `module` | 分组/模块/字段/表单/表头/查询字段/场景/记录/团队/关联/规则按一个模块旅程操作 | `identity` | 字段类型和必填、场景过滤排序、持久化、并发版本和逐记录权限 |
| `flow` | 流程草稿、发布版本、模块事件绑定、实例、待办、操作、定时和异常 | `module` | 快照不变、保存记录自动触发、处理人失效、幂等与到期状态 |
| `examine` | 审批定义及人员/节点配置、模块记录发起、转办/拒绝/通过/撤回/超时 | `module` | 审批实例与流程实例独立、处理人范围、幂等和历史 |
| `work` | 项目、成员、任务组、任务字段、任务与协作历史、日报评论 | `identity` | 成员离开后失权、任务版本、状态历史、已提交日报不可编辑 |
| `data` | 数据源、仪表盘组件、KPI 目标与实际值 | `module` | 统计只读取当前用户可见记录，数值聚合与非法口径拒绝 |
| `print` | 模板配置和模块记录代入 | `module` | 无权记录不能打印、模板只代入文本 |
| `app` | 应用创建、密钥验证/轮换、事件订阅配置 | `identity` | 旧密钥失效、停用范围拒绝、配置与实际投递边界明确 |

身份与租户范围先稳定；模块配置先于记录和场景；模块记录权限和保存合同先于流程、审批、数据与打印。工作、公共资源和应用可在身份边界稳定后独立实施。共享 SQL 迁移和接口变更串行，互不依赖的业务模块可并行；最终用 `server` 组合成一个后端服务。

## 模块接口的明确约定

- 模块配置：`/api/modules/groups`、`/api/modules`、`/api/modules/{moduleId}/fields`、`/api/modules/{moduleId}/form-schema`、`/api/modules/{moduleId}/tenant-fields`、`/api/modules/{moduleId}/query-fields`。
- 模块记录：`/api/modules/{moduleId}/records` 提供列表/新建；`/api/modules/{moduleId}/records/{recordId}` 提供详情/修改/删除。列表响应含 `columns` 与 `records`，`columns` 返回字段编码、标题、类型、可排序标志和当前顺序；记录写入以 `values` 按字段编码传值。
- 表头与排序：`/api/modules/{moduleId}/columns` 查询/保存可见列和顺序；列表的 `sortField`、`sortOrder` 必须匹配有效查询字段，稳定排序补充记录 ID。
- 场景：`/api/modules/{moduleId}/scenes` 提供列表/新建；`/api/modules/{moduleId}/scenes/{sceneId}` 提供详情/修改/删除；场景配置保存列顺序、筛选条件和排序；列表可带 `sceneId` 使用配置。
- 审批/流程与模块绑定：`/api/modules/{moduleId}/examine-bindings`、`/api/modules/{moduleId}/flow-bindings`，必须核对同租户以及定义启用状态。

具体 DTO 字段和错误码随批次实现写在接口测试中；不能把“接口规划”当作已经完成的接口。

## 当前断点（2026-10-19）

- `unexamine_r15` 库已保留本轮原名 94 张表及 QA 数据；表及字段备注缺失数均为 0，`*_at` 时间列数为 0。Base 已从这 94 张实际表生成，JDK 21 后端编译和测试通过。
- Maven 构建现按九个业务域、通用设施 `foundation` 和启动入口 `server` 拆分；94 张表的 Entity/Mapper 各归所属业务模块，`foundation` 不含业务表。模块、流程及审批内的大 Controller 按实际操作拆开；干净构建、单服务打包和代表性真实 HTTP 请求通过，证据见 `backend-acceptance.md`。下一步按模块逐项复核能力边界，不把结构调整等同于业务完成。
- 平台/系统/租户身份、模块表单与记录/场景、流程与审批人工流转、工作管理、应用配置、公共资源、仪表盘/KPI/打印均已有真实接口；按业务模块的权限、持久化与失败结果实测见 `backend-acceptance.md`。接口文档也按业务模块拆分，不再用混合文档代表多个模块。
- 当前已实现模块记录的流程绑定自动触发、人工设置期限后的后台超时与异常确认，以及应用凭据验证和轮换。仍未实现的范围包括流程自动安排期限与提醒/重试、应用事件投递、应用凭据进入业务接口、AI 服务调用、外部数据源及 KPI 非全周期统计；这些能力不能因建有对应配置表而视为完成。
- 前端代码已移出当前实现，待后端边界及业务结果由用户验收后开发。
