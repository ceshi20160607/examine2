# 系统管理员配置和发布手册

系统管理员通过 Web 页面建立业务系统、授权成员并发布配置。运行台只使用已发布版本；保存草稿或通过预检本身不会改变成员看到的业务能力。

## 建立系统和工作空间

在平台后台“组织架构”可按名称建立平台部门，并在成员列表调整平台成员的部门和职务。该操作使用平台组织权限，且不会自动授予系统成员资格或修改平台角色；修改后刷新列表核对归属。

在平台后台“角色权限”建立普通平台角色，填写名称和用途后选择允许的平台动作，核对受影响成员数和撤回动作数，再确认发布。到“平台成员授权”按账号搜索成员并分配角色；用该成员账号重开页面，核对授权入口和无权操作的拒绝结果。角色只作用于平台；系统和租户角色仍在对应系统后台设置。内置超级管理员角色以及当前管理员自己的平台角色不能在这里变更。

1. 使用平台管理员账号进入平台工作区，在“系统”中新建系统。系统所属人进入系统后拥有系统管理权限。
2. 系统默认有主工作空间。需要多个租户时，先在系统后台开启多租户，再建立次租户和成员。关闭多租户会隐藏非主租户入口，不会删除其数据；重新开启后应核对授权与数据。
3. 在系统后台建立组织、成员和角色。角色发布后重新检查成员在目标工作空间的菜单、记录范围和字段读写权限。系统成员资格与业务角色均须满足，不能仅凭平台账号进入系统。

## 发布两个业务模块

1. 进入“系统管理 → 模板配置 → 模块搭建”，先建模块组，再在组下建模块。名称由管理员填写，内部编码由系统生成。进入模块的“模块字段”配置字段、列表、表单和详情页。
2. 进入“模块动作”检查新建、编辑、列表、详情等默认动作；需要自定义操作时点“新建手动动作”，选择业务字段更新或记录状态变更、出现位置和确认提示，保存为草稿。进入“模块信息 → 发布与版本”，等待发布检查通过，再确认发布。运行页只读取已发布版本。
3. 进入“模板配置 → 导出配置”，选择已发布导出动作的模块，设置配置名称、导出列和顺序，依次点“保存草稿”“发布导出配置”。普通成员的导出仍受已发布动作、角色、字段及记录范围约束。
4. 进入“系统管理 → 角色权限”，选择或新建角色，按“基本信息 → 权限范围 → 保存与发布”配置菜单、动作、字段及每项数据范围。保存草稿后填写发布原因，在影响确认框内确认发布；取消时旧授权保持生效。回到“组织架构”为成员分配已发布角色，并以成员账号核对列表、详情、导出和拒绝结果。
5. 进入运行台新增、编辑记录并刷新页面，核对字段值、负责人和工作空间。修改模块或角色后，在同一记录上检查新版本与原记录的可见性。

## 审批和应用

审批动作先在“模板配置 → 模块动作”中启用并发布，再到“流程配置 → 设计与发布”建立 Flow、设置审批人、保存草稿并发布版本。最后从“模块 Flow”或“流程配置 → 触发绑定”选中该模块的“发起审批”，选择已发布 Flow 和“仅启动流程”，发布绑定；替换已有绑定时先核对影响，旧绑定保留为停用记录。新实例使用当前发布版本，已发起实例保留原版本。由有审批动作权限的成员从记录发起，由被指派的成员在“待办”办理；无权成员不能代办。

邀请成员在“系统管理 → 组织架构 → 邀请成员”填写目标账号和工作空间，可同时分配已发布角色。把页面生成的一次性邀请链接交给目标用户；用户接受后进入系统。未授予业务角色的成员可以进入系统，但不能因此看到业务记录。

跨系统访问由目标系统配置应用和发布授权，逐项选择系统、租户、资源、动作、字段和数据范围。来源系统成员不因能调用目标应用而获得直接进入目标系统的资格。停用应用后，调用应立即被拒绝；操作前后查看应用调用日志。

## OAuth2 企业身份源

平台管理员在“企业身份源”建立 OAuth2 草稿，填写授权、令牌、用户信息和回调地址、Client ID、仅作引用的 Client SecretRef，以及授权范围。域名白名单启用时，应将外部用户标识、邮箱和邮箱已验证的布尔属性分别映射到身份源返回字段；预检要求三项映射齐全。连接探活地址如已配置，预检会请求该地址。预检通过后发布，登录页才显示入口。当前 OAuth2 运行态使用授权码、PKCE 和 Bearer 用户信息端点；身份源必须支持这些能力。平台自动建号 JIT 尚未接入运行态，启用后预检会拒绝发布。

系统管理员在一级“统一认证配置”页选择平台已发布的身份源和版本，指定租户域名、外部部门与系统部门、成员匹配顺序及未匹配策略；上传或填写样例后执行预检，核对匹配的账号、员工、部门和拟执行动作，再人工确认同步。对已存在成员可先用邮箱等键匹配并绑定外部身份；无有效系统成员及租户成员资格时，SSO 登录得到的平台会话仍不能进入该系统。确认前不会凭身份源登录自动授予系统权限。平台登录日志先记录账号绑定成功且尚未选择系统；实际进入系统时另记成员匹配或拒绝，并以服务端会话、登录 traceId 和本次 requestId/traceId 关联。系统后台“登录映射日志”可按身份源、外部用户和追踪号筛选，追踪号可复制；本地账号登录不会写成企业登录。

## SAML 2.0 企业身份源

平台管理员填写 IdP Issuer、SP Entity ID、IdP SSO 端点、当前站点的 `/api/auth/sso/{身份源编码}/saml/acs` 地址，并在“允许回调地址”中填入相同 ACS。将 IdP 用于签署完整 Response 的有效 RSA X.509 PEM 证书放入部署环境，以 `env:` 或 `property:` SecretRef 引用；不要把证书文本或私钥填进草稿。域名白名单启用时，填写签名断言内的邮箱及邮箱已验证属性。预检解析证书、检查 ACS 路由及可选探活地址；通过后发布才开放登录入口。

当前浏览器路径由 SP 发起未签名的 HTTP Redirect AuthnRequest，IdP 以签名的 HTTP POST Response 返回 ACS。配置的 IdP 必须接受该请求绑定与签名策略；要求 SP 请求签名、只签署 Assertion、加密断言或 IdP 主动发起登录的身份源不适用当前路径。ACS 校验响应签名、证书、请求关联、受众、回调地址和时效后才交接平台登录；平台和系统账号绑定仍按上节人工确认流程配置。真实企业 IdP 接入前应在隔离环境完成其元数据和策略联调。

## LDAP 目录身份源

平台管理员在“企业身份源”新建 LDAP 草稿，填写 `ldaps://` 目录地址、服务账号 Bind DN、搜索基准 DN、登录名属性、外部用户标识属性、邮箱属性和服务密码 `env:` 或 `property:` SecretRef。目录证书必须由运行后端的 JVM 信任库验证；不接受明文 LDAP、匿名服务 Bind 或空搜索基准。预检会实际建立 LDAPS 连接、用服务账号 Bind 并读取搜索基准；通过后发布，登录页才展示该目录入口。用户在登录页填写目录账号和密码，后端用唯一检索结果的 DN 再次 Bind；密码只用于本次验证，不写入身份映射或审计。

启用域名白名单时，邮箱必须来自已认证的目录条目。系统管理员仍须在“统一认证配置”中预检外部身份和部门，人工确认平台账号及系统成员映射；未绑定平台账号、无有效成员或无权系统会拒绝进入。当前 LDAP 路径不支持 MFA 或自动建号，要求 MFA 或 JIT 的草稿无法通过平台预检。Active Directory 的特定登录名和目录行为、企业微信/钉钉、真实企业目录证书及跨真实身份源的联合验收仍需单独完成。

## 发布前检查

在“平台管理 → 审计日志”按事件、对象、结果和时间检索平台操作，打开详情核对请求追踪号；系统后台审计只显示当前系统与租户。平台和系统事件不得相互混入，敏感字段按审计权限遮罩。

检查管理端与运行台桌面及手机页面、角色拒绝结果、数据库迁移版本、文件存储和应用调用日志。部署包的版本与校验值、首装、升级前备份和恢复步骤见[部署说明](../README.md)；打印模板的版本与历史 PDF 处理见[打印说明](printing-and-settings.md)。
