# 原型流水线：通用教训库（可移植）

> **用途：** Agent 在 L0 前 **必读**；项目结束后 **追加** 新条目。  
> **规则：** 每条教训必须 **去项目化**（不出现 unexamine/车系统等专名，用「示例」代替）。  
> **维护：** 每次 user-approval 返工或 design-diff fail → 走 [learning-loop.md](./learning-loop.md)。

---

## A. 顺序教训（不遵守必返工）

### A1. 先页表，后 HTML

- **错：** 直接让模型「画原型」→ 页数常缺 40～60%，配置链断裂。
- **对：** `design-package.md` P0 行数 = 最终 HTML 数；brief 与页表 1:1。
- **断言：** design-diff 统计 `P0_html / P0_planned = 100%`。

### A2. 先名词，后 IA

- **错：** 「应用」「模块」「分组」多义 → 整页概念错，无法局部修。
- **对：** L0 `domain-glossary.md` 每词两行：**是什么 / 不是什么**。
- **断言：** analyst review 与 glossary 零冲突。

### A3. 先按钮，后视觉

- **错：** 只有线框和壳 → 列表像调试表、缺批量条/场景/抽屉。
- **对：** L3 `config-spec` 写清工具栏、权限点、显隐；标准列表页 deep spec。
- **断言：** runtime-list 含 §1.1 全部控件类（见 defaults）。

### A4. 一次 brief，禁止聊天 patch

- **错：** 「再加个导出」「侧栏不要待办」分散在对话 → 模型上下文丢项。
- **对：** 所有要求合并进 `prototype-brief.md` 再生成 HTML。
- **断言：** brief 版本号 + 变更只 via spec 文件 diff。

## B. IA 教训（企业后台通用）

### B1. 配置态 ≠ 使用态

- **错：** 同一侧栏既有「字段设计」又有「业务列表」→ 普通用户迷路。
- **对：** 管理入口仅管理员可见；业务用户登录直达运行态。
- **断言：** 剧本中「业务用户」全程无后台菜单。

### B2. 导航勿重复

- **错：** 待办/消息既在顶栏又在侧栏。
- **对：** 高频全局动线放顶栏图标；侧栏只放域导航。
- **断言：** ui-spec 侧栏项与顶栏项集合不交叠（待办/消息类）。

### B3. 导出是动作，不是中心

- **错：** 独立「导出中心」与业务模块平级。
- **对：** 导出在列表工具栏；权限挂在页面动作。
- **断言：** design-package 无 export-center 页。

### B4. 用户管理与角色管理分页

- **错：** 成员+角色同页多 Tab → 权限矩阵说不清。
- **对：** 成员页管人；角色页管模块/字段/数据/动作权限。
- **断言：** admin-users 与 admin-roles 独立 ID。

## C. 列表页教训（最易被模型做差）

### C1. 三层信息：搜索 / 场景 / 表格

- **错：** 场景横铺一整行、搜索占两行 → 首屏无业务行。
- **对：** 标题行 + **单行**工具栏；场景用下拉或 2～3 chip。
- **断言：** 1440×900 首屏 ≥ 8 行业务数据。

### C2. 选择与批量

- **错：** 无勾选列；或批量条常显。
- **对：** 序号 + 勾选列；**勾选后才**出现 batch bar（≤40px）。
- **断言：** 未勾选时 DOM 无批量操作区。

### C3. 详情不打断列表

- **错：** 居中 modal 覆盖全屏。
- **对：** 行点击 → 右侧详情抽屉；列表仍可滚动。
- **断言：** runtime-list wire 含 drawer 区。

### C4. 配置可溯源

- **错：** 列表列与建模页无关。
- **对：** 建模页含列表列/筛选/场景/动作 Tab；原型能对照。
- **断言：** admin-modeling 含列表场景配置块。

## D. 数据与演示教训

### D1. 禁 generic-table

- **错：** 「Column A / Column B / Lorem」。
- **对：** `*-seed.md` 定义 ≥8 列业务字段 + ≥5 行样例。
- **断言：** HTML 表头与 seed 字段名一致。

### D2. 一条垂直剧本

- **错：** 每页孤立，无法演示「配置→发布→使用」。
- **对：** prd §演示剧本 ≤15 步，每步有页面 ID。
- **断言：** test review pass。

## E. 模型/接稿教训

### E1. 好看 ≠ 对

- 其它模型常：视觉 modern 但 IA 错、页数少。**必须用页表和 checklist，不能信「看起来 OK」。**

### E2. 不继承聊天

- 新会话只读 `docs/design/*` 与 `.cursor/knowledge/*`（见 context-policy）。

### E3. 接稿检查顺序

1. 数 P0 页  
2. 跑 IA 断言  
3. 打开标准列表页看首屏行数  
4. 走演示剧本  
5. 再谈视觉
